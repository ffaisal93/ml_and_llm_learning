## Question

<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">Build a binary text classifier on top of a language model that you can only query through one helper function. You may not use model weights, hidden states, gradients or fine-tuning. The classifier turns the model&#x27;s next-token probabilities for the two label tokens into a normalized score, a predicted label and a loss.

What to implement

The helper next_token_probs is passed in as an argument. It maps a token prefix to a dictionary from each possible next token to its probability, P(next_token | tokens):

def next_token_probs(tokens: list[str]) -&gt; dict[str, float]: ...

The provided helper tokenize(s: str) -&gt; list[str] splits a string on whitespace.

1.
classify_and_score(text, threshold, next_token_probs, l_pos=&quot; yes&quot;, l_neg=&quot; no&quot;) -&gt; dict
text: the input text x.
threshold: the decision threshold in [0, 1].
next_token_probs: the helper above.
l_pos, l_neg: the two label tokens (each a single token).
2.
bce_loss(result, y) -&gt; float
result: the dict returned by classify_and_score.
y: the ground truth, 1 for the positive label and 0 for the negative one.
Rules
1.
Build the prompt string exactly as &quot;Text:
&quot; + text + &quot;

Label:&quot; and tokenize it with tokenize.
2.
Call next_token_probs exactly once on those tokens. One call returns the probability of every next token, so it covers both labels. A label missing from the returned dictionary has probability 0.
3.
Let p_pos and p_neg be the raw probabilities of l_pos and l_neg, and Z = p_pos + p_neg. Return a dict with exactly these keys:
&quot;p_pos&quot;: p_pos / Z
&quot;p_neg&quot;: p_neg / Z
&quot;prediction&quot;: l_pos if p_pos / Z &gt;= threshold, otherwise l_neg (a tie goes to the positive label).
4.
If Z == 0 (neither label token is in the dictionary), return p_pos = p_neg = 0.5, and apply the same threshold rule to 0.5.
5.
bce_loss returns -(y * log(p_pos) + (1 - y) * log(p_neg)) using the normalized values in result. Clamp each probability to at least 1e-12 before taking the log so the loss stays finite.
Examples
1.
The stub returns {&quot; yes&quot;: 0.6, &quot; no&quot;: 0.2, &quot; maybe&quot;: 0.2} and threshold = 0.7. Then Z = 0.8, the result is {&quot;p_pos&quot;: 0.75, &quot;p_neg&quot;: 0.25, &quot;prediction&quot;: &quot; yes&quot;}, because 0.75 &gt;= 0.7. With y = 1 the loss is -log(0.75) = 0.2877.
2.
The stub returns {&quot; yes&quot;: 0.1, &quot; no&quot;: 0.3} and threshold = 0.5. Then Z = 0.4, the result is {&quot;p_pos&quot;: 0.25, &quot;p_neg&quot;: 0.75, &quot;prediction&quot;: &quot; no&quot;}, because 0.25 &lt; 0.5. With y = 1 the loss is -log(0.25) = 1.3863.
3.
The stub returns {&quot; other&quot;: 1.0}. Then Z = 0, so both normalized probabilities fall back to 0.5. With threshold = 0.5 the result is {&quot;p_pos&quot;: 0.5, &quot;p_neg&quot;: 0.5, &quot;prediction&quot;: &quot; yes&quot;}, because 0.5 &gt;= 0.5 and a tie goes to the positive label.
Constraints
0 &lt;= threshold &lt;= 1; every probability is in [0, 1].
Use only the helper; no other model access.</pre>

## Worked solution

1. Turn next-token probabilities into a binary classifier. Define two mutually exclusive labels and compare their model scores under the same prompt and scoring convention.
2. For single-token labels A and B, compute P(A|A or B)=P(A)/(P(A)+P(B)), preferably from their log scores via stable normalization.
3. If a label spans multiple tokens, score its complete conditional sequence and state how termination is handled; one next-token probability is insufficient.
4. Choose the decision threshold on validation data, then measure calibration, class-specific errors and sensitivity to prompt changes.

### Small example / sanity check

If the label probabilities are 0.06 and 0.02, the conditional binary probability for the first is 0.75, even though most mass lies elsewhere.

### Common trap

Reporting 0.06 as the binary probability without explaining unallocated token mass.
