## Question

Build a binary text classifier on top of a language model that you can only query through one helper function. You may not use model weights, hidden states, gradients or fine-tuning. The classifier turns the model's next-token probabilities for the two label tokens into a normalized score, a predicted label and a loss.

### What to implement

The helper next_token_probs is passed in as an argument. It maps a token prefix to a dictionary from each possible next token to its probability, P(next_token | tokens):

```python
def next_token_probs(tokens: list[str]) -> dict[str, float]: ...
```

The provided helper tokenize(s: str) -&gt; list[str] splits a string on whitespace.
1. classify_and_score(text, threshold, next_token_probs, l_pos=" yes", l_neg=" no") -&gt; dict
text: the input text x.
threshold: the decision threshold in [0, 1].
next_token_probs: the helper above.
l_pos, l_neg: the two label tokens (each a single token).
2. bce_loss(result, y) -&gt; float
result: the dict returned by classify_and_score.
y: the ground truth, 1 for the positive label and 0 for the negative one.

### Rules

1. Build the prompt string exactly as "Text:
" + text + "

Label:" and tokenize it with tokenize.
2. Call next_token_probs exactly once on those tokens. One call returns the probability of every next token, so it covers both labels. A label missing from the returned dictionary has probability 0.
3. Let p_pos and p_neg be the raw probabilities of l_pos and l_neg, and Z = p_pos + p_neg. Return a dict with exactly these keys:
"p_pos": p_pos / Z
"p_neg": p_neg / Z
"prediction": l_pos if p_pos / Z &gt;= threshold, otherwise l_neg (a tie goes to the positive label).
4. If Z == 0 (neither label token is in the dictionary), return p_pos = p_neg = 0.5, and apply the same threshold rule to 0.5.
5. bce_loss returns -(y * log(p_pos) + (1 - y) * log(p_neg)) using the normalized values in result. Clamp each probability to at least 1e-12 before taking the log so the loss stays finite.

### Examples

1. The stub returns {" yes": 0.6, " no": 0.2, " maybe": 0.2} and threshold = 0.7. Then Z = 0.8, the result is {"p_pos": 0.75, "p_neg": 0.25, "prediction": " yes"}, because 0.75 &gt;= 0.7. With y = 1 the loss is -log(0.75) = 0.2877.
2. The stub returns {" yes": 0.1, " no": 0.3} and threshold = 0.5. Then Z = 0.4, the result is {"p_pos": 0.25, "p_neg": 0.75, "prediction": " no"}, because 0.25 &lt; 0.5. With y = 1 the loss is -log(0.25) = 1.3863.
3. The stub returns {" other": 1.0}. Then Z = 0, so both normalized probabilities fall back to 0.5. With threshold = 0.5 the result is {"p_pos": 0.5, "p_neg": 0.5, "prediction": " yes"}, because 0.5 &gt;= 0.5 and a tie goes to the positive label.

### Constraints

0 &lt;= threshold &lt;= 1; every probability is in [0, 1].
Use only the helper; no other model access.

## Worked solution

### Solution outline

Define two mutually exclusive labels and compare their model scores under the same prompt and scoring convention.

1. For single-token labels A and B, compute P(A|A or B)=$P(A)/(P(A)+P(B))$, preferably from their log scores via stable normalization.
2. If a label spans multiple tokens, score its complete conditional sequence and state how termination is handled; one next-token probability is insufficient.
3. Choose the decision threshold on validation data, then measure calibration, class-specific errors and sensitivity to prompt changes.

### Understand why the approach works

#### Build the computation before optimizing it

Start by saying which axis represents examples, positions, heads and features. With batch size $B$, query length $T_q$, key length $T_k$ and head width $d_k$, a head receives $Q\in\mathbb R^{B\times T_q\times d_k}$ and $K\in\mathbb R^{B\times T_k\times d_k}$. Values may have a different final width $d_v$. The essential operation is

$$
S=\frac{QK^\top}{\sqrt{d_k}}+M,\qquad
P_{ij}=\frac{\exp(S_{ij}-m_i)}{\sum_j\exp(S_{ij}-m_i)},\qquad O=PV.
$$

Here the transpose affects the final two axes, $m_i=\max_j S_{ij}$ is a row maximum, and $M$ contains zero for allowed positions and $-\infty$ for forbidden ones. Each query produces one distribution **over keys**, so summing the wrong axis changes the operation even when the output shape looks plausible.

For a tiny check, give a query access to exactly one key. Its output must equal that key's value, regardless of the score. Then change a forbidden future token: earlier causal outputs must remain unchanged. These checks expose mistakes that a random shape test misses.

Explain the limitation of the simple implementation. Explicitly materializing $P$ uses $O(T_qT_k)$ score storage per head. A reference implementation is useful for correctness; a tiled kernel can avoid that materialization while preserving the mathematical attention operation. Generation additionally needs correct target shifts, positions and cache state, not just a working matrix multiplication.
