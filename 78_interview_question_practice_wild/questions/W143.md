## Question

Implement a Basic Tokenizer and Train a Simple Language Model

Build a small end-to-end language-model pipeline: tokenize text, encode tokens to ids, decode ids back to text, and train a next-token model whose loss decreases.

Implement the class SimpleTokenizer and the function train_bigram using NumPy only (no deep-learning framework).

### Requirements

1. tokenize(text) — split text into word tokens on whitespace. A string returns List[str]; a list of strings returns List[List[str]]. Runs of whitespace collapse, and the result is deterministic.
2. build_vocab(texts) — from a list of strings, build vocab (token -&gt; id) and inv_vocab (id -&gt; token). Id 0 is reserved for the unknown token "&lt;unk&gt;"; the other tokens get ids in order of first appearance. Return vocab.
3. word_to_token(text) (encoding) — map a string to a list of ids, or a list of strings to a list of id lists. A token that is not in the vocabulary maps to the &lt;unk&gt; id.
4. token_to_word(ids) (decoding) — map a list of ids to a space-joined string, or a list of id lists to a list of strings. An unknown id decodes to &lt;unk&gt;.
5. train_bigram(token_ids, vocab_size, epochs=200, lr=0.5, seed=0) — train a bigram next-token model: a vocab_size x vocab_size weight matrix W (initialized from a normal distribution with standard deviation 0.01 and the given seed) whose row x holds the logits of the token that follows x. Each epoch computes the mean cross-entropy over all (current, next) pairs and takes one plain SGD step on its gradient. Return (W, losses), where losses holds the loss of each epoch.
Input / Output
Texts are Python strings; ids are non-negative integers.
train_bigram takes the id sequence of a training text and returns the trained matrix and the per-epoch losses.

### Constraints

Decoding the encoding of in-vocabulary text returns the whitespace-normalized text.
Training must reduce the loss: losses[-1] &lt; losses[0].
Example
tok = SimpleTokenizer()
tok.tokenize("the  cat   sat")       -&gt;  ["the", "cat", "sat"]
tok.tokenize(["a b", "c"])           -&gt;  [["a", "b"], ["c"]]
tok.build_vocab(["the cat sat on the mat", "the dog sat on the log"])
-&gt;  {"&lt;unk&gt;": 0, "the": 1, "cat": 2, "sat": 3,
"on": 4, "mat": 5, "dog": 6, "log": 7}
tok.word_to_token("the cat elephant") -&gt;  [1, 2, 0]
tok.token_to_word([1, 2, 3])         -&gt;  "the cat sat"

ids = tok.word_to_token("the cat sat on the mat the dog sat on the log")
W, losses = train_bigram(ids, 8)     # losses[0] ~ 2.08, losses[-1] ~ 0.59

## Worked solution

### Solution outline

#### Implement a deterministic toy tokenizer, then explain what BPE adds.

A tokenizer turns text into a reproducible token sequence; BPE learns reusable merges beyond individual symbols.

1. Define the base alphabet and normalization policy, including whitespace and unknown characters.
2. For BPE training, repeatedly count adjacent pairs, choose the most frequent under a deterministic tie rule, merge non-overlapping occurrences and update the vocabulary.
3. At encoding time apply learned merge ranks, not a fresh frequency count on each document. Keep decoding and special-token handling explicit.

#### Why is a next-token model trained with shifted targets?

At position t, the model sees tokens through t and predicts token t+1. The target shift makes the training task match autoregressive generation.

1. Given tokens [x0,x1,x2,x3], use inputs [x0,x1,x2] and targets [x1,x2,x3], unless the library performs this shift internally.
2. Apply a causal mask to prevent access to later input positions. Use cross-entropy over vocabulary logits without an extra softmax first.
3. For instruction tuning, mask unwanted target positions after aligning the shift. Divide by the count of supervised targets, not padded sequence length.

#### Debug a miniature GPT that fails to learn.

Localize the first broken invariant rather than changing many hyperparameters at once.

1. Check shifted labels, causal masking, tensor axes, vocabulary bounds and padding/loss masks on a tiny batch.
2. Check train/eval mode, gradient presence, optimizer steps and parameter changes. Overfit a tiny dataset with dropout disabled as a diagnostic.
3. Compare against a simple trusted baseline; then test generation and caching separately. Record one controlled change and its effect at a time.

### Understand why the approach works

#### Build the computation before optimizing it

Start by saying which axis represents examples, positions, heads and features. With batch size $B$, query length $T_q$, key length $T_k$ and head width $d_k$, a head receives $Q\in\mathbb R^{B\times T_q\times d_k}$ and $K\in\mathbb R^{B\times T_k\times d_k}$. Values may have a different final width $d_v$. The essential operation is

$$
S=\frac{QK^\top}{\sqrt{d_k}}+M,\qquad
P_{ij}=\frac{\exp(S_{ij}-m_i)}{\sum_j\exp(S_{ij}-m_i)},\qquad O=PV.
$$

Here the transpose affects the final two axes, $m_i=\max_j S_{ij}$ is a row maximum, and $M$ contains zero for allowed positions and $-\infty$ for forbidden ones. Each query produces one distribution **over keys**, so summing the wrong axis changes the operation even when the output shape looks plausible.

For a tiny check, give a query access to exactly one key. Its output must equal that key's value, regardless of the score. Then change a forbidden future token: earlier causal outputs must remain unchanged. These checks expose mistakes that a random shape test misses.

Explain the limitation of the simple implementation. Explicitly materializing $P$ uses $O(T_qT_k)$ score storage per head. A reference implementation is useful for correctness; a tiled kernel can avoid that materialization while preserving the mathematical attention operation. Generation additionally needs correct target shifts, positions and cache state, not just a working matrix multiplication.

### Readable reference implementation

Read the explanation first, then trace one small input through these functions. This is the same implementation used by the local checks; its stated simplifications still apply.

```python
from collections import Counter


def train_bpe(texts, num_merges):
    """Count adjacent pairs, break frequency ties lexically, merge non-overlapping."""
    if num_merges < 0:
        raise ValueError("num_merges must be nonnegative")
    sequences = [list(text) for text in texts]
    merges = []
    for _ in range(num_merges):
        counts = Counter()
        for tokens in sequences:
            counts.update(zip(tokens, tokens[1:]))
        if not counts:
            break
        pair = min(counts, key=lambda item: (-counts[item], item))
        merges.append(pair)
        updated_sequences = []
        for tokens in sequences:
            updated = []
            i = 0
            while i < len(tokens):
                if i + 1 < len(tokens) and tuple(tokens[i:i + 2]) == pair:
                    updated.append(tokens[i] + tokens[i + 1])
                    i += 2
                else:
                    updated.append(tokens[i])
                    i += 1
            updated_sequences.append(updated)
        sequences = updated_sequences
    return merges


def encode_bpe(text, merges):
    """Character-level reference: texts are separate sequences; no special tokens."""
    tokens = list(text)
    for left, right in merges:
        updated = []
        i = 0
        while i < len(tokens):
            if i + 1 < len(tokens) and tokens[i:i + 2] == [left, right]:
                updated.append(left + right)
                i += 2
            else:
                updated.append(tokens[i])
                i += 1
        tokens = updated
    return tokens
```
