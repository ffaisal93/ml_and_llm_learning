## Question

Be ready for a rapid-fire MLE round covering:
1. Classification pipeline: data cleaning, feature construction, model choice, training, offline eval, online eval, monitoring.
2. LLM concepts: Transformer structure, SFT, DPO, prompt engineering, agents, MCP, knowledge distillation, evaluation.
3. Ads / ranking: binary CTR prediction, DCN v1 vs v2, bidding objectives, CPA design, A/B testing.
4. Production debugging: online performance drops, GPU OOM, bad embeddings, metric regressions, data issues.
5. Domain adaptation: audio processing, image/video compression, multimodal embeddings, model optimization.
6. Inference & deployment: LLM latency/memory bottlenecks (KV cache, quantization, batching), vision-encoder training basics.

## Worked solution

### 1. Classification: give a complete causal chain

Define the decision and error costs, inspect labels/missingness, and create an entity/time-safe split. Fit cleaning/encoders only on training data. Start with a simple model, then compare richer alternatives on held-out quality, calibration and serving cost. Choose thresholds on validation data, run a guarded online experiment, and monitor feature freshness, drift, delayed outcomes and latency. A good training score is not a production evaluation.

### 2. LLM terms: explain what actually changes

A decoder Transformer alternates masked self-attention and feed-forward blocks with normalization/residual connections. SFT fits desired response tokens by cross-entropy; DPO fits pairwise preferences relative to a reference policy. Prompt engineering changes conditioning without necessarily changing weights. An agent adds a bounded observation–tool–decision loop; ordinary code validates tools, permissions and stop conditions. MCP standardizes interfaces for capabilities such as tools, resources and prompts; it is not a model or an authorization policy by itself.

Distillation trains a student from teacher outputs/distributions, trading teacher-query cost and inherited errors against a cheaper deployed model. Evaluate task success, grounding, format validity, tool effects, latency and cost with held-out tasks and human-audited judges. Do not use a model's self-confidence as a correctness test.

### 3. Ads and ranking

CTR is a Bernoulli probability: train on actual impressions/clicks, use raw-logit binary cross-entropy and calibrate on representative data. Log exposure positions and delay conversion labels appropriately. For cross networks, v1 uses a vector interaction $x_0(w_l^\top x_l)+b_l+x_l$; v2 uses matrix interactions $x_0\odot(W_lx_l+b_l)+x_l$, with low-rank/mixture variants for efficiency. V2 is more expressive but still needs an equal-budget experiment.

For conversion-valued bids, rank using calibrated expected value, with pCVR defined conditionally or unconditionally consistently. A CPA objective minimizes spend per attributed acquisition; that ratio depends on delayed attribution and can be gamed by low volume. Guard spend, conversion quality, user experience and budget pacing. A/B tests need stable assignment, prespecified metrics, sufficient mature outcomes and valid handling of multiple comparisons.

### 4. Debug with evidence

| Symptom | First checks | Likely targeted action |
|---|---|---|
| Online quality drops | traffic/label delay, experiment mix, feature freshness, schema/model versions | isolate affected slice, rollback, fix pipeline |
| GPU OOM | weights vs activations/KV/workspace, batch/context tails, fragmentation | cap admission/context, reduce batch, quantize supported tensors |
| Bad nearest neighbors | tokenizer/normalization, model/index version, pooling, ID mapping | compare exact neighbors, rebuild incompatible index |
| Metric regression | denominator, joins, time windows, duplicates, label maturity | reconcile one request end to end before retraining |

Change one suspected cause at a time and compare a reproducible baseline. A model retrain cannot repair a wrong SQL join.

### 5. Adapt to the modality

For audio, define sample rate, waveform/log-mel representation, duration and augmentations, then split by speaker/session. For image/video compression, distinguish codec rate–distortion from ML model compression; bitrate, perceptual/task quality and encode/decode latency trade off. Video also requires temporal sampling/context. Multimodal embeddings need paired/contrastive training, normalization, hard-negative checks and modality-specific slices.

For a vision encoder, use correct preprocessing, a declared frozen/fine-tuned backbone, train/validation mode and a suitable supervised/contrastive loss. Test small-batch overfitting and data leakage before tuning scale. A pretrained embedding is not automatically appropriate for every domain.

### 6. Inference and deployment

Measure queueing, prefill/first-token and decode/inter-token latency separately. KV cache reduces repeated prefix computation but consumes memory; continuous batching improves utilization while queueing can hurt tails. Quantization saves memory only with suitable kernels and acceptable quality. Version model/tokenizer/preprocessing together, shadow/canary, monitor task and systems metrics, and retain rollback. An optimization succeeds only if the end-to-end user metric and resource cost improve under realistic load.
