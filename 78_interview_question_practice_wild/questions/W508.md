## Question

Build a React component FilterableList that shows a dataset and lets the user narrow it with filter controls. The visible results must update immediately whenever a control changes.

### What to implement

FilterableList({ items }), where each item has the shape { id, name, description, status, type } (all strings; status is "active" or "inactive", type is "camera" or "sensor").
1. Render the matching items as a list or as cards, showing at least the name, status and type of each.
2. Provide three controls: a text input for a keyword search, a select for status and a select for type. Each select has an "all" option meaning no restriction.
3. An item is visible only if it passes every active control (AND): the search text must appear in its name or description, and its status and type must equal the selected values unless "all" is selected.
4. Search is case-insensitive and ignores leading and trailing whitespace; a query that is empty or only whitespace matches everything.
5. A "Reset" button restores all controls to their initial values, which shows the full dataset again.
6. When nothing matches, show an explicit "No results" message instead of an empty area.
Deliverables
The component and its filtering logic. The filtering rule itself should be a pure function of the item and the filter values.
A short explanation of your state design: which values are stored in state, which are derived from it, and where memoization helps.

### Constraints

Filtering must not mutate items.
Do not store the filtered list in state; compute it from items and the filter values.
Assume up to a few thousand items; no pagination is required.

## Worked solution

### Store the controls, derive the results

The three independent filter values are query, status and type. Keep only those in React state. The visible list is derived from current props plus those values, so it cannot become stale because a separate “filtered items” state missed an update. Combine active conditions with AND, and combine name/description text matches with OR.

### Pure filtering function

```javascript
export function matches(item, { query = "", status = "all", type = "all" }) {
  const q = query.trim().toLocaleLowerCase();
  const textMatches =
    !q ||
    item.name.toLocaleLowerCase().includes(q) ||
    item.description.toLocaleLowerCase().includes(q);
  return (
    textMatches &&
    (status === "all" || item.status === status) &&
    (type === "all" || item.type === type)
  );
}
```

### React component

```jsx
import React, { useMemo, useState } from "react";
import { matches } from "./filter_508.mjs";
export function FilterableList({ items }) {
  const [query, setQuery] = useState("");
  const [status, setStatus] = useState("all");
  const [type, setType] = useState("all");
  const visible = useMemo(
    () => items.filter((item) => matches(item, { query, status, type })),
    [items, query, status, type],
  );
  function reset() {
    setQuery("");
    setStatus("all");
    setType("all");
  }
  return (
    <section aria-label="Device list">
      <label>
        Search <input value={query} onChange={(e) => setQuery(e.target.value)} />
      </label>
      <label>
        Status{" "}
        <select value={status} onChange={(e) => setStatus(e.target.value)}>
          <option value="all">All</option>
          <option value="active">Active</option>
          <option value="inactive">Inactive</option>
        </select>
      </label>
      <label>
        Type{" "}
        <select value={type} onChange={(e) => setType(e.target.value)}>
          <option value="all">All</option>
          <option value="camera">Camera</option>
          <option value="sensor">Sensor</option>
        </select>
      </label>
      <button type="button" onClick={reset}>
        Reset
      </button>
      <p aria-live="polite">{visible.length} results</p>
      {visible.length ? (
        <ul>
          {visible.map((item) => (
            <li key={item.id}>
              {item.name} — {item.status} — {item.type}
            </li>
          ))}
        </ul>
      ) : (
        <p>No results</p>
      )}
    </section>
  );
}
```

Download [the component](../FilterableList508.jsx) and [its pure predicate](../filter_508.mjs) into the same folder in a React application. The example IDs are numbers despite the text contract saying strings; React keys work for either stable unique type. The filter does not change items or their order.

The query is normalized once per predicate call for readability; for a larger dataset normalize once before calling `filter`. An empty trimmed query passes every item. Each select independently skips its check when set to `all`. Reset sets exactly the initial values and therefore restores the entire input list.

### Follow the examples and measure before optimizing

“garage” matches the names of items two and three. Adding active status removes item two. “door” matches descriptions of cameras, but combining it with sensor type leaves no result, so the explicit empty state appears. The pure function was checked against all four supplied examples, including Reset's initial filter values.

`useMemo` avoids repeating filtering when a parent rerenders with the same item-array identity and controls. It is an optimization, not a correctness requirement. Parents must replace arrays when data changes rather than mutating the same array in place. For a few thousand rows, linear filtering is usually a good starting point; memoization does not make a changed query sublinear or prevent rendering every visible row. If measured DOM rendering becomes slow, add virtualization separately. Labels, native controls, a polite result count and stable keys support accessible interaction without inventing a custom control behavior.
