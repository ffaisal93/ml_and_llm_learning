## Worked solution

1. Design tool schemas and validate LLM outputs. A tool response becomes useful only when its structure and meaning are checked by ordinary code.
2. Specify names, field types, required fields, bounds and enumerations; validate syntax before execution.
3. Perform semantic checks such as date ordering, inventory availability, authorization and allowed resource identifiers.
4. Return structured errors that allow a bounded repair attempt. Keep untrusted tool output separate from higher-priority instructions.

### Small example / sanity check

A JSON object with quantity=-3 can be syntactically valid but invalid for an order request.

### Common trap

Assuming successful JSON parsing proves that a tool call is safe or correct.
