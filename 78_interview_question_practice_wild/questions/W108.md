## Worked solution

### Search and sampling solve different problems

Beam search maintains up to $b$ prefixes with score $s(y)=\sum_t\log P(y_t\mid x,y_{<t})$. Start with the prompt at score zero, expand each unfinished prefix over vocabulary tokens, rank all expansions, and retain the best $b$. Freeze completed EOS sequences; do not append tokens to them or add their score repeatedly. Stop when all retained hypotheses are finished, the generation limit is reached, or a sound bound proves no live prefix can beat the best completed one under the declared score. Width one with the same rules is greedy. Finite pruning makes search approximate: an initially weak prefix can lead to the best completion after it was pruned.

A declared length score such as $s(y)/((5+|y|)/6)^\alpha$ changes both ranking and safe early stopping; compare it separately from raw likelihood. A larger beam explores more candidates and usually improves search quality, but need not monotonically improve even the chosen objective across arbitrary pruning rules, much less user preference. It adds work and can expose the model's preference for short, bland or repetitive strings. Repetition can be self-reinforcing because a generated phrase makes its continuation likely.

For nucleus sampling, divide logits by temperature $\tau>0$, softmax, sort descending and retain the smallest prefix reaching mass $p\in(0,1]$. Include the crossing token, renormalize and sample. For probabilities `[.6,.25,.15]` and $p=.8$, keep the first two and sample with probabilities `.6/.85,.25/.85`. Low temperature sharpens before selecting the nucleus; high temperature flattens and usually enlarges it. Too-small $p$ approaches greedy; too-large $p$ admits unlikely continuations and instability.

### Implementation logic

```python
import math
import random

def beam_search(prompt, next_probs, eos, width=2, max_new=30):
    if width < 1 or max_new < 0:
        raise ValueError('invalid search limits')
    # next_probs(prefix) returns a normalized dictionary: token -> probability.
    beams = [(list(prompt), 0.0, False)]
    for _ in range(max_new):
        candidates = []
        for seq, score, done in beams:
            if done:
                candidates.append((seq, score, True))
                continue
            for token, probability in next_probs(seq).items():
                if probability > 0:
                    candidates.append((seq+[token], score+math.log(probability), token==eos))
        if not candidates:
            raise ValueError('no positive-probability continuation')
        # Python sort is stable: dictionary order is the chosen equal-score rule.
        beams = sorted(candidates, key=lambda x:x[1], reverse=True)[:width]
        if all(done for _,_,done in beams):
            break
    return beams[0]  # Sequence, raw log score, whether EOS was reached.

def nucleus_token(logits, top_p=.9, temperature=1., rng=None):
    if not logits or not 0 < top_p <= 1 or temperature <= 0:
        raise ValueError('invalid distribution/sampling controls')
    if not all(math.isfinite(v) for v in logits):
        raise ValueError('finite logits required in this reference')
    rng = rng or random.Random()
    maximum = max(logits)
    weights = [math.exp((z-maximum)/temperature) for z in logits]
    total = sum(weights)
    order = sorted(range(len(logits)),key=lambda i:weights[i],reverse=True)
    kept, mass = [], 0.
    for i in order:
        kept.append(i); mass += weights[i]
        if mass >= top_p*total:
            break
    return rng.choices(kept,weights=[weights[i] for i in kept],k=1)[0]

# Demonstration checks: EOS cannot acquire an extra token; p=.8 keeps the crossing token.
def tiny(prefix):
    return {'A': .6, 'B': .4} if not prefix else {'EOS': 1.}
assert beam_search([], tiny, 'EOS', width=2)[0] == ['A','EOS']
rng = random.Random(7)
draws = [nucleus_token([math.log(.6),math.log(.25),math.log(.15)],.8,rng=rng) for _ in range(1000)]
assert set(draws) == {0,1}
assert nucleus_token([0.,10.],.0001,rng=rng) == 1
```

This callback reference deliberately recomputes prefix scores externally; it is executable algorithm logic, not a fast transformer serving implementation. In a transformer adapter, prefill once, then pass only the new token and KV cache into each decode step. Beam candidates carry parent indices; gather/reorder **all layer caches** by those indices before appending selected tokens, with correct position offsets and EOS masks. Shared prompt blocks can use copy-on-write; diverged beams need separate continuation cache. KV memory is approximately $2bLTH_{KV}d_hs$ versus one sequence for one nucleus sample. Finished requests free blocks promptly.

Batch active requests continuously, use chunked prefill to protect decode latency, vectorize beam top-k over `[batch,beam,vocab]` scores, and keep selection/random draws on GPU. Top-p sorting can be expensive at large vocabulary sizes. A top-k prefilter reduces sorting/selection work and caps tails but generally defines a different distribution: if k excludes mass needed for the true nucleus, it is not exact pure top-p. An exact optimization must expand k until sufficient *original* probability mass is covered. KV caching avoids repeated prefix projections/MLPs, though attention still reads previous keys and values.

### Compare at a declared workload

| Dimension | Beam search | Nucleus sampling |
|---|---|---|
| Quality/coherence | Strong for constrained, well-scored tasks; likelihood is only a proxy | Natural alternatives for dialogue/writing; can lose global consistency |
| Diversity/repetition | Beams often overlap; can amplify loops or generic replies | Greater variety; high temperature/p may wander or contradict |
| Factuality | No guarantee; probable falsehood remains possible | No guarantee; tail sampling can add unsupported claims |
| Control/reproducibility | Deterministic given kernels/ties/configuration; grammar constraints possible | Seeded stochastic choices; grammar constraints still possible |
| Latency/throughput | More active sequences and selections; usually worse latency/cost | One continuation per request; usually better high-QPS utilization |
| Memory/cost | Cache grows with beam count and length | One cache per sampled continuation; multiple samples multiply cost |

Prefer beam for translation or constrained structured generation when the scoring objective correlates with correctness; prefer nucleus for conversation and creative alternatives. Higher model likelihood can reward commonplace, terse language that users dislike. Stochastic choices can improve naturalness while creating run-to-run answer variation. Greedy is a good fastest deterministic baseline, but benchmark it: memory traffic and batching dominate many workloads. Reliability/exactness requires schema constraints, evidence and verification, not simply a wider beam.

### A decision-ready evaluation

Freeze a decontaminated prompt suite stratified into factual QA, dialogue, summarization, code, long-form narrative and brainstorming; include languages, safety slices, lengths and difficult turns. Hold model checkpoint, tokenizer, prompt template, tools, hardware and stopping rules constant. Tune beam width/length penalty and $(p,\tau)$ on a separate development split, not the final test. Report raw and length-normalized log likelihood under the *unmodified* model, answer length, stop reasons, repetition rate and distinct-n with token/length normalization. For factual QA use reference correctness and grounded claim checks; for code execute hidden tests and report pass@1/pass@k at equal k; for summaries check factual coverage; for long form rate cross-section consistency and entity/fact contradictions, including early facts probed late.

Have blinded randomized human pairs rate helpfulness, naturalness, coherence, factuality and preference, with ties and rater disagreement. Run several nucleus seeds per prompt and aggregate uncertainty at prompt level, not by treating each sample as a new independent task. Beam is deterministic and should not receive a best-of-many advantage. Compare both one-output-per-request and equal GPU-second/token budgets, including verifier cost. Match requested lengths, cap lengths equally, and also stratify by actual length so an overly terse decoder cannot win latency by omitting the answer.

Under representative load measure TTFT, end-to-end p50/p95, inter-token latency, aggregate output tokens/s, GPU memory and dollar cost, with queueing and failed requests included. Investigate beam-disliked cases for genericness, length bias and loops; try smaller width, tuned length penalty or validated repetition controls. Investigate nucleus inconsistency using seed variance, contradiction checks and grounding; reduce temperature/p or add verification with its cost counted. Deploy endpoint-specific versioned presets (deterministic extraction versus creative drafting), canary against the fixed suite and online preference/task completion, and rollback on critical regressions. Neither method is inherently a factuality fix.
