## Question

Estimate how fast matrix multiplications run on one GPU using the roofline model, then scale the estimate to a 72-layer network and compare two ways of splitting it over two GPUs. This is a pen-and-paper performance-modelling question: show the formula, the arithmetic and the conclusion for each part.

Hardware (one GPU, all numbers given)
Peak compute: 312 TFLOP/s (BF16)
HBM bandwidth: 1.5 TB/s

```text
VRAM: 40 GB (take 1 GB = 10^9 bytes)
```

Link between two GPUs: 300 GB/s per direction
All tensors are BF16 (2 bytes per element). A matmul C = A @ B with A: m x k, B: k x n, C: m x n reads A and B once and writes C once.
1. Cost of a single matmul

For each shape (m, k, n) below, derive:
1. FLOPs: 2 * m * k * n
2. Bytes moved: 2 * (m*k + k*n + m*n)
3. Arithmetic intensity: FLOPs / bytes (FLOP/byte), and the ridge point peak FLOP/s / bandwidth
4. Bound regime: memory-bound below the ridge point, compute-bound above it
5. Predicted time: max(FLOPs / peak FLOP/s, bytes / bandwidth)

Shapes: (1, 8192, 8192), (64, 8192, 8192), (512, 8192, 8192), (4096, 4096, 4096).

2. A 72-layer network on one GPU

The network has 72 layers that alternate between two matmul patterns, 36 layers of each. Every layer reads its own weight matrix, and layers are costed independently.

Pattern A: (m, k, n) = (2048, 8192, 8192)
Pattern B: (m, k, n) = (2048, 8192, 32768)

Compute: (a) the total compute time sum FLOPs / peak, (b) the total data-transfer time sum bytes / bandwidth, (c) the predicted end-to-end time as the sum of the per-layer predicted times from Part 1's rule, and (d) whether all weights plus the largest input and output activation of any one layer fit in 40 GB.

3. Splitting over two GPUs

Compare, for the same network and a single batch of m = 2048 rows:

Pipeline parallelism: layers 1-36 on GPU 0 and layers 37-72 on GPU 1. Only the m x 8192 activation crosses the link once.
Tensor parallelism: every weight matrix is split along n into two halves, one per GPU, so each GPU runs (m, k, n/2). After every layer each GPU sends its half of the output (m * n * 2 / 2 bytes) to the other GPU over the link, with no overlap with compute.

Report end-to-end latency, per-GPU weight memory, and the trade-off (latency against communication volume and memory). Ignore pipeline bubbles: one batch, no micro-batching.

### Constraints

Use exactly the numbers above; round results to three significant figures.
State the bound regime of each matmul before computing its time.

## Worked solution

### 1. One-GPU roofline arithmetic

Use decimal units, P=312×10¹² FLOP/s, BW=1.5×10¹² byte/s. For shape(m,k,n), F=2mkn, bytes B=2(mk+kn+mn), intensity I=F/B and time=max(F/P,B/BW). The ridge is P/BW=**208 FLOP/byte**. Classify by intensity before choosing the larger time.

| (m,k,n) | FLOPs | Bytes | I (FLOP/B) | Regime | Compute time | Memory time | Predicted |
|---|---:|---:|---:|---|---:|---:|---:|
| (1,8192,8192) |1.34×10⁸|1.34×10⁸|1.00|Memory|.000430ms|.0895ms|**.0895ms**|
| (64,8192,8192) |8.59×10⁹|1.36×10⁸|63.0|Memory|.0275ms|.0909ms|**.0909ms**|
| (512,8192,8192) |6.87×10¹⁰|1.51×10⁸|455|Compute|.220ms|.101ms|**.220ms**|
| (4096,4096,4096) |1.37×10¹¹|1.01×10⁸|1.37×10³|Compute|.441ms|.0671ms|**.441ms**|

For example, first shape has F=134,217,728 and B=134,250,496, so I=.999756 and memory dominates. Rounding in the table is to three significant figures; use unrounded values for totals.

### 2. Sum the 72 independent layer costs

Pattern A: F_A=274,877,906,944, B_A=201,326,592, I_A=1365.33>208, hence compute-bound, time .881019ms (memory .134218ms).

Pattern B: F_B=1,099,511,627,776, B_B=704,643,072, I_B=1560.38>208, hence compute-bound, time3.524076ms (memory .469762ms).

Total pure compute=36(F_A+F_B)/P=**159ms** (unrounded158.583ms). Total pure transfer=36(B_A+B_B)/BW=**21.7ms**. Sum of per-layer roofline times=36(.881019+3.524076)=**159ms**; generally sum(max) need not equal max(sum), but here every layer is compute-bound.

Weights occupy 36·2(8192²+8192·32768)=24,159,191,040 bytes=**24.2GB**. Largest simultaneous input+output is2(2048·8192+2048·32768)=167,772,160 bytes=.168GB. Combined **24.3GB** fits40GB under the stipulated single-layer activation model; training gradients/optimizer and other runtime buffers were not requested. Alternating raw shapes are not a self-contained dimension-compatible neural architecture; this is the question's independent-layer cost model, with no invented bridging operations.

### 3. Pipeline versus tensor splitting

Pipeline: GPU0 and GPU1 each hold18 A and18 B weights, **12.1GB/GPU**. One batch visits both halves sequentially, so compute latency remains158.583ms. Boundary bytes=2·2048·8192=33,554,432 bytes=.0336GB, transfer=.111848ms. End-to-end **159ms** (158.695 unrounded). No microbatch overlap means no single-batch2× speedup; adding throughput overlap would be a different scenario.

Tensor: each GPU computes A'=(2048,8192,4096), I=1170.29 and time.440509ms; B'=(2048,8192,16384), I=1489.45 and time1.762038ms. Both remain compute-bound. Sum local compute=36(.440509+1.762038)=**79.3ms**. Per-direction output transfer per layer is m·n bytes: A16,777,216 and B67,108,864. Across all layers each GPU sends36(16,777,216+67,108,864)=3,019,898,880 bytes=**3.02GB**. Full-duplex per-direction300GB/s gives **10.1ms**, not twice that latency; total bidirectional traffic is6.04GB. With no overlap, end-to-end **89.4ms**. Weight storage is again**12.1GB/GPU**, plus temporary gathers/activations.

Tensor parallelism reduces this modeled latency about1.78× versus pipeline while sending about180× the pipeline's total link bytes (6.04GB/.0336GB). Pipeline has much less communication and can improve throughput with microbatches, but not this single-batch latency. All times are optimistic roofline estimates excluding launches, collectives/software and contention; no achieved benchmark is implied.
