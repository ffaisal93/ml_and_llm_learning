## Question

A task marketplace lets a customer post a task that a driver completes. The driver then uploads evidence (for example photos) that the task was done. Identify where machine learning adds value across this end-to-end flow.

Flow
1. The customer describes and submits a task.
2. The platform turns the request into instructions and assigns a driver.
3. The driver performs the task.
4. The driver uploads evidence, and the platform accepts or rejects it.

### Requirements

1. Walk through each stage of the flow and name the machine-learning opportunities in it. Candidate areas include using an LLM to collect complete requirements from the customer, generating step-by-step guidelines the driver can follow, and automatically judging the quality of the uploaded evidence.
2. Choose the opportunity you would build first and justify the choice with its expected impact and cost.
3. For each opportunity you propose, specify:
the prediction target or label, and where the labels come from;
the input features or context;
the serving path and its latency budget;
the main failure modes and the fallback when the model is wrong;
the offline and online metrics that show it works.

## Worked solution

### Solution outline

1. Start with the user action and business outcome, then map the funnel into observable stages and possible interventions. Separate a prediction target from the action the system will take.
2. Pick a simple baseline and one high-value, feasible ML use case using label availability, latency and error costs. For onboarding, instrument activation/retention and avoid optimizing a single click in isolation.
3. Define time-valid labels and a comparison design; consider whether human review, a rule or better instrumentation should come before ML. Consequential decisions require appropriate governance and validation.
4. Propose a small reversible experiment with guardrails and quantify expected impact using explicitly assumed rates, not invented business data.

### Understand why the approach works

#### Design the decision, not only the predictor

State which user action follows the model output, when the prediction occurs and which errors are costly. Then define labels and features using information available at that time. A feature recorded after the outcome is not made legitimate by being stored in the same table.

For a retrieval/ranking product, use a cascade: generate a broad eligible set, score a bounded candidate set, then apply policy and presentation rules. Evaluate retrieval recall separately because a ranker cannot rescue an item excluded upstream. Availability, permissions and budgets are hard constraints, not merely features a model may learn to respect.

Expected action utility can be written as

$$
a^*(x)=\arg\max_a\sum_y P(y\mid x)\,U(a,y).
$$

This makes clear why a probability metric and a product objective are different. The same calibrated probability may produce different actions when error costs change.

Describe a baseline, time/entity-aware validation, exposure logging and one controlled rollout. For a recommender, unexposed items are not automatically observed negatives. For moderation or fraud, mature labels and human-review capacity matter. Finish with a failure walkthrough: what happens when features are stale, the model is unavailable or the distribution changes? A simpler fallback with explicit monitoring is often more defensible than an elaborate system without an operational plan.

### Work a small example

If onboarding abandonment is mainly a broken form, a recommender is not the first fix. If comment prediction is the task, define whether the label is comment occurrence, text content or ranking utility.

### Edge cases and common mistakes

Choosing a sophisticated model before defining a measurable intervention and reliable feedback.

### Check your reasoning on related cases

**Structure an ML system-design answer.** For spam detection, the correct latency and false-positive cost differ between pre-publication blocking and later review.

What should you ask first? What action follows the prediction, and which errors are most costly?

**Design an A/B test for a new ML ranking model.** If users see many recommendations, randomizing each impression can cause cross-treatment contamination; user-level randomization may fit better.

When might a switchback experiment help? Shared marketplaces or systems with interference where treatment changes across time blocks.

**Separate correlation, prediction and causation.** Umbrella use predicts rain but making people carry umbrellas does not cause rain.

Can a noncausal predictor still be useful? Yes for prediction, subject to availability, stability and policy constraints.
