## Question

<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">Given the schemas:

events(event_id, block_id, user_id, event_type, platform)
users(id, subscription_id, country, created_at)

where events.user_id = users.id.

Write a SQL query to count total events per country and return the country (or all tied countries) with the highest number of events.

Output: country, event_count

Scale assumption: events up to 1e8 rows, users up to 1e7 rows.

Example

Input:

users:  (1, US), (2, US), (3, CA)
events: (u1), (u1), (u2), (u3)

Output: US 3</pre>

## Worked solution

1. Join each event to the user dimension on the supplied unique users.id key, then aggregate by country.
2. Use a maximum-count comparison or DENSE_RANK on the count only to retain all tied countries.
3. Define how unmatched users and null countries count; this inner-join example excludes unmatched users. Deduplicate event ids upstream only if duplicate event rows are possible under the data contract.

### Reference query

```sql
WITH counts AS (
 SELECT u.country,COUNT(*) AS event_count
 FROM events e JOIN users u ON u.id=e.user_id
 GROUP BY u.country
)
SELECT country,event_count FROM counts
WHERE event_count=(SELECT MAX(event_count) FROM counts)
ORDER BY country;
```

### Small example / sanity check

Two events from user 1 and one from user 2, both US, contribute US=3, not two distinct users.

### Common trap

Counting users instead of events or arbitrarily discarding a country tied for maximum.
