## Question

Given the schemas:

events(event_id, block_id, user_id, event_type, platform)
users(id, subscription_id, country, created_at)

where events.user_id = users.id.

Write a SQL query to count total events per country and return the country (or all tied countries) with the highest number of events.

Output: country, event_count

Scale assumption: events up to 1e8 rows, users up to 1e7 rows.

Example

### Input

users:  (1, US), (2, US), (3, CA)
events: (u1), (u1), (u2), (u3)

Output: US 3

## Worked solution

### Count events after the many-to-one user join

Assume users.id is unique. Each event contributes once to its user's country; repeated events by one user are separate events, not one active user. An inner join excludes orphan events; choose an UNKNOWN bucket via LEFT JOIN if the product requires their inclusion. NULL country on a matched user forms a NULL group in this query.

```sql
WITH totals AS (
 SELECT u.country,COUNT(*) AS event_count
 FROM events e JOIN users u ON u.id=e.user_id GROUP BY u.country
)
SELECT country,event_count FROM totals
WHERE event_count=(SELECT MAX(event_count) FROM totals);
```

Two events from user1/US, one from user2/US and one from user3/CA produce US=3 and CA=1. The maximum filter returns all tied countries, and empty input returns no rows. Duplicate user dimension rows would inflate counts, so enforce its primary key. For 1e8 events and 1e7 users, a hash join plus aggregation may scan both tables; preaggregating counts by user before the dimension join reduces traffic if users repeat heavily, but does not avoid reading raw events. Materialize country/time rollups only with a declared rule for whether country means event-time country or the current user country. Tests include ties, multiple events/user and unmatched user handling.
