## Question

In a k-means clustering problem, a dataset contains n data points, where the i data point is represented by the feature vector location[i]. The goal is to create k clusters, where the cluster centers (the cluster centroids) can be placed at any point in the feature space. The overall quality of the clustering is measured by the maximum distance between any data point and its nearest cluster center.

The best possible quality is achieved by optimally placing the cluster centers to minimize this maximum distance. Determine this maximum distance between any data point and its nearest cluster center.

Note: The distance between two feature points x and y is defined as |x - y|, where |x| denotes the absolute value of x.

Example

### Input

```python
location = [4, 1, 6, 7, 2]
k = 2
```

### Output

```python
2
```

## Worked solution

### Correct the objective and the conflicting example

This is one-dimensional minimax **k-center**, not squared-error K-means. Under the written rule that centers may be anywhere, the sample's optimal radius is **1.5**, not 2: use centers 2.5 and 6.5 to cover `[1,2,4]` and `[6,7]`. Radius below 1.5 gives intervals shorter than 3; two such intervals cannot cover the sorted points (the greedy check below verifies this). The advertised output 2 is consistent with requiring an integer radius (or integer centers), a restriction absent from the statement. Both contracts are implemented explicitly.

```python
from fractions import Fraction
from itertools import combinations


def minimax_radius(location,k,integer_radius=False):
    if not location or k<1:raise ValueError('nonempty locations and positive k required')
    values=sorted(Fraction(v) for v in location)
    if k>=len(values):return 0 if integer_radius else Fraction(0)
    def feasible(diameter):
        used=0;i=0
        while i<len(values):
            used+=1
            if used>k:return False
            right=values[i]+diameter
            while i<len(values) and values[i]<=right:i+=1
        return True
    if integer_radius:
        lo,hi=0,int((values[-1]-values[0]+1)//2)+1
        while lo<hi:
            mid=(lo+hi)//2
            if feasible(2*mid):hi=mid
            else:lo=mid+1
        return lo
    # Exact solution for arbitrary finite rational inputs; O(n^2) candidates.
    diameters=sorted({b-a for a in values for b in values if b>=a})
    lo,hi=0,len(diameters)-1
    while lo<hi:
        mid=(lo+hi)//2
        if feasible(diameters[mid]):hi=mid
        else:lo=mid+1
    return diameters[lo]/2

assert minimax_radius([4,1,6,7,2],2)==Fraction(3,2)
assert minimax_radius([4,1,6,7,2],2,integer_radius=True)==2
assert minimax_radius([0,10],1)==5
assert minimax_radius([2,2,2],1)==0
# Independent exhaustive contiguous-partition oracle for small integer cases.
for values in ([0,1,4,8],[0,2,3,9,10],[1,1,2,7]):
    for k in range(1,len(values)+1):
        expected=None
        for cuts in combinations(range(1,len(values)),k-1):
            bounds=(0,)+cuts+(len(values),)
            radius=max(Fraction(values[bounds[j+1]-1]-values[bounds[j]],2) for j in range(k))
            expected=radius if expected is None else min(expected,radius)
        assert minimax_radius(values,k)==expected
print('W133: real versus integer radius and exhaustive partition oracle passed')
```

### Greedy feasibility and exact search

For candidate radius r, the leftmost uncovered point a can be covered by placing a center at a+r, covering through a+2r. Moving any covering interval's left edge to a cannot reduce coverage to the right, so this greedy placement uses the fewest intervals by induction. Radius feasibility is monotone, permitting binary search.

For arbitrary rational coordinates, an optimal partition of sorted points into contiguous groups has group radius half its endpoint span. Thus the optimum occurs among pairwise spans/2; the exact implementation searches those candidates using Fraction and returns an exact rational. It costs O(n² log n) time/storage for candidate construction plus O(n log n) feasibility work after sorting; no n bound was provided. For large real-valued inputs, use numeric bisection over `[0,(max-min)/2]` for O(n log(range/tolerance)) time and state an error tolerance. For integer coordinates/radius, integer bisection is exact in O(n log range), implemented separately.

Checks include the conflicting sample under both interpretations, all-identical points, k≥n and an independent exhaustive contiguous-partition oracle. Do not force the real-radius solver to return 2 merely to match an inconsistent sample.
