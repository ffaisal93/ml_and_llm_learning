## Question

An applied-ML coding round: build a model on tabular data that predicts two regression targets jointly, where one target is negative-valued (e.g. in [-1e6, -1]) and the other positive ([10, 1e3]). Because the targets have opposite signs and very different magnitudes, naive joint training is dominated by the larger-scale target. Requirements: flip the sign of the negative task during training, standardize/normalize each target separately so their losses are comparable, train a shared model with two heads minimizing MSE(A) + MSE(B), and de-normalize predictions back to the original space (task A must come out negative again).

## Worked solution

### Normalize targets using training statistics only

No dataset is supplied. The implementation below accepts float tensors `x_train [n,d]` and `y_train [n,2]`, where column A is negative and column B positive; batch tests use a clearly synthetic fixture. Transform A to -A, compute each target's own training mean/std, and fit a shared trunk with two heads. Each head returns `[batch,1]`, concatenated to `[batch,2]`; avoid broadcasting `[batch]` targets against `[batch,1]` predictions.

Optimize the sum of the two per-target standardized MSEs, not unscaled MSE. If A has std 100,000 and B std 100, a 10%-of-std error contributes .01 to each standardized task, instead of $10^8$ versus $10^2$ in raw squared units. Flipping the sign alone does not solve the scale problem. Standardize input features too, with train-only statistics. Split before fitting any transform; use validation for epochs/architecture and report test MAE/RMSE in original units for each task.

```python
import torch
from torch import nn

class TwoHeadRegressor(nn.Module):
    def __init__(self, features):
        super().__init__()
        self.shared = nn.Sequential(nn.Linear(features, 32), nn.ReLU(), nn.Linear(32, 16), nn.ReLU())
        self.head_a, self.head_b = nn.Linear(16, 1), nn.Linear(16, 1)

    def forward(self, x):
        h = self.shared(x)
        return torch.cat((self.head_a(h), self.head_b(h)), dim=1)  # [batch,2]

def fit_two_targets(x_train, y_train, epochs=300, seed=0):
    """Inputs CPU float tensors [n,d], [n,2]; original target A negative."""
    if y_train.ndim != 2 or y_train.shape[1] != 2:
        raise ValueError('expected targets [n,2]')
    if not bool((y_train[:, 0] < 0).all()) or not bool((y_train[:, 1] > 0).all()):
        raise ValueError('task A negative and task B positive required')
    torch.manual_seed(seed)
    xm, xs = x_train.mean(0), x_train.std(0, unbiased=False).clamp_min(1e-6)
    signed = y_train * y_train.new_tensor([-1., 1.])
    ym, ys = signed.mean(0), signed.std(0, unbiased=False).clamp_min(1e-6)
    x, target = (x_train - xm) / xs, (signed - ym) / ys
    model = TwoHeadRegressor(x.shape[1])
    optimizer = torch.optim.Adam(model.parameters(), lr=0.01)
    for _ in range(epochs):
        pred = model(x)
        loss = ((pred - target) ** 2).mean(0).sum()
        optimizer.zero_grad(); loss.backward(); optimizer.step()
    model.eval()
    return model, (xm, xs, ym, ys)

@torch.no_grad()
def predict_two_targets(model, stats, x):
    xm, xs, ym, ys = stats
    signed = model((x - xm) / xs) * ys + ym
    # Standardized linear heads are unbounded. Domain projection enforces signs.
    signed = signed.clamp_min(torch.finfo(signed.dtype).eps)
    return signed * signed.new_tensor([-1., 1.])
```

Inverse transform is `prediction * target_std + target_mean`, then multiply A by -1. Standardized linear outputs are unbounded; the inference function projects the restored magnitudes to a positive epsilon before flipping A, ensuring the requested signs even for out-of-distribution input. Report this projection and monitor how often it activates; it can mask extrapolation error. A positive-output head trained with the corresponding transformed objective is an alternative if strict range behavior is essential. Constant targets use a clamped standard deviation, and no validation/test statistics are used. Tests check restored signs, shape, loss reduction on a synthetic two-task problem and constant-target finiteness; there is no claim of performance on unavailable interview data.
