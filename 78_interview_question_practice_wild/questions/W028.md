## Question

A GPU cluster scheduler receives tasks as a stream. Each task occupies one GPU node for a time range. Build a tracker that records the busy time of every node as tasks arrive and, on request, reports when a node was idle inside a time window.

### What to implement

```text
class GPUIdleIntervalTracker:
def add_task(self, start: int, end: int, node_id: str) -> None: ...
def get_idle_intervals(
self, node_id: str, window_start: int, window_end: int
```

) -&gt; list[tuple[int, int]]: ...
add_task(start, end, node_id): record a task that occupies node node_id during [start, end). Times are integers.
get_idle_intervals(node_id, window_start, window_end): return the idle intervals of that node inside [window_start, window_end), sorted by start time.

### Rules

1. All intervals are half-open: [start, end) contains start but not end.
2. The busy time of a node is the union of its tasks. Tasks that overlap or touch form one busy stretch: [1, 3) and [3, 5) give [1, 5), [1, 4) and [2, 6) give [1, 6), while [1, 3) and [4, 6) stay separate. Tasks may arrive in any order.
3. An idle interval is a maximal stretch of the window that is not busy. Idle intervals are clipped to the window and returned in increasing order.
4. A node that has never received a task is idle for the whole window. An empty window (window_start == window_end) returns [].
5. add_task raises ValueError if start &gt;= end; get_idle_intervals raises ValueError if window_start &gt; window_end. A call that raises changes nothing.
6. Nodes are independent: a task on one node never affects another.

### Examples

Example 1:

```python
tracker = GPUIdleIntervalTracker()
```

tracker.add_task(10, 20, "node-A")
tracker.add_task(30, 40, "node-A")
tracker.add_task(18, 35, "node-A")
tracker.get_idle_intervals("node-A", 0, 50)   # [(0, 10), (40, 50)]

Explanation: the third task overlaps both earlier ones, so the busy time becomes [(10, 40)].

Example 2:

```python
tracker = GPUIdleIntervalTracker()
```

tracker.add_task(5, 10, "node-B")
tracker.add_task(15, 20, "node-B")
tracker.add_task(10, 15, "node-B")
tracker.get_idle_intervals("node-B", 0, 25)   # [(0, 5), (20, 25)]
tracker.get_idle_intervals("node-B", 7, 17)   # []
tracker.get_idle_intervals("node-C", 3, 8)    # [(3, 8)]

Explanation: the three tasks touch end to start and merge into [(5, 20)]. The window [7, 17) lies inside the busy interval, so nothing is idle; node-C never ran a task, so its whole window is idle.

### Constraints

Up to 10^5 calls in total; times fit in 64-bit integers.
Let k be the number of busy intervals on the node, m the number of intervals an insertion merges and r the number of busy intervals that overlap a query window.
add_task should find its position in O(log k) and examine only the m intervals it merges. With a Python list, replacing the merged run shifts the intervals after it whenever the run's length changes and the run is not at the end of the list, so a list-based add_task is O(k) in the worst case; Follow-up 2 asks how to remove that cost.
get_idle_intervals should take O(log k + r) time.
Follow-up 1: complexity

Justify these bounds, and say which step dominates when the busy intervals are kept in a Python list.

Follow-up 2: millions of intervals per node

How would you scale the structure when a node holds millions of busy intervals?

Follow-up 3: cancelling a task

How would you support deleting or cancelling a task after intervals have merged?

Follow-up 4: all nodes

How would you answer an idle-interval query across all nodes?

Follow-up 5: production API

How would you design this as a production API for a distributed GPU scheduler?

## Worked solution

### Keep a sorted, disjoint union per node

Insertion bisects by start, checks the predecessor for overlap/touching and visits only intervals absorbed into the new union. Query bisects to the first possibly intersecting busy interval, then emits clipped positive-length gaps using a cursor. Do not sort all prior tasks on every insertion or scan a million irrelevant intervals for every query.

```python
from bisect import bisect_left, bisect_right


class GPUIdleIntervalTracker:
    def __init__(self):
        self.busy = {}

    def add_task(self, start, end, node_id):
        if start >= end:
            raise ValueError("task must be nonempty")
        intervals = self.busy.setdefault(node_id, [])
        left = bisect_left(intervals, (start,))
        if left and intervals[left - 1][1] >= start:
            left -= 1
        right = left
        while right < len(intervals) and intervals[right][0] <= end:
            start = min(start, intervals[right][0])
            end = max(end, intervals[right][1])
            right += 1
        intervals[left:right] = [(start, end)]

    def get_idle_intervals(self, node_id, window_start, window_end):
        if window_start > window_end:
            raise ValueError("reversed window")
        if window_start == window_end:
            return []
        intervals = self.busy.get(node_id, [])
        result = []
        cursor = window_start
        position = bisect_right(intervals, (window_start, float("inf")))
        if position and intervals[position - 1][1] > window_start:
            position -= 1
        while position < len(intervals):
            start, end = intervals[position]
            if start >= window_end:
                break
            if start > cursor:
                result.append((cursor, min(start, window_end)))
            cursor = max(cursor, min(end, window_end))
            position += 1
        if cursor < window_end:
            result.append((cursor, window_end))
        return result

for a, b in [(10, 20), (30, 40), (18, 35)]:
    t.add_task(a, b, "A")
assert t.get_idle_intervals("A", 0, 50) == [(0, 10), (40, 50)]
for a, b in [(5, 10), (15, 20), (10, 15)]:
    t.add_task(a, b, "B")
assert t.get_idle_intervals("B", 0, 25) == [(0, 5), (20, 25)]
assert t.get_idle_intervals("B", 7, 17) == [] and t.get_idle_intervals("C", 3, 8) == [
    (3, 8)
]
assert t.get_idle_intervals("B", 3, 3) == []
# Independent integer-cell coverage oracle, random insertion order.
import random

rng = random.Random(0)
t = GPUIdleIntervalTracker()
occupied = set()
for _ in range(100):
    a = rng.randrange(-30, 30)
    b = a + rng.randrange(1, 8)
    t.add_task(a, b, "x")
    occupied.update(range(a, b))
    gaps = t.get_idle_intervals("x", -35, 40)
    actual = {p for a, b in gaps for p in range(a, b)}
    assert actual == set(range(-35, 40)) - occupied
before = {k: v[:] for k, v in t.busy.items()}
try:
    t.add_task(1, 1, "new")
except ValueError:
    pass
assert t.busy == before
```

### Bounds and follow-ups

The tests reproduce both examples, unknown/empty windows, touching/bridging intervals and a random integer-cell coverage oracle. Validation happens before any state mutation. Sorted nonoverlapping intervals have strictly increasing ends as well as starts, so the predecessor is the only earlier interval that can overlap a query start; scanning r intersections plus a boundary yields O(log k+r). Insertion finds its position in O(log k) and examines m absorbed intervals, but Python list slice replacement may shift O(k) following entries. This is the acknowledged list limitation, not O(log k+m) worst-case total insertion.

For millions of intervals use a balanced ordered tree/treap or persistent B-tree keyed by start with predecessor/successor iteration and range deletion; insertion is O(log k+m), query O(log k+r), with batched storage/cache-aware choices. Cancellation cannot be recovered from the merged union alone: retain task ids and original intervals plus a coverage-count interval map or event-delta tree, decrementing only that task and emitting gaps where coverage becomes zero. For “all nodes,” return per-node gaps in O(number_of_nodes·log k+total output) using known node inventory; to find times all nodes are idle, union all busy ranges first, while “any node idle” needs coverage counts against inventory. State which interpretation is requested.

A production API can use `PUT /nodes/{id}/tasks/{task_id}` and `GET /nodes/{id}/idle?start=&end=` with idempotency, task version and query snapshot/version. Serialize writes per node or transact tree/count updates, partition by node id, enforce ownership and reject conflicting duplicate task payloads. Persist an event log/snapshots for recovery, bound query/output size, and monitor intervals/node, query p99 and merge/cancellation cost. A recording tracker does not itself prevent double-booking; admission policy is a separate transaction.
