## Question

Build a small similarity search engine over a list of text documents using a bag-of-words representation, written from scratch without scikit-learn or any other vectorizer library. Given a query string, rank the documents by cosine similarity to it and return the best matches.

### What to implement

1. tokenize(text) -&gt; list[str]: split text into tokens.
2. build_vocab(docs) -&gt; dict[str, int]: map each distinct token in a list of documents to an index.
3. vectorize(text, vocab) -&gt; dict[int, int]: the sparse bag-of-words vector of a text, mapping vocabulary index to count.
4. cosine(u, v) -&gt; float: cosine similarity of two sparse vectors.
5. search(query, corpus, k) -&gt; list[tuple[int, float]]: the top k documents of corpus for query, as (document_index, score) pairs.

### Rules

1. Tokenization: convert to lowercase, then a token is a maximal run of the characters a-z and 0-9. Every other character separates tokens. There is no stop-word removal and no stemming.
2. build_vocab assigns indices 0, 1, 2, ... in order of first appearance, reading the documents in order and each document left to right.
3. vectorize uses raw counts (no TF-IDF weighting). A token that is not in the vocabulary is ignored.
4. cosine returns dot(u, v) / (|u| * |v|), or 0.0 when either vector is empty (zero norm).
5. search builds the vocabulary from corpus only, vectorizes the query and every document with it, and scores each document with cosine. Query tokens outside the vocabulary are ignored, so they do not change the query's norm.
6. Scores are rounded to 9 decimal places. The results are sorted by rounded score, highest first; documents with equal rounded score are ordered by lower index first. Documents with score 0.0 are included when fewer than k documents score above zero.
7. Return min(k, len(corpus)) pairs, with the rounded score as the second element; k = 0 returns an empty list.

### Examples

1. tokenize("Hello, World! Hello-2024") returns ["hello", "world", "hello", "2024"]: case is folded and punctuation separates tokens.
2. build_vocab(["b a", "a c"]) returns {"b": 0, "a": 1, "c": 2}, and vectorize("a a c z", vocab) returns {1: 2, 2: 1} because z is not in the vocabulary.
3. search("cat", ["cat sat", "dog", "cat cat dog"], 2) returns [(2, 0.894427191), (0, 0.707106781)]. Document 2 scores 2/sqrt(5), document 0 scores 1/sqrt(2), and document 1 shares no token with the query so it scores 0.0 and falls outside the top 2.
4. search("a", ["a b", "b", "a b"], 3) returns [(0, 0.707106781), (2, 0.707106781), (1, 0.0)]: documents 0 and 2 tie, so the lower index comes first.

### Constraints

Up to 1000 documents of at most 200 tokens each, and 0 &lt;= k &lt;= 1000.
Do not build dense vectors over the whole vocabulary; sparse dictionaries keep a query fast.

## Worked solution

### Solution outline

Represent documents using a shared vocabulary, then compare normalized vectors under a clearly defined weighting scheme.

1. Tokenize consistently and construct term counts or TF-IDF using corpus statistics fitted on the intended index.
2. Transform the query with the same vocabulary and inverse-document-frequency convention.
3. Use cosine similarity, handling zero vectors explicitly, and rank ties deterministically.

### Understand why the approach works

#### Choose the geometry before the update rule

An algorithm's center update follows its objective. Squared Euclidean clustering uses means:

$$
J_2=\sum_i\|x_i-\mu_{c_i}\|_2^2.
$$

For fixed assignments, differentiating with respect to a center sets it to its members' arithmetic mean. Manhattan distance instead uses coordinatewise medians:

$$
J_1=\sum_i\|x_i-m_{c_i}\|_1.
$$

For points $0,2,10$, the squared-error center is $4$, while the absolute-distance center is $2$. Swapping these updates silently solves a different problem.

Alternating nearest-center assignment and an exact fixed-cluster update cannot increase the chosen objective, but it need not reach a global optimum. State initialization, empty-cluster handling, deterministic ties and a stopping rule. Recompute assignments for returned centers after the last update.

For retrieval, state normalization, similarity and relevance labels. Cosine and raw dot product rank differently when embedding norms vary. Index approximation must be evaluated using recall and downstream quality, not latency alone. Negative examples can actually be valid alternative matches; audit this before interpreting a lower contrastive loss as better semantics. Evaluate cluster/retrieval stability across seeds and important slices rather than trusting a visually attractive plot.

### Work a small example

Two documents with proportional count vectors have cosine similarity 1 despite different lengths.

### Edge cases and common mistakes

Fitting a different vocabulary to each document or dividing by zero for an empty/out-of-vocabulary query.
