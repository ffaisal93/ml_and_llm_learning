## Question

<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">Capital One DS Power Day round 3, 45 minutes, role-play. The interviewer plays a non-technical Product Manager who asks why a model that performed well in validation is regressing in production. Explain the likely causes in plain English without technical jargon, and propose a diagnostic plan. The PM applies light pushback (&quot;but we tested it before launch — what changed?&quot;) to test composure.</pre>

## Worked solution

1. Explain a regressing model to a product manager. Translate a metric change into affected decisions, user impact and a concrete next action.
2. State what changed, how reliable the evidence is, which users or slices are affected and the estimated cost.
3. Check deployment differences, feature freshness, label windows and threshold changes; distinguish observations from hypotheses.
4. Recommend rollback, a limited canary or targeted repair with clear success criteria and an owner.
5. Distinguish data drift, concept drift and label delay. A production metric can change because inputs changed, the input-to-label relationship changed, or the labels are not yet mature.
6. Check pipeline health, feature distributions and missingness before assuming the model changed.
7. When mature labels exist, compare conditional performance and calibration on matched slices and periods.
8. Separate delayed outcome windows from true degradation; use operational proxies cautiously and validate them against final outcomes.

### Small example / sanity check

“Recall dropped from 80% to 70% on the same mature-label cohort, adding about 100 missed cases per 1000 actual positives” is more actionable than “the model drifted.”

### Common trap

Blaming an algorithm before checking data and operational changes, or hiding uncertainty behind technical vocabulary.
