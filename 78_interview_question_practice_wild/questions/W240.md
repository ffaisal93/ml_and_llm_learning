## Question

A shuttle operator knows the two-dimensional coordinates of its riders and wants to choose pickup locations that reduce walking distance. Design a practical algorithm for this optimization problem and state honestly what guarantee it provides.

This is a design discussion, not a coding task: describe the method, argue its guarantee and analyse its cost. Pseudocode is welcome, but no runnable code is required.

### Input

points: N rider coordinates (x, y).

```text
K: the number of pickup locations, with 1 <= K <= N.
```

Pickup locations may be any points in the plane; they do not have to coincide with rider coordinates.
Walking distance is Manhattan distance: |x1 - x2| + |y1 - y2|.
What your method must produce
1. Exactly K pickup coordinates, listed in a fixed order (index 0 to K - 1).
2. An assignment of every rider to a nearest pickup. When a rider is equally close to several pickups, it goes to the one with the lowest index.
3. The resulting total walking distance.
Success criteria
1. The general two-dimensional problem need not be solved to global optimality. State its computational difficulty.
2. Give a scalable local-search or approximation method. No accepted iteration may increase the total distance.
3. State the stopping rule, and say that the result is a local solution, not a proven optimum.
4. Discuss initialization, empty clusters, repeated runs, complexity, and how solution quality is measured.
5. When a cluster has an even number of riders, any value between the two middle coordinates is an optimal median. Use the lower median (the smaller middle value) so that results are deterministic.

### Examples

Example 1: points = [(0, 0), (2, 0), (10, 0)], K = 1. One optimal pickup is (2, 0). Assigning all riders there gives total distance 2 + 0 + 8 = 10.

Example 2: points = [(1, 1), (4, 1), (6, 2), (7, 3), (8, 0), (10, 1)], K = 2. An optimal answer is pickup 0 at (1, 1) and pickup 1 at (7, 1).

Rider (4, 1) is at distance 3 from both pickups, so the tie rule assigns it to pickup 0.
Pickup 0 serves (1, 1) and (4, 1), at distances 0 and 3.
Pickup 1 serves (6, 2), (7, 3), (8, 0) and (10, 1), at distances 2, 2, 2 and 3.
The total walking distance is 0 + 3 + 2 + 2 + 2 + 3 = 12, and no choice of two pickups does better.

### Constraints

1 &lt;= N &lt;= 100,000
1 &lt;= K &lt;= min(N, 100)
-10^9 &lt;= x, y &lt;= 10^9
Coordinates and total distance must be handled without overflow.
Follow-up: pickups restricted to rider coordinates

How would the method change if each pickup had to be one of the rider coordinates? Give the update step, its cost, and its guarantee.

## Worked solution

### Alternating L1 k-medians gives a practical local solution

For variable K, the general planar Manhattan k-median problem is computationally hard (NP-hard); do not promise a global optimum for 100,000 riders. Use multiple starts of alternating nearest-center assignment and coordinate-wise median updates. Keep the K center indices fixed throughout; for every assignment, minimize `(distance, center_index)` so ties go to the smaller index.

Initialize K centers using a seeded distance-weighted seeding scheme or a deterministic farthest-point heuristic; those are starting heuristics here, not a claimed approximation ratio. Each iteration assigns every rider, then updates each nonempty cluster to `(lower_median(x),lower_median(y))`. Since Manhattan loss separates into a sum of x and y absolute losses, each coordinate median minimizes its cluster's cost. Keep an empty cluster's old center; this preserves exactly K output coordinates and cannot increase cost. A more ambitious empty-cluster reseed is acceptable only after recomputing and accepting its nonincreasing objective.

After proposed centers are updated, reassign every rider using the same tie rule and compute total distance. Accept only a **strict** cost decrease; if cost is equal or higher, keep the previous centers/assignment and stop. Also stop at an iteration/time budget and report whether convergence was reached. Strict improvement prevents equal-cost cycling, and all median coordinates come from finite input coordinate sets. Each median update cannot worsen the old assignment cost, and reassignment cannot worsen the new-center cost; hence any accepted iteration decreases the objective. This is an alternating-update local solution, not a certificate against arbitrary multi-center swaps or global optimality.

One assignment costs O(NK), and sorting clusters for medians costs at most O(N log N) per iteration; selection algorithms can reduce the median phase to expected O(N). R restarts and I iterations cost O(RI(NK+N log N)), with O(N+K) storage. At K=100, N=100,000, ten million distance evaluations per pass require vectorization/compiled loops and a bounded restart budget. Use at least 64-bit totals: the coordinate bounds permit a total up to about $4\times10^{14}$.

For `(0,0),(2,0),(10,0), K=1`, the coordinate median `(2,0)` costs 10. In Example 2, centers `(1,1),(7,1)` cost 12; `(4,1)` ties and goes to center 0. Its two-rider cluster has lower x median 1, explaining the prescribed even-size rule. Measure quality by best total over repeated starts, variability, a simpler baseline and exact/brute-force comparisons on tiny fixtures; do not infer optimality from an unchanged cost.

If centers must be rider coordinates, update each cluster to its **medoid**, the rider minimizing total Manhattan distance to that cluster. Coordinate-wise medians may not form an existing rider point. Compute each candidate rider's x- and y-distance sums using sorted coordinates and prefix sums in O(s log s) for cluster size s, then choose the best actual rider deterministically. Exact within-cluster medoid updates retain the nonincrease proof; the overall result remains local.
