## Question

A shuttle operator knows the two-dimensional coordinates of its riders and wants to choose pickup locations that reduce walking distance. Design a practical algorithm for this optimization problem and state honestly what guarantee it provides.

This is a design discussion, not a coding task: describe the method, argue its guarantee and analyse its cost. Pseudocode is welcome, but no runnable code is required.

### Input

points: N rider coordinates (x, y).

```text
K: the number of pickup locations, with 1 <= K <= N.
```

Pickup locations may be any points in the plane; they do not have to coincide with rider coordinates.
Walking distance is Manhattan distance: |x1 - x2| + |y1 - y2|.
What your method must produce
1. Exactly K pickup coordinates, listed in a fixed order (index 0 to K - 1).
2. An assignment of every rider to a nearest pickup. When a rider is equally close to several pickups, it goes to the one with the lowest index.
3. The resulting total walking distance.
Success criteria
1. The general two-dimensional problem need not be solved to global optimality. State its computational difficulty.
2. Give a scalable local-search or approximation method. No accepted iteration may increase the total distance.
3. State the stopping rule, and say that the result is a local solution, not a proven optimum.
4. Discuss initialization, empty clusters, repeated runs, complexity, and how solution quality is measured.
5. When a cluster has an even number of riders, any value between the two middle coordinates is an optimal median. Use the lower median (the smaller middle value) so that results are deterministic.

### Examples

Example 1: points = [(0, 0), (2, 0), (10, 0)], K = 1. One optimal pickup is (2, 0). Assigning all riders there gives total distance 2 + 0 + 8 = 10.

Example 2: points = [(1, 1), (4, 1), (6, 2), (7, 3), (8, 0), (10, 1)], K = 2. An optimal answer is pickup 0 at (1, 1) and pickup 1 at (7, 1).

Rider (4, 1) is at distance 3 from both pickups, so the tie rule assigns it to pickup 0.
Pickup 0 serves (1, 1) and (4, 1), at distances 0 and 3.
Pickup 1 serves (6, 2), (7, 3), (8, 0) and (10, 1), at distances 2, 2, 2 and 3.
The total walking distance is 0 + 3 + 2 + 2 + 2 + 3 = 12, and no choice of two pickups does better.

### Constraints

1 &lt;= N &lt;= 100,000
1 &lt;= K &lt;= min(N, 100)
-10^9 &lt;= x, y &lt;= 10^9
Coordinates and total distance must be handled without overflow.
Follow-up: pickups restricted to rider coordinates

How would the method change if each pickup had to be one of the rider coordinates? Give the update step, its cost, and its guarantee.

## Worked solution

### Solution outline

1. Minimize the sum of Manhattan distances to K centers: this is the continuous two-dimensional k-median clustering problem, not squared-Euclidean k-means. General variable-K optimization is computationally difficult, so state a heuristic rather than a global-optimality guarantee.
2. Initialize exactly K indexed centers and assign each rider to its nearest center, resolving ties to the lowest index. For each nonempty cluster update x and y independently to their lower medians; these minimize the cluster’s L1 objective.
3. Keep an empty cluster’s center unchanged for the simple deterministic policy. Reassign/update until assignments or objective stop improving, or an iteration budget is reached; accept no objective increase, and retain the best of multiple seeded starts.
4. A straightforward iteration costs $O(NK)$ assignment plus $O(N \log N)$ total sorting in the worst case for medians, with $O(N+K)$ state. Return centers in their index order, recomputed nearest assignments and the resulting total distance.

### Understand why the approach works

#### State the contract and prove the key invariant

Start with the precise output: any valid solution, the first solution under a tie rule, an exact optimum or a bounded heuristic are different tasks. Name the state/data structure and what stays true after each update.

For half-open intervals $[s,e)$, length is $e-s$. Sorting and merging overlapping/touching ranges gives a disjoint union; summing original lengths would double-count coverage. To find gaps in a query window, advance a cursor through the clipped union, emitting only positive-length holes.

For search/backtracking, write the constraint checked at each decision and what is restored on undo. Choosing the most constrained remaining variable can shrink typical search, but does not turn an exponential worst case into a polynomial algorithm. For clustering geometry, distinguish squared-distance means from absolute-distance medians.

Work a minimum-size case, a tie and an impossible/boundary case. Then state time in terms of input, output and any search-space size; outputting many intervals already costs their number. ### Readable reference implementation

Read the explanation first, then trace one small input through these functions. This is the same implementation used by the local checks; its stated simplifications still apply.

```python
from collections import defaultdict
from functools import lru_cache
import math
import re
import numpy as np


def manhattan_pickups(points,k,max_iter=100):
    """Simple seeded-by-input local solution; no global guarantee."""
    points=np.asarray(points,dtype=float)
    if points.ndim!=2 or points.shape[1]!=2 or not 1<=k<=len(points) or max_iter<1:
        raise ValueError('invalid points/k')
    if not np.isfinite(points).all():raise ValueError('nonfinite point')
    centers=points[:k].copy()
    history=[]
    for _ in range(max_iter):
        distances=np.abs(points[:,None,:]-centers[None,:,:]).sum(-1)
        labels=distances.argmin(1)
        history.append(float(distances[np.arange(len(points)),labels].sum()))
        updated=centers.copy()
        for j in range(k):
            members=points[labels==j]
            if len(members):updated[j]=np.sort(members,axis=0)[(len(members)-1)//2]
        if np.array_equal(updated,centers):break
        centers=updated
    distances=np.abs(points[:,None,:]-centers[None,:,:]).sum(-1)
    labels=distances.argmin(1)
    total=float(distances[np.arange(len(points)),labels].sum())
    return centers,labels,total,history
```

For [(0,0),(2,0),(10,0)] with K=1, lower coordinate medians give (2,0) and total distance 10. For two x-values 1 and 5, choose lower median 1 under the stated deterministic rule.

### Edge cases and common mistakes

Replacing medians by means or claiming the alternating local search proves a global optimum.

### Check your reasoning on related cases

**Implement k-means with convergence and empty clusters.** For [0,1,9,10] with k=2 and sensible initialization, centers converge to 0.5 and 9.5.

How does k-means++ help? It spreads initial centers probabilistically, often reducing poor local solutions.

**Choose the number of k-means clusters.** Increasing k always weakly improves the optimal within-cluster SSE, so lowest training SSE alone selects overly large k.

What if clusters have different densities or non-spherical shapes? Consider other methods rather than forcing k-means geometry.
