## Worked solution

### Solution outline

#### Fit a baseline on messy tabular data without leakage.

Build a trustworthy split and simple baseline before sophisticated feature engineering.

1. Define the target, prediction time and unit of independence, then split by time or group if required.
2. Fit imputation, scaling and category encodings on training folds only. Start with a dummy baseline and a regularized linear or small tree model.
3. Evaluate slices, missingness patterns and calibration; document features unavailable at decision time and remove them.

#### How should you split data for reliable model selection?

The validation procedure must imitate which information will be available when the model is used.

1. Use a final held-out test set and tune only within training/validation data.
2. Use grouped splits for repeated entities and forward-looking splits for time-dependent prediction. Stratification preserves class proportions when compatible with those constraints.
3. Fit the complete preprocessing and model pipeline inside each fold; reserve nested validation for unbiased evaluation of an extensive selection procedure.

#### Why can high accuracy hide failure on imbalanced data?

A model can achieve high accuracy by predicting the common class while missing nearly all important rare events.

1. Inspect class prevalence, the confusion matrix and per-class precision/recall.
2. Choose a metric connected to the decision: PR behavior for rare-event retrieval, calibration for probability-based decisions, and explicit cost curves for thresholds.
3. Try class weights, resampling or focal loss carefully, validating on the natural deployment distribution and recalibrating when needed.

### Understand why the approach works

#### Connect the model, objective and evaluation split

A model class states what relationships can be represented; the objective states which errors training penalizes; the split estimates where those relationships generalize. These are separate choices. For binary logistic regression,

$$
z_i=x_i^\top w+b,\qquad p_i=\sigma(z_i),\qquad
L=\frac1N\sum_i\left[\log(1+e^{z_i})-y_i z_i\right]+\lambda R(w).
$$

Compute the softplus term stably from logits. The derivative of the unregularized per-example loss with respect to its score is $p_i-y_i$. A decision threshold changes actions but does not refit the probability model.

Inspect a simple baseline and training/validation curves before diagnosing high bias or variance. Low training error and poor validation performance may indicate overfitting, entity leakage, an inappropriate split or a genuine distribution change. The remedies differ: regularization does not repair a broken future-information boundary.

Fit scaling, imputation and encoders within training folds. For repeated users, grouped validation can be necessary; for forecasting, preserve the direction of time. Include class imbalance, calibration and subgroup errors rather than reporting only one accuracy number. A model can improve ranking while becoming worse as a probability estimate, and a statistically better estimate can still produce worse decisions at an unsuitable operating threshold.

### Check your reasoning on related cases

**How should you split data for reliable model selection?** A patient's visits belong in the same fold if the deployment target is unseen patients; otherwise identity patterns can leak across folds.

When is a random split reasonable? When examples are sufficiently independent and identically distributed relative to the intended use.

**Why can high accuracy hide failure on imbalanced data?** At 1% positive prevalence, an always-negative classifier has 99% accuracy and zero recall on the positive class.

Why can ROC-AUC look strong while precision is poor? False positives from the large negative population can dominate the positive predictions.
