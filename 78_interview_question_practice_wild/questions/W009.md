## Question

Compute Softmax Entropy with Constant Extra Space

Given a sequence of logits, compute the entropy of its softmax distribution without constructing the probability vector. The implementation must remain stable when logits have very different magnitudes and must scan the input in fixed-size blocks.

### What to implement

Implement compute_entropy_blockwise(logits: List[float], block_size: int) -&gt; float.

logits is a read-only sequence of numeric logits that supports len(logits) and integer indexing logits[i]. It may be lazy: it does not support slicing or iteration, and it is never copied into memory by the caller.
block_size is the maximum number of consecutive input positions processed by each inner scan. The result must not depend on its value.
Return the softmax entropy in nats.

### Rules

1. Use only O(1) auxiliary memory: the peak memory allocated during a call must not grow with len(logits). Do not materialize a softmax vector, a list of weights, or a block copy.
2. Use a numerically stable calculation. Inputs may include negative infinity, which contributes zero probability, but at least one logit must be finite.
3. Raise ValueError when logits is empty, block_size &lt;= 0, a value is NaN or positive infinity, or every value is negative infinity.
4. Do not mutate logits.

### Examples

compute_entropy_blockwise([0.0, 0.0], 1)

```python
# 0.6931471805599453
```

The two outcomes have equal probability, so the result is ln(2).

compute_entropy_blockwise([1000.0, 999.0], 8)

```python
# approximately 0.5822031088882179
```

Subtracting the maximum logit keeps this case finite without changing the probabilities.

### Constraints

1 &lt;= len(logits) &lt;= 1_000_000
1 &lt;= block_size
Each entry is a finite real number or negative infinity.
The result is accepted within standard floating-point tolerance.

## Worked solution

### Solution outline

Entropy can be calculated from normalization statistics without materializing the probability vector.

1. Scan by integer indexing to validate logits and find the finite maximum m; reject NaN, positive infinity, empty input and all-negative-infinity input.
2. Scan again in bounded inner blocks, accumulating Z=sum(exp(x-m)) and S=sum(exp(x-m)*(x-m)); negative infinity contributes zero.
3. Return log(Z)-S/Z. The shifted form avoids subtracting two huge nearly equal unshifted numbers. Keep only scalar accumulators.

### Understand why the approach works

#### Eliminate the probability vector algebraically

Choose $m=\max_i z_i$ and define shifted weights $w_i=e^{z_i-m}$ and $Z=\sum_iw_i$. Then $p_i=w_i/Z$ and

$$
H(p)=-\sum_i p_i\log p_i
=\log Z-\frac{\sum_iw_i(z_i-m)}{Z}.
$$

This identity requires only a maximum and two scalar sums. First scan the indexed input to validate values and find $m$; scan again to accumulate $Z$ and the weighted shifted sum. A block controls each inner loop's index range; no slice or block array is needed, so auxiliary memory remains $O(1)$.

For logits $[1000,999]$, shifting gives $[0,-1]$, $Z=1+e^{-1}$, and the weighted sum is $-e^{-1}$. The entropy is approximately $0.582203109$ nats. Computing huge unshifted exponentials would overflow even though the answer is ordinary-sized.

A negative-infinity logit has zero probability and should be skipped in the weighted sum: evaluating $0\cdot(-\infty)$ gives NaN. Empty input, nonpositive block size, NaN, positive infinity and an all-negative-infinity sequence violate the stated contract. Validate before publishing a result.

Test an object that supports only integer indexing and `len`: this catches accidental slicing or iteration hidden in convenient NumPy conversion. Changing block size must not change the mathematical result apart from harmless floating-point accumulation effects.

### Readable reference implementation

Read the explanation first, then trace one small input through these functions. This is the same implementation used by the local checks; its stated simplifications still apply.

```python
import math
from collections import deque
from dataclasses import dataclass
import numpy as np


def compute_entropy_blockwise(logits, block_size):
    """Two scalar scans; supports len/index-only lazy inputs and negative infinity."""
    n = len(logits)
    if n == 0 or block_size <= 0:
        raise ValueError("empty input or non-positive block size")
    maximum = -math.inf
    for start in range(0, n, block_size):
        for i in range(start, min(start + block_size, n)):
            x = float(logits[i])
            if math.isnan(x) or x == math.inf:
                raise ValueError("invalid logit")
            maximum = max(maximum, x)
    if maximum == -math.inf:
        raise ValueError("at least one logit must be finite")
    z_sum, weighted_shift = 0.0, 0.0
    for start in range(0, n, block_size):
        for i in range(start, min(start + block_size, n)):
            x = float(logits[i])
            if x == -math.inf:
                continue
            shift = x - maximum
            weight = math.exp(shift)
            z_sum += weight
            # Avoid 0 * -inf after subtraction overflows for extreme finite inputs.
            if weight:
                weighted_shift += weight * shift
    return math.log(z_sum) - weighted_shift / z_sum
```

### Work a small example

For [0,0], Z=2 and S=0, so entropy is log(2). For one finite logit and the rest negative infinity, entropy is zero.

### Edge cases and common mistakes

Using slices or copying each block, which breaks the read-only lazy-sequence and $O(1)$-memory requirements.
