## Worked solution

### ML basics: answer the actual task and metric

Classification predicts a discrete label or class probabilities; regression predicts a numeric value. Use binary cross-entropy for Bernoulli labels, multiclass cross-entropy for mutually exclusive classes, squared error for a conditional mean and absolute error for a conditional median. Loss is the training objective; the product decision metric can differ.

Precision is $TP/(TP+FP)$, recall $TP/(TP+FN)$ and $F_1=2TP/(2TP+FP+FN)$, the harmonic mean of precision and recall. If TP=8, FP=2 and FN=4, precision=.8, recall=.667 and F1=.727. F1 is useful when both false positives and false negatives matter and true negatives need not dominate; it assumes an implicit trade-off and is inappropriate when explicit costs or calibrated probabilities determine actions. State zero-denominator rules and macro versus micro averaging.

Benchmark a dummy/domain baseline and candidate on the same frozen leakage-free test units, report uncertainty and important slices, and count failures in the denominator. Training learns parameters, validation selects hyperparameters/thresholds, and final test estimates the frozen procedure. Group repeated users/documents and preserve time for future prediction; fit transforms only on training folds. Accuracy can hide minority failure, so include PR behavior/calibration as appropriate.

### Serving and agents

Quantization reduces weight/activation/cache bytes with possible quality loss; measure kernels on target hardware. Batching amortizes work but can increase queue delay; continuous batching admits/removes active requests each step. A KV cache reuses earlier keys/values during autoregressive decode, trading memory for avoided repeated prefix computation. Benchmark TTFT, inter-token latency, end-to-end tails and throughput together, with bounded queues and overload policies.

An agent service persists task/step state, stable operation ids, tool versions and explicit stop conditions. Validate tool arguments and permissions outside the model. Retry reads with deadlines; reconcile uncertain writes using the same provider idempotency key. Record outcomes, tool failures, cost and latency; canary model/prompt/tool changes against fixed end-to-end tasks, then roll back configuration if needed. A transcript is not a durable operation ledger.

### Transformer, context and evidence

A decoder block combines causal self-attention, residual paths, normalization and a per-token feed-forward network. $Q=XW_Q$ asks what to retrieve, $K=XW_K$ describes matches and $V=XW_V$ supplies content; attention is $\operatorname{softmax}(QK^T/\sqrt{d_k}+M)V$. Heads learn multiple feature spaces and positional encoding supplies order. Encoder attention is bidirectional over allowed tokens; a decoder's mask prevents future access.

Prompting writes instructions/examples for a call. Context engineering also selects, retrieves, compresses and budgets tools, history, memory and evidence across calls. RAG ingests versioned authorized documents, retrieves/reranks relevant chunks, generates with evidence ids and returns supported citations or abstains. Grounding means claims can be checked against appropriate evidence; a citation string alone does not prove entailment, and a faithfully quoted outdated document can still give a currently wrong answer.

Guardrails include input/output policy checks, prompt-injection boundaries, tool allowlists, resource authorization, schema/semantic validation and high-risk escalation. Content filters do not enforce account permissions; syntactically valid JSON can still request an unauthorized transfer. Test adversarial prompts and data, monitor real violations and keep failure/human fallback paths.
