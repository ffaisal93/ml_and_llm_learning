## Question

<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">Value iteration and policy iteration are the two classical dynamic-programming methods for solving a Markov decision process whose transition model is known. In this exercise the MDP is a small grid world, Frozen Lake: an agent walks on ice towards a goal and must avoid holes, and on slippery ice a move can go sideways. You compute the optimal state values and an optimal policy with both methods.

The environment

The default map is a 4x4 grid. Rows are listed top to bottom.

S F F F
F H F H
F F F H
H F F G
S: start (safe). F: frozen surface (safe). H: hole, a terminal state. G: goal, a terminal state.
States are numbered row by row, so the start is state 0 and the goal of the 4x4 map is state 15.
Actions: 0 = left, 1 = down, 2 = right, 3 = up. A move into the border leaves the agent where it is.
Reward: +1 when a move enters G, 0 otherwise (the reward_schedule default (1.0, 0.0, 0.0)).
With is_slippery=True the agent moves in the intended direction with probability success_rate, and in each of the two perpendicular directions with probability (1 - success_rate) / 2. With is_slippery=False the intended move always happens.
G and H are absorbing: every action keeps the agent there with reward 0.

The class FrozenLakeEnv (standalone, no Gym needed) is given in full under &quot;Environment code&quot; at the end. Use env.nS, env.nA and the transition table env.P, where env.P[s][a] is a list of (probability, next_state, reward, done) tuples. Do not change the class.

What to implement
value_iteration(env, gamma=0.95, tol=1e-8, max_iterations=10000) -&gt; (V, policy)
policy_iteration(env, gamma=0.95, tol=1e-8, max_iterations=1000) -&gt; (V, policy)

Arguments: env is a FrozenLakeEnv; gamma is the discount factor; tol is the convergence threshold on the largest value change in one sweep; max_iterations caps the number of sweeps (value iteration) or improvement rounds (policy iteration).

Both functions return V, a float NumPy array of length env.nS with the optimal value of each state, and policy, an integer NumPy array of length env.nS with the optimal action of each state.

Rules
1.
The value of a state is the expected discounted sum of rewards, Q(s, a) = sum over (p, s&#x27;, r, done) in env.P[s][a] of p * (r + gamma * V[s&#x27;]), and the optimal value satisfies V[s] = max over a of Q(s, a). Terminal states have value 0.
2.
value_iteration starts from V = 0, sweeps over all states updating V[s] to max_a Q(s, a), and stops when the largest change in a sweep is below tol. The policy is greedy with respect to the final V.
3.
policy_iteration starts from the policy that always plays action 0, evaluates the current policy until the largest change in a sweep is below tol, then improves it greedily, and stops when no action changes.
4.
The returned policy is greedy: in every state its action has a Q(s, a) within 1e-6 of the best one under the returned V. When two actions are exactly tied, as down and right are at the start of the deterministic 4x4 map, return the smaller index.
5.
Both methods must give the same V (to within 1e-4) on the same environment and gamma; for the gamma and tol ranges in the constraints this is achievable, because each result is within about tol / (1 - gamma) of the true optimum.
6.
Do not call env.step or env.reset: the model is known, so no sampling is needed.
Examples
env = FrozenLakeEnv(is_slippery=False)
V, policy = value_iteration(env, gamma=0.95)
# V[0] is about 0.7738 (= 0.95 ** 5) and policy[0] == 1
On deterministic ice the shortest safe path from the start to the goal takes 6 moves, and the reward arrives on the last one, so the value of the start is 0.95 ** 5. Down and right are equally good at the start; the smallest index is down (1).
env = FrozenLakeEnv(is_slippery=True, success_rate=0.8)
V, policy = policy_iteration(env, gamma=0.95)
# V[0] is about 0.5312; V[5] == V[7] == V[11] == V[12] == V[15] == 0 (holes and goal)
Slipping can push the agent into a hole, so the value of the start is lower than in the deterministic case, even though the policy is similar.
Constraints
Maps up to 8x8 (env.nS &lt;= 64), 4 actions, 0 &lt; gamma &lt;= 0.99.
1e-12 &lt;= tol &lt;= 1e-6.
Python 3 with NumPy.

# Transition model

def _build_transition_model(self) -&gt; Dict[int, Dict[int, List[Tuple[float, int, float, bool]]]]:
P = {s: {a: [] for a in range(self.nA)} for s in range(self.nS)}
for r in range(self.nrow):
for c in range(self.ncol):
s = self.to_state(r, c)
for a in range(self.nA):
P[s][a] = self._calculate_transitions(r, c, a)
return P

def _calculate_transitions(self, r: int, c: int, a: int):
transitions = []
letter = self.desc[r, c].decode(&quot;utf-8&quot;)
if letter in &quot;GH&quot;:  # terminal states
transitions.append((1.0, self.to_state(r, c), 0.0, True))
return transitions

def move(row, col, act):
if act == self.LEFT:
col = max(col - 1, 0)
elif act == self.DOWN:
row = min(row + 1, self.nrow - 1)
elif act == self.RIGHT:
col = min(col + 1, self.ncol - 1)
elif act == self.UP:
row = max(row - 1, 0)
return row, col

possible_actions = [a]
probs = [1.0]
if self.is_slippery:
# random left/right with some probability
left = (a - 1) % 4
right = (a + 1) % 4
intended = a
possible_actions = [intended, left, right]
probs = [self.success_rate, (1 - self.success_rate) / 2, (1 - self.success_rate) / 2]

for act, p in zip(possible_actions, probs):
newr, newc = move(r, c, act)
newstate = self.to_state(newr, newc)
newletter = self.desc[newr, newc].decode(&quot;utf-8&quot;)
done = newletter in &quot;GH&quot;
if newletter == &quot;G&quot;:
reward = self.reward_schedule[0]
elif newletter == &quot;H&quot;:
reward = self.reward_schedule[1]
else:
reward = self.reward_schedule[2]
transitions.append((p, newstate, reward, done))
return transitions

def step(self, action: int) -&gt; Tuple[int, float, bool, bool, dict]:
assert 0 &lt;= action &lt; self.nA
transitions = self.P[self.state][action]
probs = [p for p, _, _, _ in transitions]
i = np.random.choice(len(transitions), p=probs)
p, next_state, reward, done = transitions[i]
self.state = next_state
self.last_action = action
return next_state, reward, done, False, {}

## Worked solution

1. Implement value iteration for a finite MDP. Repeated Bellman optimality backups improve the estimate of long-run discounted return.
2. Specify transition probabilities, immediate rewards, terminal states and discount gamma<1 for the standard contraction setting.
3. Update V_new(s)=max_a sum_s' P(s'|s,a)*(R(s,a,s')+gamma*V(s')), with terminal treatment explicit.
4. Stop on a convergence criterion or iteration cap, then derive the greedy policy from the final values.
5. Compare policy iteration with value iteration. Policy iteration alternates evaluating a whole policy and improving it; value iteration interleaves shorter optimality updates.
6. For a fixed policy, solve or iteratively approximate V_pi=R_pi+gamma*P_pi*V_pi.
7. Improve by choosing actions greedy with respect to the evaluated values.
8. Repeat until the policy stabilizes, explaining evaluation accuracy and tie rules; compare computational cost per iteration as well as iteration count.

### Small example / sanity check

An action giving reward 1 forever at gamma=0.9 has value 1/(1-0.9)=10.

### Common trap

Bootstrapping from a terminal state as if it continues generating rewards.
