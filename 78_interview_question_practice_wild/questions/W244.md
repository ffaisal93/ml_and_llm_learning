## Question

<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">A small internal chat service answers commands such as !help with a mock reply. It is written as one function with a global message list and a chain of if/elif prefix checks. Refactor it into an object-oriented design in which every command is its own bot, every channel keeps its own history and its own list of bots, and one server routes messages to channels. The old entry point llm_response must keep returning exactly the same strings.

Legacy code
messages = []   # All chat history in one place

def llm_response(user_id: str, text: str) -&gt; str:
&quot;&quot;&quot;Legacy function with mock LLM responses.&quot;&quot;&quot;
messages.append({&quot;user&quot;: user_id, &quot;text&quot;: text})

if text.startswith(&quot;!help&quot;):
return &quot;[help] Available commands: !help, !schedule, !weather&quot;
elif text.startswith(&quot;!schedule&quot;):
return f&quot;[schedule] Okay {user_id}, your meeting is scheduled.&quot;
elif text.startswith(&quot;!weather&quot;):
return &quot;[weather] It is sunny today.&quot;
elif text.startswith(&quot;!echo&quot;):
return text[5:]
else:
return &quot;[error] Unknown command.&quot;
What to implement
1.
class Bot(ABC) with two abstract methods: can_handle(text: str) -&gt; bool (is this bot responsible for the message) and handle(user_id: str, text: str) -&gt; str (the reply).
2.
Four concrete bots, each with the prefix test and the reply of the matching legacy branch: HelpBot (!help), ScheduleBot (!schedule), WeatherBot (!weather) and EchoBot (!echo).
3.
class ChatChannel with the constructor ChatChannel(name: str, bots: list[Bot]), the attributes name, bots and messages (a list of {&quot;user&quot;: user_id, &quot;text&quot;: text} dicts, oldest first), and the methods record_message(user_id, text) -&gt; None and dispatch(user_id, text) -&gt; str.
4.
class ChatServer with the constructor ChatServer(), the attribute channels (a dict from channel name to ChatChannel), register_channel(name: str, bots: list[Bot]) -&gt; None and send_message(channel: str, user_id: str, text: str) -&gt; str.
5.
llm_response(user_id: str, text: str) -&gt; str, a thin wrapper that sends the message to the channel &quot;default&quot; of one module-level server. That channel has all four bots, in the order help, schedule, weather, echo.
Rules
1.
send_message finds the channel, records the message in that channel&#x27;s own messages list, then dispatches it.
2.
dispatch asks the bots in list order and returns the reply of the first bot whose can_handle is true. If no bot accepts the text, it returns &quot;[error] Unknown command.&quot;.
3.
A channel only knows its own bots: a command whose bot is not in the channel&#x27;s list gets the unknown-command reply, even if another channel has that bot.
4.
Histories are isolated: a message sent to one channel never appears in another channel&#x27;s messages.
5.
register_channel with an existing name replaces that channel, including its history.
6.
send_message to a channel that was never registered raises ValueError.
7.
The old module-level messages list does not need to exist any more. Only the return values of llm_response have to stay identical to the legacy ones, for every (user_id, text).
8.
A bot matches on the prefix only, as in the legacy code: &quot;!echoes&quot; is an echo message and &quot;!help me&quot; is a help message.
Examples
server = ChatServer()
server.register_channel(&quot;channelA&quot;, [HelpBot(), ScheduleBot(), WeatherBot()])
server.register_channel(&quot;channelB&quot;, [WeatherBot(), EchoBot()])

server.send_message(&quot;channelA&quot;, &quot;u1&quot;, &quot;!help&quot;)
# &quot;[help] Available commands: !help, !schedule, !weather&quot;
server.send_message(&quot;channelB&quot;, &quot;u2&quot;, &quot;!echo hello&quot;)
# &quot; hello&quot;  (the legacy code returns text[5:], so the leading space stays)
server.send_message(&quot;channelB&quot;, &quot;u2&quot;, &quot;!help&quot;)
# &quot;[error] Unknown command.&quot;  (channelB has no HelpBot)
server.channels[&quot;channelA&quot;].messages
# [{&quot;user&quot;: &quot;u1&quot;, &quot;text&quot;: &quot;!help&quot;}]
llm_response(&quot;u3&quot;, &quot;!schedule&quot;)
# &quot;[schedule] Okay u3, your meeting is scheduled.&quot;
The first call is answered by HelpBot of channelA; only channelA records it.
The second call shows that the echo reply is the text after the five characters of !echo, unchanged.
The third call shows rule 3.
Constraints
Plain Python 3, standard library only.
Bot objects hold no per-message state; the same bot instance may be shared by several channels.
At most 100 channels, 10 bots per channel and 10^4 messages per channel.</pre>

## Worked solution

1. First preserve observable behavior with characterization tests for normal inputs, ordering, errors and state changes. Extract pure parsing/routing logic from mutable state and external I/O.
2. Represent each bot or handler behind a small interface; use a registry for dispatch and explicit per-channel/conversation state. Make ownership, reset and history retention visible rather than using hidden globals.
3. Inject clocks, model clients and storage so behavior can be tested without a live service. Add concurrency control only around the state that needs it and preserve the existing message/response contract.
4. Ship small verified changes. A longer-term design can add typed requests, bounded context, logging and persistence, but should not silently alter semantics during the refactor.

### Small example / sanity check

A new prefix handler should be registered without modifying every existing bot. Two channels should not share a conversation history unless that sharing is intentional.

### Common trap

Rewriting the entire program and calling it a behavior-preserving refactor.
