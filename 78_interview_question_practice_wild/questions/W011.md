## Question

When a language model generates text, it produces a score (logit) for every token in its vocabulary and the decoder picks the next token from them. Top-p (nucleus) sampling keeps only the most likely tokens whose combined probability reaches a threshold p, then samples among those. Implement it in two functions: one that computes the kept set (the nucleus), and one that samples a token from it.

### What to implement

```text
def top_p_filter(logits, p, temperature=1.0) -> tuple[list[int], np.ndarray]: ...
    def top_p_sample(logits, p, temperature=1.0, rng=None) -> int: ...
```

logits: a list or 1-D NumPy array of V finite floats, one per token id 0 .. V-1. Do not modify it.

```text
p: the probability threshold, a float with 0 < p <= 1.
temperature: 0 (greedy) or a float with 0.01 <= temperature <= 100 (default 1.0).
```

rng: an object with a random() method that returns a float in [0, 1), such as numpy.random.default_rng(seed). If it is None, use numpy.random.default_rng().
top_p_filter returns (indices, probs): the nucleus token ids, most likely first, and a NumPy array of their probabilities, renormalised to sum to 1.
top_p_sample returns one token id (an int in the original vocabulary indexing).

### Rules

1. If temperature &gt; 0, the probabilities are softmax(logits / temperature). Compute the softmax stably: subtract the largest scaled logit before exp, so logits such as 1000.0 do not overflow.
2. Sort tokens by probability, highest first. Equal probabilities keep the smaller token id first.
3. The nucleus is the shortest prefix of that order whose cumulative probability (summed in float64, in order) is at least p - 1e-12. The 1e-12 tolerance absorbs rounding, so a prefix that reaches p exactly is enough. The nucleus never holds more than V tokens.
4. If temperature == 0, decoding is greedy: the nucleus is the single token with the largest logit (the smallest id among ties), with probability 1.0.
5. top_p_sample calls top_p_filter. If temperature == 0 it returns the nucleus token and does not call rng.random(). Otherwise it calls rng.random() exactly once to get u, and returns the first nucleus token whose renormalised cumulative probability is strictly greater than u (the last nucleus token if rounding leaves none).
6. Raise ValueError if logits is empty, p is not in (0, 1], or temperature is negative, between 0 and 0.01 (exclusive), or above 100. A positive temperature that small would push the scaled logits to infinity.

You may use NumPy and the Python standard library.

### Examples

In the examples, FixedRng(u) is an object whose random() returns u.

Example 1

top_p_filter([2.0, 1.0, 0.5, -1.0], p=0.8)
-&gt; ([0, 1], array([0.73105858, 0.26894142]))
top_p_sample([2.0, 1.0, 0.5, -1.0], p=0.8, rng=FixedRng(0.5)) -&gt; 0
top_p_sample([2.0, 1.0, 0.5, -1.0], p=0.8, rng=FixedRng(0.9)) -&gt; 1

```text
Explanation: the softmax is about [0.6095, 0.2242, 0.1360, 0.0303]. Token 0 alone has 0.6095 < 0.8; adding token 1 gives 0.8337 >= 0.8, so the nucleus is tokens 0 and 1. Renormalised, they are 0.7311 and 0.2689. A draw of 0.5 falls in token 0's share; 0.9 is past 0.7311, so it picks token 1.
```

Example 2

top_p_filter([1.0, 3.0, 3.0], p=0.5)
-&gt; ([1, 2], array([0.5, 0.5]))
top_p_sample([1.0, 3.0, 3.0], p=0.5, rng=FixedRng(0.5)) -&gt; 2

Explanation: tokens 1 and 2 tie at 0.4683, so token 1 comes first. Token 1 alone is below 0.5, so token 2 is added (cumulative 0.9366). The cumulative probabilities are [0.5, 1.0]; the first one strictly greater than 0.5 belongs to token 2.

Example 3

top_p_sample([1.0, 3.0, 3.0], p=0.9, temperature=0) -&gt; 1

Explanation: temperature 0 is greedy. Tokens 1 and 2 share the largest logit, so the smaller id, 1, is returned without a draw.

### Constraints

1 &lt;= V &lt;= 10^5.
Every logit is finite and at most 10^4 in absolute value.
0 &lt; p &lt;= 1; temperature is 0 or in [0.01, 100].
Time: O(V log V); with V = 10^5 one filter plus one sample must finish within 2 seconds in the browser runtime.
Follow-up: top-p versus top-k

Top-k sampling always keeps the k most likely tokens. When does top-p behave better than top-k, and when can it keep a very large set of tokens?

## Worked solution

### Solution outline

Keep the smallest highest-probability prefix whose cumulative mass reaches p, then renormalize and sample.

1. Compute stable softmax and sort token indices by descending probability.
2. Find the first cumulative sum >=p and include that boundary token. Always keep at least one token.
3. Sample from the retained probabilities after renormalization, then map back to vocabulary ids. Define p in (0,1].

### Understand why the approach works

#### Define the candidate set before sampling

Sampling has three operations: choose retained tokens, normalize their scores, and draw a vocabulary id. With temperature $\tau>0$ and retained set $S$,

$$
P(i\mid i\in S)=\frac{\exp(z_i/\tau)}{\sum_{j\in S}\exp(z_j/\tau)}.
$$

Top-$k$ defines $S$ as the $k$ largest logits. Temperature changes the distribution within that fixed set but does not change its ordering for positive $\tau$. With logits $[1,2,0.5,4]$ and $k=2$, only original ids 1 and 3 may be returned. A local index zero in the two-element candidate array is not necessarily vocabulary id zero.

For top-$p$, first sort probabilities $p_{(1)}\ge\cdots\ge p_{(V)}$ and choose

$$
k^*=\min\left\{k:\sum_{j=1}^k p_{(j)}\ge p\right\}.
$$

Include the token that crosses the threshold, then renormalize. For $[0.6,0.25,0.15]$ and threshold $0.8$, retain the first two tokens, whose mass is $0.85$. Keeping only the first would fail the requested coverage.

A readable reference sorts in $O(V\log V)$; partial selection can improve top-$k$ selection cost but needs a deliberate equal-score rule. Use an explicit random generator to reproduce experiments. Test $k=1$, $k=V$, $p=1$, very small positive $p$ and tied logits. A fixed seed does not guarantee identical sequences after a change in floating-point reduction or the number/order of random draws.

### Readable reference implementation

Read the explanation first, then trace one small input through these functions. This is the same implementation used by the local checks; its stated simplifications still apply.

```python
import math
from collections import deque
from dataclasses import dataclass
import numpy as np


def log_softmax(x, axis=-1):
    x = np.asarray(x, dtype=np.float64)
    if x.size == 0 or not np.isfinite(x).all():
        raise ValueError("expected non-empty finite logits")
    z = x - np.max(x, axis=axis, keepdims=True)
    return z - np.log(np.exp(z).sum(axis=axis, keepdims=True))


def softmax(x, axis=-1):
    return np.exp(log_softmax(x, axis=axis))


def nucleus_candidates(logits, p, temperature=1.0):
    x = np.asarray(logits, dtype=np.float64)
    if x.ndim != 1 or not 0 < p <= 1 or temperature <= 0:
        raise ValueError("invalid logits, p or temperature")
    probs = softmax(x / temperature)
    order = np.argsort(-probs, kind="stable")
    count = min(len(order), int(np.searchsorted(np.cumsum(probs[order]), p)) + 1)
    ids = order[:max(1, count)]
    selected = probs[ids]
    return ids, selected / selected.sum()


def sample_top_p(logits, p, rng=None, temperature=1.0):
    rng = np.random.default_rng() if rng is None else rng
    ids, probs = nucleus_candidates(logits, p, temperature)
    return int(rng.choice(ids, p=probs))
```

### Work a small example

For probabilities [0.6,0.25,0.15] and p=0.8, keep the first two tokens because their combined mass is 0.85.

### Edge cases and common mistakes

Dropping the token that first crosses the threshold, which retains less probability mass than requested.
