<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">Task: Debug an NLP Classifier Training Pipeline (BERT + Linear)

You are given a training codebase skeleton for text classification (you may choose a PyTorch or TensorFlow implementation). The high-level components include:

Dataset
DataLoader
Customized Model   (Transformer/BERT + a few Linear layers)
Trainer            (similar to HuggingFace Transformers)

The code contains multiple bugs that prevent training/evaluation from running correctly or produce incorrect metrics. Your task is to debug and fix the pipeline within a limited time.

Issues you are expected to identify and fix (cover at least these areas)

1. Dataset / label parsing

The dataset parses label as a string.
Training expects labels in a numeric form usable by the loss function (e.g., int / tensor).

2. One-hot encoding bug

A one-hot encoding snippet is provided and can replace the current label logic.
However, the provided one-hot implementation has a dimension/shape mismatch that must be fixed.

3. Incorrect use of model output (last_hidden_state)

The model uses a BERT/Transformer output for classification.
The current usage of last_hidden_state is incorrect, leading to wrong shapes or an invalid classifier head input. Fix it (e.g., choose an appropriate pooling strategy or token representation).

4. Loss bug: applying Softmax before CrossEntropy

The implementation applies softmax before cross entropy loss.
Fix it to follow the correct usage for the chosen framework.

5. AUC metric input/parameter bug

The AUC computation has incorrect inputs and/or key parameters, causing errors or wrong results.
Fix the AUC call so it matches the binary or multiclass setting.

6. Training detail checks

Verify dropout behavior (train vs eval mode).
Verify no incorrect requires_grad settings that freeze parameters unintentionally.
Deliverables

## Worked solution

1. A classifier's loss does not decrease. What do you check first? Use a small controlled problem to distinguish a broken training loop from a difficult learning task.
2. Check target encoding, logits/loss compatibility, preprocessing, train mode, optimizer parameters and zero_grad/backward/step order.
3. Inspect finite activations and gradients, then confirm that parameters change. Try overfitting a tiny batch.
4. Once basic learning works, sweep learning rate and compare a simple baseline; change one factor at a time.
5. Fit a baseline on messy tabular data without leakage. Build a trustworthy split and simple baseline before sophisticated feature engineering.
6. Define the target, prediction time and unit of independence, then split by time or group if required.
7. Fit imputation, scaling and category encodings on training folds only. Start with a dummy baseline and a regularized linear or small tree model.
8. Evaluate slices, missingness patterns and calibration; document features unavailable at decision time and remove them.

### Apply the exact contract

Inspect the tokenizer/model pairing, attention masks, hidden-state selection and classifier-head dimension. Use raw classification logits with cross-entropy and integer class labels; ensure encoder/head parameters are in the optimizer if intended. Verify device placement, train/eval state and gradient flow. Pooling a padding token or feeding probabilities into a logits loss are independent bugs that a tiny-batch overfit test can reveal.

### Small example / sanity check

Passing softmax probabilities into a loss expecting logits applies a second normalization and can produce weak or misleading gradients.

### Common trap

Blaming insufficient model size before proving that the optimizer is updating the intended parameters.
