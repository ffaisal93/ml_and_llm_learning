## Question

Problem: Model the Distribution of LLM Decoding Stopping Time and Implement a Minimax Strategy Against Adversaries

In a simplified LLM decoding process, at each step the model may emit a special token &lt;STOP&gt; and terminate. You must do two things.

Part A: Stopping-Time Distribution

Given a maximum length N (generation runs for at most N tokens; if it does not stop early, it is forced to stop at N) and a per-step stop probability sequence:

At step t (1-indexed), the probability of emitting &lt;STOP&gt; is p[t] (0 &lt;= p[t] &lt;= 1)
If it does not stop at step t, it proceeds to step t+1

Compute:

For all t = 1..N, the stopping-time probability P(T=t)
The expected stopping time E[T]

## Worked solution

### Part A: use survival probability

Let $S_t=P(T\ge t)=\prod_{j<t}(1-p_j)$, with $S_1=1$. For $t<N$,

$$P(T=t)=S_tp_t.$$

At the last position, **all** remaining mass stops, whether STOP is emitted or the length cap fires:

$$P(T=N)=S_N,\qquad E[T]=\sum_{t=1}^N tP(T=t)=\sum_{t=1}^N S_t.$$

Using $S_Np_N$ as the final mass incorrectly discards forced-stop outcomes. In particular, the distribution of T is independent of $p_N$ under this definition. Compute survival in one pass, multiplying rather than enumerating every possible token sequence.

### Part B: state the missing decision contract

The prompt leaves decisions and adversary payoffs unspecified. There is no unique optimal policy without them. The following complete interface handles a **finite set of deterministic actions** and an adversary that chooses one fixed mechanism after seeing our action:

$$a^*=\arg\max_{a\in A}\min_{m\in\{1,\ldots,M\}}
\sum_tP_m(T=t)R_m(a,t).$$

It does not solve a mixed-strategy game or an adversary that changes behavior after every observation. Those require different optimization/dynamic-programming specifications.

### JSON input and output

Input contains `N`, base probabilities `p`, distinct scalar action labels `decisions`, and `adversaries`. Each adversary has its own length-N `p` and an A-by-N `rewards` table ordered by decisions. Output is JSON with the base PMF, expected T, selected action and worst-case expected reward. Ties use the first listed action. For arbitrary callable rewards, use `minimax` directly instead of serializing code.

```json
{"N":2,"p":[0.5,0],"decisions":["A","B"],"adversaries":[
 {"p":[1,0],"rewards":[[2,2],[1,1]]},
 {"p":[0,0],"rewards":[[0,0],[1,1]]}]}
```

The base PMF is `[0.5,0.5]`, expectation 1.5. A has worst reward zero, B has worst reward one, so choose B.

```python
"""W075 finite-action minimax. Run: python stopping_075.py < input.json"""

import json
import math
import sys


def stopping_distribution(probabilities):
    if not probabilities or any(
        not math.isfinite(p) or not 0 <= p <= 1 for p in probabilities
    ):
        raise ValueError("Need N>=1 probabilities in [0,1]")
    survival = 1.0
    pmf = []
    for probability in probabilities[:-1]:
        pmf.append(survival * probability)
        survival *= 1 - probability
    pmf.append(survival)  # emitted STOP or forced stop: both count as T=N
    expectation = math.fsum((t + 1) * mass for t, mass in enumerate(pmf))
    return pmf, expectation


def minimax(decisions, adversaries, reward):
    if not decisions or not adversaries:
        raise ValueError("Need at least one decision and one adversary")
    distributions = [stopping_distribution(a["p"])[0] for a in adversaries]
    if len({len(p) for p in distributions}) != 1:
        raise ValueError("All adversaries must use the same N")
    best = None
    best_value = float("-inf")
    for action in decisions:
        value = min(
            math.fsum(
                mass * reward(action, t + 1, adversary) for t, mass in enumerate(pmf)
            )
            for adversary, pmf in zip(adversaries, distributions)
        )
        if value > best_value:  # ties choose the first listed action
            best, best_value = action, value
    return best, best_value


def solve(data):
    N = data["N"]
    p = data["p"]
    actions = data["decisions"]
    adversaries = data["adversaries"]
    if N != len(p) or any(len(a["p"]) != N for a in adversaries):
        raise ValueError("N and probability lengths differ")
    if any(
        len(a["rewards"]) != len(actions) or any(len(row) != N for row in a["rewards"])
        for a in adversaries
    ):
        raise ValueError("Reward tensor must have shape (M,A,N)")
    # Distinct JSON scalar action labels keep row lookup unambiguous.
    index = {action: i for i, action in enumerate(actions)}
    if len(index) != len(actions):
        raise ValueError("Action labels must be unique")
    chosen, value = minimax(
        actions, adversaries, lambda a, t, adv: adv["rewards"][index[a]][t - 1]
    )
    pmf, expected = stopping_distribution(p)
    return dict(
        pmf=pmf, expected_T=expected, decision=chosen, worst_expected_reward=value
    )


if __name__ == "__main__":
    print(json.dumps(solve(json.load(sys.stdin))))
```

With A actions, M adversaries and N positions, time is $O(AMN)$ and cached PMFs occupy $O(MN)$ memory, apart from the input reward tensor. For an interview-scale concrete contract, set $N\le1000$, $M\le20$, $A\le100$ and benchmark larger products; this is a chosen interface, not a constraint supplied by the question. Production JSON should also reject nonfinite rewards and enforce input-size limits.

### Five independent edge checks

1. `p=[0]`: PMF `[1]`, expectation one, despite no emitted STOP.
2. `p=[1,0,0]`: PMF `[1,0,0]`, expectation one.
3. `p=[0,0,0]`: PMF `[0,0,1]`, expectation three.
4. `p=[0.5,0.25,0.9]`: PMF `[0.5,0.125,0.375]`, expectation 1.875; changing the last probability changes nothing.
5. The two-adversary input above chooses B with value one; if both actions have identical rewards, the first action wins the tie.

Also reject probabilities outside `[0,1]` and inconsistent table lengths. Very long low-hazard horizons can underflow survival; a log-survival representation is useful if accurate tiny tail masses matter.
