## Worked solution

### Solution outline

1. Let survival s_1=1. For t<N set P(T=t)=s_t*p_t and s_(t+1)=s_t*(1-p_t). Assign P(T=N)=s_N, absorbing both an actual stop and forced termination at N; this final mass does not need an extra p_N factor.
2. Compute E[T]=sum_t t*P(T=t), or equivalently sum_t s_t. Use stable accumulation and verify total probability is one, including p=0/1 boundaries.
3. For each fully specified decision a and adversary m, compute expected payoff sum_t P_m(T=t)*reward(a,t,m). Choose the decision maximizing the minimum of those expectations; define deterministic tie-breaking.
4. Time is $O(M\,A\,N)$ for explicit finite action/adversary lists, plus distribution construction. The prompt does not define a unique decision/reward interface, so state a concrete schema rather than claiming one universal numerical minimax answer.

### Understand why the approach works

#### Name the random experiment and condition on the right event

Write the sample space and independence assumptions before counting. Bayes' rule reverses conditioning:

$$
P(A\mid B)=\frac{P(B\mid A)P(A)}{P(B)},\qquad P(B)>0.
$$

A $90\%$ detection rate is not a $90\%$ probability that an alert is genuine. Prevalence and false-positive rate determine the latter. Work expected counts in a hypothetical population when the formula feels abstract.

For waiting-time and random-walk exercises, first-step analysis often gives a solvable recurrence:

$$
h(s)=1+\sum_{s'}P(s'\mid s)h(s'),\qquad h(s)=0\text{ at absorbing states}.
$$

Specify what counts as one step: two particles moving once each may cost two coin flips but only one elapsed second. At a forced horizon, all surviving probability mass must be assigned to the final stopping time.

For expected counts, indicator variables and linearity do not require independent indicators. For uncertainty or variance, dependence does matter. Check normalization, limiting cases and a small enumeration. Simulation is useful validation but not a replacement for a requested exact derivation; conversely, a neat-looking fraction should not be asserted merely because a numerical estimate is close to it.

#### Put the result in mathematical notation

Let $s_1=1$ and $s_{t+1}=s_t(1-p_t)$. Then
$$P(T=t)=s_tp_t\quad(t<N),\qquad P(T=N)=s_N,\qquad
\mathbb E[T]=\sum_{t=1}^N s_t.$$
The final mass includes every surviving path. For finite actions and adversaries,
$$a^*=\arg\max_a\min_m\sum_t P_m(T=t)R(a,t,m).$$
Averaging adversaries solves a different problem from the requested worst-case criterion.

### Readable reference implementation

Read the explanation first, then trace one small input through these functions. This is the same implementation used by the local checks; its stated simplifications still apply.

```python
from collections import defaultdict
from functools import lru_cache
import math
import re
import numpy as np


def stopping_distribution(p):
    """p includes the final step, where remaining mass is forced to stop."""
    if not p or any(not 0<=x<=1 for x in p):raise ValueError('invalid probabilities')
    masses=[];survival=1.0
    for probability in p[:-1]:
        masses.append(survival*probability)
        survival*=1-probability
    masses.append(survival)
    return masses,sum((i+1)*mass for i,mass in enumerate(masses))


def minimax_decision(decisions, adversary_probabilities, reward):
    """Finite action/adversary model. Ties keep the first supplied action."""
    if not decisions or not adversary_probabilities:raise ValueError('empty choices')
    distributions=[stopping_distribution(p)[0] for p in adversary_probabilities]
    scored=[]
    for decision in decisions:
        expected=[sum(mass*reward(decision,t+1,adversary) for t,mass in enumerate(dist))
                  for adversary,dist in enumerate(distributions)]
        scored.append(min(expected))
    best=max(range(len(decisions)),key=lambda i:scored[i])
    return decisions[best],scored[best]
```

### Edge cases and common mistakes

Losing survival mass at the forced-stop boundary or averaging adversaries when the requested criterion is worst-case.
