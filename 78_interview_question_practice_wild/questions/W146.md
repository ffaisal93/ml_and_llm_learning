## Question

Apple ML Engineer phone screen (Round 2), shared editor. You are given a stream of labeled (text, label) records and must build an end-to-end online pipeline that:
1. Processes tokens online — one record at a time, no pre-reading the whole corpus.
2. Generates embeddings for each token/document.
3. Trains a classifier on the stream and predicts for new records.

Keep it simple: hashed token ids, an embedding table you update online, mean-pool for the document vector, a linear softmax head, and SGD. It is not asking you to pretrain word2vec or a Transformer.

Before coding, clarify: single-pass online vs. replayable stream; binary vs. fixed multi-class C; vocabulary growth (feature hashing vs. lazy growth); embedding dim (32–64); optimizer; and metrics (progressive validation).

## Worked solution

### Choose a genuine single-pass contract

Assume a one-pass iterator with fixed C classes, hash buckets=4096, dimension=32 and SGD; no pre-scan, vocabulary training or implicit replay. Tokens are lowercased whitespace words with deterministic BLAKE2 ids, collisions allowed; reserve bucket 0 for an empty document. An embedding table supplies a vector per token occurrence; mean pooling supplies the document vector, then a linear softmax classifier supplies probabilities. Both table and head update online using PyTorch autograd, which is appropriate here because no manual-backward restriction was stated.

```python
import hashlib
import torch
from torch import nn
import torch.nn.functional as F


class OnlineTextClassifier(nn.Module):
    def __init__(self, buckets=4096, dim=32, classes=2):
        super().__init__()
        if buckets < 2 or dim < 1 or classes < 2:
            raise ValueError("invalid model dimensions")
        self.buckets = buckets
        self.classes = classes
        self.embedding = nn.Embedding(buckets, dim)
        nn.init.normal_(self.embedding.weight, std=0.05)
        self.head = nn.Linear(dim, classes)

    def token_ids(self, text):
        # Stable across processes: Python hash() is deliberately randomized.
        tokens = text.lower().split()
        return [
            1
            + int.from_bytes(hashlib.blake2b(t.encode(), digest_size=8).digest(), "big")
            % (self.buckets - 1)
            for t in tokens
        ] or [0]

    def forward(self, text):
        ids = torch.tensor(
            self.token_ids(text), dtype=torch.long, device=self.embedding.weight.device
        )
        token_vectors = self.embedding(ids)
        document_vector = token_vectors.mean(dim=0)
        return self.head(document_vector), token_vectors, document_vector

    @torch.no_grad()
    def predict(self, text):
        return self(text)[0].softmax(dim=-1)


def learn_stream(model, records, lr=0.1):
    optimizer = torch.optim.SGD(model.parameters(), lr=lr)
    correct = total = 0
    loss_sum = 0.0
    for text, label in records:  # No list(records), vocabulary scan or second pass.
        if not 0 <= label < model.classes:
            raise ValueError("label out of range")
        model.train()
        logits, _, _ = model(text)
        # Progressive validation predicts BEFORE updating on this record.
        correct += int(logits.argmax().item() == label)
        total += 1
        loss = F.cross_entropy(
            logits[None, :], torch.tensor([label], device=logits.device)
        )
        loss_sum += loss.item()
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
    return {
        "records": total,
        "progressive_accuracy": correct / total if total else None,
        "progressive_logloss": loss_sum / total if total else None,
    }


if __name__ == "__main__":
    torch.manual_seed(7)
    torch.set_num_threads(1)
    model = OnlineTextClassifier(buckets=128)
    before = model.embedding.weight.detach().clone()

    # Chosen synthetic stream. Each event is consumed once; repeating text is
    # a property of the generator, not a hidden replay of an exhausted iterator.
    def events():
        for _ in range(200):
            yield "sunny warm", 1
            yield "rainy cold", 0

    report = learn_stream(model, events(), lr=0.3)
    assert report["records"] == 400 and report["progressive_accuracy"] > 0.9
    assert model.predict("sunny warm").argmax().item() == 1
    assert model.predict("rainy cold").argmax().item() == 0
    assert not torch.equal(before, model.embedding.weight)
    assert model.predict("").shape == (2,) and torch.isfinite(model.predict("")).all()
    assert model.token_ids("warm warm")[0] == model.token_ids("warm warm")[1]
    print(
        "W146:", report, "; positive probability", model.predict("sunny warm").tolist()
    )
```

### Validate before learning each record

For one record with token ids $i_1..i_m$, $h=\frac1m\sum_j E_{i_j}$ and logits $Wh+b$. Cross-entropy sends $W^T(p-onehot(y))/m$ to each token occurrence; repeated/hash-colliding ids accumulate automatically in the embedding gradient. Head weights receive $(p-onehot(y))h^T$. Predict-then-update progressive metrics prevent scoring an example after memorizing its label. An empty stream returns undefined metrics explicitly; empty text uses a learnable reserved representation.

The chosen synthetic stream contains 400 one-use events alternating positive “sunny warm” and negative “rainy cold.” Checks show table weights actually change, progressive accuracy exceeds .9, both new-text predictions are correct and empty-text probabilities are finite. This is a behavior demonstration, not a claim about real language accuracy. Memory is O(buckets·dim+classes·dim), independent of corpus length, and per-record work is O(tokens·dim+classes·dim). Hash collisions lose information, token order is ignored, and class drift needs rolling metrics/possible forgetting; checkpoint model, optimizer and stream offset atomically enough to define replay semantics after restart. For delayed labels, store a bounded prediction log keyed by record id and avoid counting duplicate events twice.
