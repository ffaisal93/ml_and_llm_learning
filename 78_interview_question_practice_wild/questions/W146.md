## Question

<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">Apple ML Engineer phone screen (Round 2), shared editor. You are given a stream of labeled (text, label) records and must build an end-to-end online pipeline that:

1.
Processes tokens online — one record at a time, no pre-reading the whole corpus.
2.
Generates embeddings for each token/document.
3.
Trains a classifier on the stream and predicts for new records.

Keep it simple: hashed token ids, an embedding table you update online, mean-pool for the document vector, a linear softmax head, and SGD. It is not asking you to pretrain word2vec or a Transformer.

Before coding, clarify: single-pass online vs. replayable stream; binary vs. fixed multi-class C; vocabulary growth (feature hashing vs. lazy growth); embedding dim (32–64); optimizer; and metrics (progressive validation).</pre>

## Worked solution

1. Define versioned endpoints and schemas for token processing, embeddings and classification; specify input normalization, maximum sizes, supported batch shapes and error types.
2. Keep model/preprocessing versions in responses and cache keys. Batch compatible work under latency budgets, preserve request/output mapping and handle partial errors explicitly.
3. For streaming input, retain only the state the model needs and distinguish append-only token updates from corrections. Return normalized probabilities or scores under a documented label order.
4. Enforce tenant quotas, privacy and bounded queues; measure quality, p99 latency, token throughput and failure rates under representative lengths.

### Small example / sanity check

A stored embedding produced by version A must not silently be compared with a query embedding from incompatible version B. A failed item cannot shift every later batch result by one index.

### Common trap

A supposedly generic API that hides model-version, dimension and normalization differences.
