## Question

<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">Mechanistic-interpretability team take-home (~4 hours). Design and run an experiment that reproduces sample-wise double descent on a small model, explain why it occurs using theory, and propose a fix. Deliverable is a slide deck or notebook plus a live discussion.

Build the experiment yourself: pick the model class, the data-scaling axis, and the metric.
Show the double-descent curve clearly. (A reported successful approach: linear regression with varying training-set size + Random Matrix Theory analysis.)
Explain the phenomenon: why does test error spike near the interpolation threshold and then decrease again?
Propose a remediation (ridge regularization is the textbook fix).</pre>

## Worked solution

1. Explain double descent without claiming it is universal. Prediction error can rise near an interpolation threshold and fall again as model size or sample size moves beyond it under particular conditions.
2. Create a controlled regression experiment with known data generation, train/test separation and a fixed fitting rule.
3. Sweep model dimension relative to sample count, recording train loss, test loss and the conditioning of the design matrix.
4. Repeat seeds and compare regularization strengths. Discuss noise, minimum-norm solutions and how the result depends on the experimental setup.
5. Prepare a research experiment with limited compute. Spend the budget on experiments that most clearly distinguish hypotheses.
6. State the hypothesis, expected observable effect and a simple falsifying result.
7. Choose a small faithful setting, strong baseline and controlled ablation before scaling.
8. Track compute, seeds and failures, and reserve budget for confirmation rather than spending everything on a broad unreplicated search.

### Small example / sanity check

For unregularized random-feature least squares, error may peak when the number of fitted parameters approaches the number of samples.

### Common trap

Using one noisy curve as proof that “more parameters always helps,” or changing data noise while changing model size.
