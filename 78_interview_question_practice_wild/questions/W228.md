## Question

<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">Data Engineer first-round screen combining a noisy CSV cleaning pipeline with three SQL tasks: monthly-reset cumulative sales, recursive employee hierarchy, and conditional order aggregation.

Requirements
Cleaning pipeline input: customer transaction CSV with columns date, amount, customer_id, payment_method, and notes.
Data issues:
Dates appear in mixed formats: YYYY-MM-DD, MM/DD/YYYY, and strings such as Jan 5, 2024.
Amounts include currency symbols and commas, such as USD 1,234.56.
customer_id can lose leading zeros after Excel processing.
payment_method contains typos and inconsistent casing.
After cleaning, describe what validations should run.
SQL task 1: sales table with date, store_id, amount; compute cumulative sales by store, resetting to 0 whenever a new month starts. Output store_id, date, total_amount.
SQL task 2: organization table with employee_id, manager_id, name; find all direct and indirect reports under manager_id = 1, returning employee_id, manager_id, name, level, and hierarchy_path.
SQL task 3: orders table with order_id, status, amount, date; in one pass, compute completed-only revenue, pending count, and cancelled count by date.</pre>

## Worked solution

1. Fit a baseline on messy tabular data without leakage. Build a trustworthy split and simple baseline before sophisticated feature engineering.
2. Define the target, prediction time and unit of independence, then split by time or group if required.
3. Fit imputation, scaling and category encodings on training folds only. Start with a dummy baseline and a regularized linear or small tree model.
4. Evaluate slices, missingness patterns and calibration; document features unavailable at decision time and remove them.
5. Define label windows for click-through-rate analysis. The numerator and denominator must refer to the same eligible exposures and mature observation windows.
6. Define an impression, a valid click, attribution rules, deduplication and the outcome window.
7. Join outcomes to exposures without multiplying rows, then aggregate clicks and impressions by the intended category.
8. Report counts and uncertainty; distinguish unobserved outcomes from confirmed non-clicks when logs are incomplete.
9. Find each user's consecutive login-day streaks. Convert repeated events into distinct user-days before detecting consecutive dates.
10. Choose timezone and deduplicate (user_id,login_date).
11. Order each user's dates and assign ROW_NUMBER; consecutive runs share a key like login_date minus row_number days.
12. Group by user and run key, then compute length and boundaries with deterministic handling of ties.

### Small example / sanity check

A “refund issued” field may predict churn extremely well but be recorded after the churn decision, making it unusable for a prospective model.

### Common trap

Fitting preprocessing on all rows before cross-validation, even when labels were not directly used.
