## Question

Data Engineer first-round screen combining a noisy CSV cleaning pipeline with three SQL tasks: monthly-reset cumulative sales, recursive employee hierarchy, and conditional order aggregation.

### Requirements

Cleaning pipeline input: customer transaction CSV with columns date, amount, customer_id, payment_method, and notes.
Data issues:
Dates appear in mixed formats: YYYY-MM-DD, MM/DD/YYYY, and strings such as Jan 5, 2024.
Amounts include currency symbols and commas, such as USD 1,234.56.
customer_id can lose leading zeros after Excel processing.
payment_method contains typos and inconsistent casing.
After cleaning, describe what validations should run.
SQL task 1: sales table with date, store_id, amount; compute cumulative sales by store, resetting to 0 whenever a new month starts. Output store_id, date, total_amount.
SQL task 2: organization table with employee_id, manager_id, name; find all direct and indirect reports under manager_id = 1, returning employee_id, manager_id, name, level, and hierarchy_path.
SQL task 3: orders table with order_id, status, amount, date; in one pass, compute completed-only revenue, pending count, and cancelled count by date.

## Worked solution

### Clean without destroying identifiers or inventing repairs

Read CSV fields as strings, not inferred numbers. Parse the three declared date formats explicitly; do not guess whether an undeclared `05/01/24` means May 1. Parse USD amounts with a strict grouping grammar and Decimal, preserving exact cents. Normalize payment methods through an approved alias map and quarantine unknown methods for review. Preserve notes as free text with appropriate access controls, not as a place to silently extract customer identity.

Leading zeros already lost by Excel cannot be recovered from `123` alone: it could mean `00123` or `000123`. Only pad when a documented fixed width or authoritative customer lookup provides the missing information. The function's `id_width=None` preserves the available string; a declared width enables explicit zero-padding. Rejects retain row number, raw record and reason.

```python
import csv
import re
from datetime import datetime
from decimal import Decimal, InvalidOperation

PAYMENT_ALIASES = {'card':'card', 'credit card':'card', 'credit_card':'card',
                   'credit crad':'card', 'cash':'cash', 'paypal':'paypal', 'pay pal':'paypal'}

def clean_transactions(path, id_width=None):
    clean, rejects = [], []
    with open(path, newline='', encoding='utf-8') as f:
        for line, row in enumerate(csv.DictReader(f), 2):
            try:
                date = None
                for fmt in ('%Y-%m-%d', '%m/%d/%Y', '%b %d, %Y'):
                    try: date = datetime.strptime(row['date'].strip(), fmt).date(); break
                    except ValueError: pass
                if date is None: raise ValueError('unsupported date')
                # Explicit USD-only grammar avoids silently accepting mixed currencies.
                raw = re.sub(r'^(?:USD\s*|\$\s*)', '', row['amount'].strip(), flags=re.I)
                if not re.fullmatch(r'[+-]?(?:\d{1,3}(?:,\d{3})+|\d+)(?:\.\d{1,2})?', raw):
                    raise ValueError('invalid USD amount')
                amount = Decimal(raw.replace(',', ''))
                if not amount.is_finite(): raise ValueError('nonfinite amount')
                customer = row['customer_id'].strip()
                if not customer: raise ValueError('missing customer_id')
                if id_width is not None:
                    if not customer.isdigit() or len(customer) > id_width:
                        raise ValueError('customer ID violates declared fixed width')
                    customer = customer.zfill(id_width)
                payment = PAYMENT_ALIASES.get(row['payment_method'].strip().lower())
                if payment is None: raise ValueError('unknown payment method')
                clean.append(dict(date=date.isoformat(), amount=str(amount.quantize(Decimal('.01'))),
                                  customer_id=customer, payment_method=payment, notes=row.get('notes','')))
            except (ValueError, KeyError, InvalidOperation) as exc:
                rejects.append(dict(line=line,raw=row,reason=str(exc)))
    return clean, rejects
```

After cleaning, validate field types, allowed currencies/methods, amount scale, plausible dates, customer referential integrity, null rates, duplicates (with a real transaction key), input=accepted+rejected counts and aggregate monetary reconciliation. Negative amounts may be valid refunds; the business policy must decide. The fixture uses `USD 1,234.56`, `Jan 5, 2024`, `00123` and `Credit Crad`, yielding `1234.56`, `2024-01-05`, the unchanged ID and `card`; an unknown currency is rejected.

### Three PostgreSQL answers

Monthly cumulative sales first aggregates same-day rows; otherwise `ROWS` with tied dates has nondeterministic intermediate totals. The hierarchy returns direct reports at level 1, excludes the root and uses a visited path to prevent cycles. Conditional aggregation scans orders once; unrecognized statuses contribute zero, while a data-quality check should flag them.

```sql
-- W228, PostgreSQL. Group daily first so duplicate dates have deterministic totals.
WITH daily AS (
  SELECT store_id, CAST(date AS date) AS day, SUM(amount) AS amount
  FROM sales GROUP BY store_id, CAST(date AS date)
)
SELECT store_id, day AS date,
       SUM(amount) OVER (PARTITION BY store_id,date_trunc('month',day)
                         ORDER BY day ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS total_amount
FROM daily ORDER BY store_id,day;

-- W228 hierarchy: manager_id=1 is the root ID, not an employee row filter at every depth.
WITH RECURSIVE reports AS (
  SELECT employee_id,manager_id,name,1 AS level,ARRAY[1,employee_id] AS hierarchy_path
  FROM organization WHERE manager_id=1 AND employee_id<>1
  UNION ALL
  SELECT e.employee_id,e.manager_id,e.name,r.level+1,r.hierarchy_path||e.employee_id
  FROM organization e JOIN reports r ON e.manager_id=r.employee_id
  WHERE NOT e.employee_id=ANY(r.hierarchy_path)
)
SELECT employee_id,manager_id,name,level,hierarchy_path FROM reports ORDER BY hierarchy_path;

-- W228 one scan, explicit NULL-to-zero monetary behavior.
SELECT CAST(date AS date) AS date,
       SUM(CASE WHEN status='completed' THEN COALESCE(amount,0) ELSE 0 END) AS completed_revenue,
       SUM(CASE WHEN status='pending' THEN 1 ELSE 0 END) AS pending_count,
       SUM(CASE WHEN status='cancelled' THEN 1 ELSE 0 END) AS cancelled_count
FROM orders GROUP BY CAST(date AS date) ORDER BY date;


```

An index on `(manager_id,employee_id)` helps recursive expansion; `(store_id,date)` helps sales ordering, though the planner may still sort. On Jan 1 sales 10 and 5, Jan 2 sales 7 and Feb 1 sales 2, the daily totals are 15,22,2. Tests execute portable window/conditional equivalents and a cycle-safe recursive fixture in SQLite; PostgreSQL-specific array/date syntax is reviewed but not claimed to have run against a PostgreSQL server.
