A small GPT-style transformer in PyTorch is meant to learn next-character prediction on a handful of short strings, with causal self-attention and key/value-cache decoding. Four bugs were injected, and each one is marked in the code with a BUG label. Find them, explain the damage each one does, and fix them. Then adapt the model to a different task.

What to deliver
1.
For each of BUG 1 to BUG 4: say what is wrong, the failure mode it causes, and a corrected version of the marked code.
2.

3.
Follow-up: change the model from next-token prediction into a classifier that tells whether a decimal number is odd or even. Describe the architecture change, the loss, and how the training labels are built.
Where the bugs are
BUG 1 and BUG 2 are in the self-attention module.
BUG 3 is in the handling of positional embeddings.
BUG 4 is in the loss.
Observed symptoms

These are what you see when you run the code below on CPU with PyTorch 2.x.

Example 1, training: the loss falls from about 5.8 to below 0.001 within 100 steps, far faster than a correct model on this data. The samples printed afterwards contain only the prompt digits followed by _ padding, not the training sentences.
Example 2, cache decoding: take a batch x, run gpt(x[:, :-1], mode=&quot;prefill&quot;), then gpt(x[:, -1:], mode=&quot;decode&quot;). The logits of that single decode step should equal the last position of gpt(x, mode=None). They differ by several units (about 4 in one run).
Example 3, causality: change only the last few tokens of an input. The logits at the earlier positions must not change. They do change, by more than 1 in one run.
Follow-up: odd or even
Input: each example is a decimal number written as exactly 8 characters, left-padded with 0, so &quot;00001234&quot;. Tokens are the character codes ord(c), as in the code below.
Output: one class per example, 0 for an even number and 1 for an odd number.
Describe which parts of the model and of loss change, and how the label tensor is created.
Constraints
Hidden size 64, 4 heads, 4 layers, at most 64 positions, vocabulary 256.
The fixes must keep the public interface: GPT.forward(x, mode) with mode in &quot;prefill&quot;, &quot;decode&quot; or None, and GPT.loss(tokens, train_label, mode).

from torch.nn import functional as F
import torch
import math

class CausalSelfAttention(nn.Module):
def __init__(self, hiddens, n_heads):
super().__init__()
self.key = nn.Linear(hiddens, hiddens)
self.query = nn.Linear(hiddens, hiddens)
self.value = nn.Linear(hiddens, hiddens)
self.out = nn.Linear(hiddens, hiddens)
self.n_heads = n_heads

self.k_cache = None
self.v_cache = None

def forward(self, x, mode=&quot;prefill&quot;):
b, t, c = x.size()

# b, h, t, hd
q = self.query(x).view(b, t, self.n_heads, c // self.n_heads).transpose(1,2)
k = self.key(x).view(b, t, self.n_heads, c // self.n_heads).transpose(1,2)
v = self.value(x).view(b, t, self.n_heads, c // self.n_heads).transpose(1,2)

if mode == &quot;prefill&quot;:
self.k_cache = k
self.v_cache = v
elif mode == &quot;decode&quot;:
k = torch.concatenate((self.k_cache, k), dim=2)
self.k_cache = k
v = torch.concatenate((self.v_cache, v), dim=2)
self.v_cache = v

att = torch.matmul(q, k.transpose(-2, -1)) # b, h, qt, kt
att = att / math.sqrt(k.shape[-1])

# BUG 1

class Block(nn.Module):
def __init__(self, hiddens, n_heads):
super().__init__()
self.ln1 = nn.LayerNorm(hiddens)
self.ln2 = nn.LayerNorm(hiddens)
self.attn = CausalSelfAttention(hiddens, n_heads)
self.mlp = nn.Sequential(
nn.Linear(hiddens, 4 * hiddens),
nn.GELU(),

def forward(self, x, mode=&quot;prefill&quot;):

x = x + self.mlp(self.ln2(x))
return x

class GPT(nn.Module):
def __init__(self, n_tokens=64, hiddens=64, n_heads=4, n_classes=256, layers=4, vocab=256):
super().__init__()

self.layers = layers
self.tok_emb = nn.Embedding(vocab, hiddens)

self.pos_emb = nn.Parameter(torch.ones(1, n_tokens, hiddens))
nn.init.normal_(self.pos_emb)

self.blocks = nn.ModuleList(Block(hiddens, n_heads) for _ in range(layers))
self.ln_f = nn.LayerNorm(hiddens)
self.final = nn.Linear(hiddens, n_classes, bias=False)

self.size_of_kv_cache = 0

def forward(self, x, mode=&quot;prefill&quot;):
b, t = x.size()
token_embeddings = self.tok_emb(x)
# BUG 3
position_embeddings = self.pos_emb[:, :t, :]
x = token_embeddings + position_embeddings

for block in self.blocks:
x = block(x, mode=mode)

x = self.ln_f(x)
return self.final(x)

def loss(self, tokens, train_label, mode=&quot;prefill&quot;):
# BUG 4

# autoregressive LM
targets = tokens[:, :-1]
logits = self.forward(tokens[:,:-1], mode=mode)

return F.cross_entropy(logits.reshape(-1, logits.size(-1)), targets.flatten())

## Worked solution

1. Debug a miniature GPT that fails to learn. Localize the first broken invariant rather than changing many hyperparameters at once.
2. Check shifted labels, causal masking, tensor axes, vocabulary bounds and padding/loss masks on a tiny batch.
3. Check train/eval mode, gradient presence, optimizer steps and parameter changes. Overfit a tiny dataset with dropout disabled as a diagnostic.
4. Compare against a simple trusted baseline; then test generation and caching separately. Record one controlled change and its effect at a time.
5. Add a KV cache and prove equivalence to full-prefix attention. Previously computed keys and values do not need to be recomputed when a causal decoder receives one new token.
6. During prefill, compute and store all layerwise K and V tensors.
7. At each decode step, project only the new token, append its K,V, and attend its Q over the entire available cache. Use the correct position offset.
8. Compare each step's last-position logits against a fresh full-prefix forward pass in evaluation mode, using tolerances before comparing sampled tokens.

### Small example / sanity check

For a uniform predictor over 10 tokens, the initial cross-entropy is about log(10)=2.303 nats. A wildly different baseline deserves investigation.

### Common trap

Interpreting unusually low training loss as success before checking whether future tokens or targets leaked into inputs.
