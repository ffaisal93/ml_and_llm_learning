## Question

Embedded-Optimized Elevation Mapping (45 minutes, whiteboard)

You need to maintain a local elevation map under embedded resource constraints while a robot moves and receives elevation observations.

Task

Design an algorithm/data structure to update a local elevation grid in real time, addressing:

Real-time updates: each observation frame must be processed within a fixed budget (justify via complexity).
Memory constraints: maintain only a fixed-size local window around the robot (sliding/local map).
Noise & outliers: fuse repeated observations to reduce noise and handle outliers.
Frame transforms: observations are in sensor/robot frame; fuse into the map frame given pose.
Output: per-cell elevation estimate (optionally with confidence/variance).
Abstract input
pose_t: robot pose at time t.
obs_t: a set of elevation observations (e.g., (x,y,z) points or scan-derived heights).
Map params: resolution r, window size W x H.
What to explain
Map representation (array, ring buffer, hashed grid, etc.) and how the sliding window works.
Fusion method (weighted average, recursive filter, variance update, time decay).
Complexity and embedded optimizations (precomputation, incremental update, SIMD/fixed-point, etc.).
Edge cases (window shifts, bounds, initialization/reset).

Discussion/whiteboard oriented; clear pseudocode or a step-by-step algorithm is expected.

Input:  (discussion) pose_t and obs_t stream; map size fixed
Output: Per-cell elevation estimate (and optional confidence) updated in real time

## Worked solution

### A fixed local grid with world-cell identity

Choose a locally fixed map frame, cell resolution r meters and W × H cells centered near the robot. Store dense arrays `mean_z`, `variance`, `last_seen`, `valid` plus integer world-cell origin and circular-buffer x/y offsets. For map point(x, y), world cell is `(floor(x/r),floor(y/r))`; inside-window check occurs **before** modulo index mapping, so an outside point cannot wrap into a valid cell. A sensor point becomes $p_M=T_{M,B}(pose_t)T_{B,S}p_S$ using calibrated extrinsics and synchronized pose; include pose uncertainty in observation variance.

When the robot crosses an integer cell, shift the origin/ring offset and clear only newly exposed rows/columns, keeping retained cells in their original world coordinates. For a teleport ≥W orH cells, clear the whole map. Never reuse an exposed slot's old height/confidence. Use generation tags or valid masks to avoid bulk writes if beneficial, but bound any deferred clearing work. Recenter only on cell boundaries to avoid interpolation/reblurring every frame.

### Per-point update pseudocode

```text
process_frame(pose, observations):
    shift_window_to_robot_cell(pose.xy)  # clear exposed strips or full reset
    T = map_from_body(pose) * body_from_sensor
    for p, sensor_variance in bounded_observations:
        q = T * p
        if nonfinite(q) or invalid_pose: reject/count
        cell = floor(q.xy / r)
        if cell not inside current window: continue
        i = circular_index(cell)
        R = max(R_min, sensor_variance + projected_pose_variance(q))
        if not valid[i]: mean[i]=q.z; variance[i]=R; valid[i]=true
        else:
            P = variance[i] + process_noise * elapsed_time(i)
            residual = q.z - mean[i]
            if residual^2 > gate^2 * (P + R): reject_or_pending_surface_change
            else:
                K = P / (P + R)
                mean[i] += K * residual
                variance[i] = max(P_min, (1-K)*P)
        last_seen[i] = frame_time only when accepted
```

This scalar Kalman/inverse-variance fusion assumes independent noise and a single local surface; correlated points from one frame should be downsampled/weighted so 100 adjacent hits do not imply100 independent measurements. A gate rejects outliers but can also freeze an old surface when a real object/terrain change occurs: track repeated consistent rejected observations, age confidence or reset under an explicit change policy. A 2.0m estimate with P=.04 and 2.2m observation withR=.04 givesK=.5, mean 2.1m, variance.02 before process noise/floors. A 10m residual is gated, not averaged blindly.

### Resource bound and edge cases

For M bounded points and shifts(dx, dy), transform/assign/fuse is O(M), exposed clearing O(min(WH, H|dx|+W|dy|)), worst O(WH); memory O(WH), independent of travel distance. Choose M_max/downsampling and fixed WH from measured worst-case time, not average throughput. A 250×250 map with four32-bit fields is about 1 MB plus masks/alignment; SIMD transforms, precomputed extrinsics, tile/block clears, bounded queues and fixed-point only with range/error analysis suit embedded hardware. Outputting the entire grid itself costs O(WH); publish changed tiles if the interface permits.

Handle negative coordinates with floor (not truncation), boundary clipping, empty frames, initial invalid cells, stale confidence, timestamp/pose interpolation, large recenter, nonfinite points and map-frame reset after localization jumps. Test a stationary plane with noisy repeats, a known rotated sensor transform and robot movement across a cell: the same world obstacle must remain in the same world cell while ring slots rotate. A 2.5D map cannot represent overhangs/multiple heights in one cell; flag that limitation rather than claim full3D mapping.
