## Question

Embedded-Optimized Elevation Mapping (45 minutes, whiteboard)

You need to maintain a local elevation map under embedded resource constraints while a robot moves and receives elevation observations.

Task

Design an algorithm/data structure to update a local elevation grid in real time, addressing:

Real-time updates: each observation frame must be processed within a fixed budget (justify via complexity).
Memory constraints: maintain only a fixed-size local window around the robot (sliding/local map).
Noise & outliers: fuse repeated observations to reduce noise and handle outliers.
Frame transforms: observations are in sensor/robot frame; fuse into the map frame given pose.
Output: per-cell elevation estimate (optionally with confidence/variance).
Abstract input
pose_t: robot pose at time t.
obs_t: a set of elevation observations (e.g., (x,y,z) points or scan-derived heights).
Map params: resolution r, window size W x H.
What to explain
Map representation (array, ring buffer, hashed grid, etc.) and how the sliding window works.
Fusion method (weighted average, recursive filter, variance update, time decay).
Complexity and embedded optimizations (precomputation, incremental update, SIMD/fixed-point, etc.).
Edge cases (window shifts, bounds, initialization/reset).

Discussion/whiteboard oriented; clear pseudocode or a step-by-step algorithm is expected.

Input:  (discussion) pose_t and obs_t stream; map size fixed
Output: Per-cell elevation estimate (and optional confidence) updated in real time

## Worked solution

### Solution outline

1. State what the coordinate represents: an aircraft position, celestial direction or a local elevation cell are different data types. Specify units, reference frame, timestamp and uncertainty before applying a transform.
2. For earth-fixed positions use latitude/longitude/altitude→ECEF, then rotate offsets into a local east/north/up frame as needed. A celestial direction uses a time-dependent astronomical frame and projection, not an arbitrary latitude/longitude substitution.
3. For an elevation map, transform calibrated sensor points into a common local frame, assign bounded grid cells and aggregate height/uncertainty with an outlier/aging rule. Tile or use a rolling grid to meet embedded memory limits.
4. Validate known landmarks/transforms and stale/timing effects. The open-ended aircraft prompt lacks a fixed input/output contract, so declare a concrete interpretation instead of inventing a unique answer.

### Understand why the approach works

#### State the contract and prove the key invariant

Start with the precise output: any valid solution, the first solution under a tie rule, an exact optimum or a bounded heuristic are different tasks. Name the state/data structure and what stays true after each update.

For half-open intervals $[s,e)$, length is $e-s$. Sorting and merging overlapping/touching ranges gives a disjoint union; summing original lengths would double-count coverage. To find gaps in a query window, advance a cursor through the clipped union, emitting only positive-length holes.

For search/backtracking, write the constraint checked at each decision and what is restored on undo. Choosing the most constrained remaining variable can shrink typical search, but does not turn an exponential worst case into a polynomial algorithm. For clustering geometry, distinguish squared-distance means from absolute-distance medians.

Work a minimum-size case, a tie and an impossible/boundary case. Then state time in terms of input, output and any search-space size; outputting many intervals already costs their number. Never hide an $O(n)$ scan inside each “lookup” and report the whole algorithm as $O(n)$ without counting those repetitions.

### Work a small example

A north/east coordinate in meters cannot be subtracted directly from a longitude/latitude pair in degrees. A single camera bearing does not uniquely determine range without additional information.
