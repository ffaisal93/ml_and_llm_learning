## Question

<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">Using the same transactions and vendors tables, write a SQL query to: within the last 2 years, group by state and city, compute each vendor&#x27;s net amount (PURCHASE positive, REFUND negative), and return the Top 3 vendors within each (state, city) by net amount.

Suggested output columns: state, city, vendor_id, net_amount, rank_in_city.

Requirements
Use a window function to rank vendors within each (state, city) partition.
Ties are allowed; state whether you use DENSE_RANK or ROW_NUMBER.
Example

Current date assumed 2025-04-01. Output: CA/San Jose: vendor2(300) rank1; vendor1(150) rank2; TX/Austin: vendor3(500) rank1</pre>

## Worked solution

1. Find the top three vendors by net charge over the last two years. Aggregate at the intended vendor grain before ranking, with refunds and time boundaries defined.
2. Filter transactions using a reproducible as-of timestamp and a half-open date interval.
3. Normalize charge/refund signs or subtract refund amounts according to the schema, then group by vendor id.
4. Sort totals descending with an explicit tie rule; use ROW_NUMBER for exactly three rows or DENSE_RANK when tied ranks should be included.

### Apply the exact contract

First group net transactions by (state,city,vendor_id), then use DENSE_RANK() OVER (PARTITION BY state,city ORDER BY net_amount DESC) and filter rank<=3 if ties at three ranks are included. Use ROW_NUMBER with a vendor-id secondary key only if exactly three rows per city are required; adding vendor_id inside DENSE_RANK’s ordering would incorrectly break amount ties.

### Small example / sanity check

A vendor with charges 100 and refunds 30 has net charge 70, not gross charge 100.

### Common trap

Joining a one-to-many vendor table before aggregation and multiplying transaction totals.
