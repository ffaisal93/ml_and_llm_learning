## Question

Using the same transactions and vendors tables, write a SQL query to: within the last 2 years, group by state and city, compute each vendor's net amount (PURCHASE positive, REFUND negative), and return the Top 3 vendors within each (state, city) by net amount.

Suggested output columns: state, city, vendor_id, net_amount, rank_in_city.

### Requirements

Use a window function to rank vendors within each (state, city) partition.
Ties are allowed; state whether you use DENSE_RANK or ROW_NUMBER.
Example

Current date assumed 2025-04-01. Output: CA/San Jose: vendor2(300) rank1; vendor1(150) rank2; TX/Austin: vendor3(500) rank1

## Worked solution

### Net within each city before ranking

The phrase “same tables” supplies no standalone schema on this page. Use the explicit W342 contract: transactions has vendor_id, positive amount_charged, transaction_type and timestamp; vendors has unique vendor_id, state and city. Count each purchase/refund by its own event timestamp, including refunds of older purchases. Choose DENSE_RANK, which returns the top three distinct net totals and may return more than three vendors per city.

```sql
WITH totals AS (
 SELECT v.state,v.city,t.vendor_id,
 SUM(CASE WHEN t.transaction_type='PURCHASE' THEN t.amount_charged
          WHEN t.transaction_type='REFUND' THEN -t.amount_charged ELSE 0 END) AS net_amount
 FROM transactions t JOIN vendors v ON v.vendor_id=t.vendor_id
 WHERE t.timestamp>=CURRENT_DATE-INTERVAL '2 years' AND t.timestamp<CURRENT_DATE+INTERVAL '1 day'
 GROUP BY v.state,v.city,t.vendor_id
), ranked AS (
 SELECT *,DENSE_RANK() OVER(PARTITION BY state,city ORDER BY net_amount DESC) AS rank_in_city FROM totals
)
SELECT state,city,vendor_id,net_amount,rank_in_city FROM ranked WHERE rank_in_city<=3
ORDER BY state,city,rank_in_city,vendor_id;
```

The time range is from current date minus two calendar years through the end of today; an as-of-now requirement would use CURRENT_TIMESTAMP as the upper boundary. With vendor2=300/vendor1=150 in San Jose, ranks are1/2 independently of Austin vendor3=500 rank1. Join to a unique vendor dimension before grouping; if locations change, this attributes to current location because no historical location contract exists. Do not self-join refunds to purchases and double-count them. Use ROW_NUMBER ORDER BY net DESC,vendor_id instead if exactly three rows/city is desired. The batch tests run a fixed-as-of portable equivalent and ties/negative totals; no unknown shared dataset is claimed.
