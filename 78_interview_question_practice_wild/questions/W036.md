## Question

Write the backward pass of a two-layer MLP whose weight matrices are split by rows across several shards that communicate only through all_gather.

Setting

The forward pass, which is given, computes

```python
h_pre = A @ x
h     = relu(h_pre)
y     = B @ h
```

A (n_hid × n_in) and B (n_out × n_hid) are row-sharded: shard i holds a contiguous block of rows, blocks appear in shard order, and blocks may have different sizes (including zero rows). The input x is identical on every shard. Each shard receives a comm object with comm.num_shards, comm.my_shard_index and comm.all_gather(value). Every shard must call all_gather the same number of times, in the same order. Each call returns the list [value_0, ..., value_{num_shards-1}] of the values that the shards passed. Matrices are lists of row lists and vectors are lists of floats.

### Requirements

1. relu_grad(x, y_grad) -&gt; list[float]: return dL/dx for relu, given the pre-activation x and y_grad = dL/d relu(x). The gradient at x[i] &lt;= 0 is 0.0, matching relu.
2. sharded_matmul_grad(sharded_W, v, out_grad, comm) -&gt; (W_grad, v_grad): the backward pass of sharded_matmul. out_grad is dL/d(W @ v) for the whole output and is identical on every shard. Return two values. W_grad is the gradient for this shard's rows only, with the same shape as sharded_W. v_grad is the full dL/dv, of length len(v) and identical on every shard. Do not assume that rows divide evenly between shards.
3. sharded_mlp_grad(sharded_A, sharded_B, activations, y_grad, comm) -&gt; dict: given the activations dict returned by sharded_mlp and y_grad = dL/dy, return {"sharded_A": dL/dA for this shard's rows, "sharded_B": dL/dB for this shard's rows}.
4. Use only comm.all_gather for communication, and support any number of shards and any dimensions.
Input

Each shard calls the functions with its own sharded_A, sharded_B and comm, and the shared x, activations and y_grad.

### Output

Per shard, a dict whose two matrices equal (to floating-point tolerance) this shard's rows of dL/dA and dL/dB, the gradients of the loss with respect to the full, unsharded A and B.

### Constraints

1 &lt;= num_shards &lt;= 8; 1 &lt;= n_in, n_hid, n_out &lt;= 64.

## Worked solution

### Solution outline

The gradient communication follows which forward tensors were replicated or assembled, not the name of a collective alone.

1. Fix a convention: X:(N,d_in), W:(d_in,d_out), Y=XW. If output columns of W are split, each worker produces a slice of Y.
2. For replicated X, each worker computes its local dW=Xᵀ*dY_slice and partial dX=dY_slice*W_sliceᵀ.
3. Sum partial dX across workers. If forward concatenated slices with all-gather, backward distributes the corresponding gradient slices with the correct sum semantics for the surrounding graph.

### Understand why the approach works

#### Follow tensor ownership and the resource bottleneck

For every major tensor, state who owns it before and after each collective. Data parallelism divides examples; tensor parallelism divides operations/weights; pipeline parallelism divides layers. Their communication and memory effects differ, so a diagram saying “use more GPUs” is incomplete.

For $C=AB$, $A\in\mathbb R^{m\times k}$ and $B\in\mathbb R^{k\times n}$, a row partition gives

$$
C_r=A_rB,\qquad C=\operatorname{ConcatRows}(C_0,\ldots,C_{p-1}).
$$

Concatenating output shards is different from summing partial products. Backward communication depends on which variables were replicated and where multiple contributions to the same derivative must be added.

Estimate the bottleneck with a roofline bound:

$$
\text{attainable FLOP/s}\leq
\min\!\left(F_{\rm peak},\;\text{bandwidth}\times\frac{\text{FLOPs}}{\text{bytes moved}}\right).
$$

Then add synchronization, imbalance, launch and checkpoint overhead rather than treating the ideal bound as achieved speed.

For a platform/scheduler, distinguish desired state, observed state and durable job completion. Launching a container or receiving a provider response does not prove the computation succeeded. Checkpoint application state, fence stale owners, publish only complete artifacts and monitor both utilization and tenant wait time. A design that maximizes utilization by starving a large job violates a different important service objective.

### Work a small example

For W=[W0 W1], dX=dY0*W0ᵀ+dY1*W1ᵀ. Neither worker's contribution alone is the complete input gradient.

### Edge cases and common mistakes

Using “row-sharded” without stating weight orientation; different libraries use the term differently.
