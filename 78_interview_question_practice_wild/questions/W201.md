## Question

GenAI Quant SWE Manager Deep Dive

Manager round for a GenAI / quant-infra SWE role, focused on practical LLM fine-tuning tradeoffs, production agent frameworks, prior scope, scale, latency, quality, cost, and reliability decisions.

### Requirements

This round is a manager / technical deep dive rather than a coding prompt. Topics include:

Role scope and how past experience maps to GenAI / quant-infrastructure work.
When to choose full-precision SFT versus LoRA versus QLoRA.
How data size, model size, GPU memory, latency, quality target, and cost constraints affect that choice.
Agentic frameworks such as Pydantic-style structured output or ADK-style orchestration.
Production concerns: schema validation, tool calling, orchestration, state management, evaluation, observability, avoiding uncontrolled agent behavior, and avoiding silent failure.
Past project scope, concrete tech stack, why a particular solution was chosen, and how the solution would change at larger scale or tighter latency.
Notes
High-level "I used LLMs" answers are not enough. The round probes whether the candidate has made real tradeoffs under constraints.
Be concrete about hardware, model size, training budget, quality target, and serving latency.
Treat agent reliability as an engineering system: typed interfaces, validation, logs, evals, fallback behavior, and monitoring.

## Worked solution

### A defensible manager-round answer

No personal project history was supplied. The following is an **illustrative project**, with assumed budgets and targets rather than claimed accomplishments: a research assistant for quantitative analysts that answers questions over approved internal documents. I would describe my actual ownership separately: for example, retrieval and evaluation, while platform engineers owned deployment and analysts owned acceptance labels.

Suppose the starting point is a 7B model, 30,000 reviewed instruction examples, one 48-GB GPU for experiments, an eight-GPU-hour trial budget, and a target of 95% supported answers with first token under two seconds on 2,000-token prompts. These are planning constraints; benchmark results must establish whether they are attainable. Start with retrieval plus prompting, since tuning cannot keep changing market facts current. Split by document and time, redact secrets, and hold out adversarial tool-use tasks.

Full-parameter SFT updates every weight and offers the greatest adaptation freedom, but is expensive and can forget useful behavior. Even mixed-precision Adam training can require roughly 12–16 bytes per trainable parameter before activations: about 84–112 GB for 7B. Literal FP32 weights/gradients increase memory further. Multi-GPU sharding or a smaller model is needed. LoRA freezes the base model and trains low-rank updates, $\Delta W=BA$; for a $4096\times4096$ matrix and rank 16, the adapters have 131,072 parameters versus 16.8 million. Choose it when base weights fit and limited domain examples primarily teach format or behavior. QLoRA stores the frozen base in approximately four bits and computes with dequantized weights; 7B raw base storage is about 3.5 GB plus scales, adapters and activations. It makes a memory-constrained trial feasible but may cost throughput and quality. Compare all candidates on the same held-out set and decoding policy. Adapter merging can remove serving adapter overhead for supported LoRA deployments; it is not automatically equivalent to keeping a quantized base unchanged.

A typed output schema might be `Answer(text, citations, tool_requests)`. Pydantic-style validation checks structure; it cannot prove a citation supports a claim. An ADK-style orchestrator supplies routing, retries and durable state, but must still enforce a tool allowlist, read/write separation, maximum steps, time/token budgets, tenant authorization and explicit confirmation for side effects. Persist `run_id, state_version, step, tool_call_id, result`; idempotency keys prevent repeated writes after a retry. Treat retrieved documents as untrusted data, never instructions.

An illustrative failure is a valid JSON answer citing an irrelevant paragraph. The fix is an evidence-support evaluator and abstention, not merely another JSON retry. Trace retrieval, queue, prefill, decode and tool latency; log model/prompt versions, validation failures, dollars per successful task and fallback rates. At ten times traffic, benchmark batching and queueing, cache permission-scoped retrieval, and cap long generations before adding orchestration complexity. A tighter latency budget may favor a deterministic retrieve–answer pipeline and smaller model over a multi-step agent. Report real ablation and incident evidence in the interview; these assumed numbers are not results.
