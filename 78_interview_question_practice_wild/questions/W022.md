## Question

A set of five open-ended questions on how large language models are made smaller, faster and trainable at scale: quantization, FlashAttention, RNNs versus Transformers, and parallelism. Answer each question as you would in a technical interview, with mechanisms and trade-offs rather than definitions alone.

### Questions

1. Quantization approaches. What quantization approaches are commonly used for LLMs? Compare them on numerical precision, training requirements, deployment complexity and accuracy or speed trade-offs. Name at least two concrete post-training methods and say when quantization-aware training is worth its cost.
2. FlashAttention. What is FlashAttention? Which compute and memory bottlenecks of standard attention does it remove, and which algorithmic ideas (tiling, fused kernel, online softmax, recomputation) make that possible? State what it does to memory use and whether the result is exact.
3. RNNs versus Transformers. Compare the two architectures: how information flows across positions, training parallelism, cost in sequence length, handling of long-range dependencies, and the advantages and disadvantages of each.
4. Parallelism. How are Transformer models parallelized for training and for inference? Cover data, tensor, pipeline, sequence or context, and expert parallelism, the memory sharding used for optimizer state (ZeRO or FSDP), and the inference-time techniques that raise throughput.
5. Where to quantize. Which parts of an LLM system are quantized, and where should quantization be prioritized in training versus in inference? Discuss weights, activations and the KV cache, which components stay in higher precision, and the hyperparameters that matter.
Expectations
Each answer covers its stated points and ends with the main trade-off.
Use correct terminology; where numbers are quoted (bit widths, memory factors) they must be accurate.
Questions 1 and 5 both involve quantization: question 1 is about the methods, question 5 is about placement and priorities.

## Worked solution

### 1. Compare quantization methods, not only bit widths

Post-training quantization converts a pretrained model with no full gradient-based retraining, often using a representative calibration sample. Weight-only INT8/INT4 reduces bandwidth/storage, but dequantization and kernel support decide speed; W8A8 also quantizes activations and must handle activation outliers. GPTQ uses approximate second-order reconstruction to choose low-bit weight values; AWQ uses activation information to preserve salient weights through scaling. Both require calibration/versioned kernels and may regress unusual domains. SmoothQuant moves activation quantization difficulty into offline weight scaling for integer weight/activation execution. These are distinct methods, not interchangeable formats.

QAT inserts fake-quantization/quantization effects during training so weights adapt to deployment error, costing training data/compute and often straight-through gradient approximations. Use it when low-bit PTQ fails quality targets at an important deployment footprint and compatible runtime kernels exist. BF16/FP16 are ordinary reduced floating precision, while FP8 training/inference needs format/scaling support; “4-bit model” does not imply every tensor is4-bit. Trade-off: PTQ is cheaper to prepare; QAT can recover quality but needs training and operational complexity.

### 2. FlashAttention changes memory scheduling

Naive attention writes $S=QK^T/\sqrt d$ and P=softmax(S) to HBM, each T×T/head, then reads P to multiply V. Tiling keeps small Q/K/V blocks and running row maxima/normalizers/output accumulators in SRAM/registers, fuses operations and avoids full score/probability HBM storage. When a new block increases max m to m', rescale old sum/output by exp(m-m') before adding new exponentials; this is online softmax, not independent block softmax. Backward can recompute blocks rather than store P. Dense-attention arithmetic remains O(T²d); activation score storage falls from quadratic to linear-size stored state plus tiles. It is mathematically exact attention up to floating-point order differences. Trade-off: faster/lower memory on supported hardware, with specialized kernels and shape-dependent performance.

### 3. RNN/LSTM versus Transformer

An LSTM uses recurrent hidden/cell state, costing O(T(dh+h²)) and sequential dependence across positions; it has bounded streaming state but long-range signals pass through many updates. A Transformer projects in O(TD²) and mixes all positions in O(T²D), allowing parallel teacher-forced training and short information paths but needing positional information and growing context/KV memory. Autoregressive generation remains token-sequential for both. RNNs can suit compact streaming/low-state tasks; Transformers exploit parallel hardware/data and direct context access. Trade-off: bounded recurrence/state versus parallel training and expensive long-context attention.

### 4. Parallelism and sharding

Data parallel replicas process different batches and synchronize gradients. Tensor parallel splits matrix operations with intra-layer collectives, best on fast links. Pipeline parallel splits layers with activation/gradient transfers and microbatch bubbles. Sequence parallel partitions token activations for suitable operations; context parallel partitions attention context and exchanges K/V or partial softmax state. Expert parallel routes MoE tokens to expert-owning devices with all-to-all and load-balance costs. ZeRO1 shards optimizer state, ZeRO2 also gradients, ZeRO3/FSDP also parameters with all-gather/reduce-scatter around layer computation. Sharding saves persistent memory at communication/transient-gather cost.

Inference uses request replicas, tensor/pipeline/expert splitting for large models, KV caching, continuous batching, chunked prefill and prefix-cache reuse. It usually has no optimizer state to shard. Trade-off: enough partitioning to fit memory versus synchronization, latency, pipeline bubbles and failure complexity.

### 5. Place precision where the bottleneck is

Training often uses BF16/FP16 matrix operations with higher-precision reductions, master/optimizer states and loss/normalization calculations; FP16 commonly needs loss scaling. Activation checkpointing/sharding can matter more than weight-only compression for training memory. In inference prioritize weight bytes when low-batch decode is bandwidth-bound, activation precision when prefill kernels benefit, and KV cache when long context/concurrency dominates. Keep sensitive norms, softmax/log-sum-exp, accumulations and outlier channels in appropriate precision if tests require it.

Tune bit width, symmetric/asymmetric representation, per-tensor/channel/group scales, group size, calibration mixture/length, clipping/outlier thresholds and cache quantization block policy. For a fixed weight count,4-bit raw weights are one quarter of16-bit bytes before scales/packing; this is not a4× whole-service speed claim. Evaluate target/rare/long-context tasks, calibration, hardware throughput and p99 under realistic shapes, with rollback to a known precision. Trade-off: compression improves fit/bandwidth only if numerical error and kernel overhead remain acceptable.
