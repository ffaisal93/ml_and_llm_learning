## Question

A set of five open-ended questions on how large language models are made smaller, faster and trainable at scale: quantization, FlashAttention, RNNs versus Transformers, and parallelism. Answer each question as you would in a technical interview, with mechanisms and trade-offs rather than definitions alone.

### Questions

2. FlashAttention. What is FlashAttention? Which compute and memory bottlenecks of standard attention does it remove, and which algorithmic ideas (tiling, fused kernel, online softmax, recomputation) make that possible? State what it does to memory use and whether the result is exact.
3. RNNs versus Transformers. Compare the two architectures: how information flows across positions, training parallelism, cost in sequence length, handling of long-range dependencies, and the advantages and disadvantages of each.

5. Where to quantize. Which parts of an LLM system are quantized, and where should quantization be prioritized in training versus in inference? Discuss weights, activations and the KV cache, which components stay in higher precision, and the hyperparameters that matter.

## Worked solution

### Solution outline

#### Choose a quantization approach and validate its cost.

Quantization stores or computes numbers with fewer bits, trading representational precision for memory and possibly speed.

1. Specify which tensors are quantized: weights, activations or KV cache, and at what granularity and scale representation.
2. Estimate actual bytes including scales and metadata. Benchmark kernels on the target hardware; smaller storage does not automatically mean faster execution.
3. Evaluate representative tasks, long contexts and sensitive slices against a baseline. Keep a rollback path if quality regresses.

#### What makes attention quadratic, and what does FlashAttention change?

Dense attention compares every query with every key. FlashAttention computes the same attention operation with a different memory-access schedule.

1. At sequence length T, the logical score matrix has T² entries per head; forming $QK^\top$ and multiplying by V cost $O(T^2d_h)$.
2. A naive implementation materializes scores and probabilities in high-bandwidth memory, creating heavy memory traffic.
3. Tiled exact attention maintains rowwise normalization statistics and avoids storing the full matrix in that memory. Arithmetic remains quadratic for full attention; practical memory use and throughput improve.

#### Compare data, tensor and pipeline parallel training.

They partition different parts of the training work and create different communication patterns.

1. Data parallelism replicates the model across workers processing different batches, then synchronizes gradients.
2. Tensor parallelism splits individual matrix operations and usually requires frequent high-bandwidth communication within layers.
3. Pipeline parallelism assigns groups of layers to stages and streams microbatches through them; balance stages and account for pipeline bubbles. Combine approaches only after estimating memory and network costs.

### Understand why the approach works

#### Separate service time, queueing and memory

A request's observed latency is not just the model kernel duration:

$$
T_{\rm request}=T_{\rm queue}+T_{\rm preprocess}+T_{\rm prefill}
+T_{\rm decode}+T_{\rm delivery}.
$$

Prefill processes the prompt; decode repeatedly adds tokens. Measure both time to first token and inter-token latency, because a configuration can improve aggregate throughput while worsening the user's experience. Batching amortizes work but may increase waiting.

Estimate the KV tensor budget independently of fixed weights. For equal-length requests,

$$
M_{\rm KV}=2BLT H_{\rm KV}d_h s,
$$

where $L$ is layer count, $T$ cached length and $s$ bytes per element. The factor two is keys plus values. With $L=32$, $T=4096$, $H_{\rm KV}=8$, $d_h=128$, $B=1$ and $s=2$, the raw cache is $512$ MiB, before allocator overhead.

Use measured capacity to set admission and live-token limits. If a worker serves batches of at most $b$ in $s_b$ seconds, $b/s_b$ is an optimistic service-rate ceiling, not a per-request guarantee. Sustained arrivals above that rate grow backlog; even lower averages can hide damaging bursts. Bound queues, define cancellation and partial-failure behavior, and compare latency on matched length/concurrency distributions rather than one isolated request.

### Work a small example

A nominal 4-bit weight tensor uses one quarter the raw weight bytes of a 16-bit tensor, before scales, packing and unquantized tensors.

### Edge cases and common mistakes

Claiming a fourfold end-to-end memory or latency improvement from raw weight bits alone.

### Check your reasoning on related cases

**What makes attention quadratic, and what does FlashAttention change?** Doubling T from 1024 to 2048 quadruples the number of pairwise scores. A tiled kernel can avoid storing those scores all at once, but still processes the interactions.

Why can two exact implementations differ slightly? Floating-point reduction order and precision differ.

**Compare data, tensor and pipeline parallel training.** Two data-parallel workers with local batch 8 process a global batch of 16 if one synchronized update uses both batches without extra accumulation.

Where does gradient accumulation fit? It increases effective batch per update without adding devices, at extra sequential compute time.
