## Question

ML Coding — BERT Span / Keyphrase Extraction

ML coding round in a notebook: extract the single most relevant span from a text (e.g. an IMDB review) by predicting start/end positions with BERT. Scaffolding is provided; you implement the model (init/forward), the loss, and the training pieces so the notebook trains to a reasonable accuracy. GPT-style models are explicitly disallowed.

### Requirements

Given a passage (e.g. an IMDB movie review), output the key span — the start and end token positions of the most relevant fragment (not necessarily a full sentence). Implement a BERT-based extractor in a provided notebook:

Define the model: a BertModel encoder plus a linear head producing start and end logits over the sequence.
Implement forward (and a predict that turns logits into a span), and the loss (cross-entropy on start and end indices, averaged).
Fill in the training loop so the notebook runs end-to-end and trains to a reasonable metric (≈90%+ accuracy was expected in one case).
Follow-ups: how would you improve training, and how would you improve evaluation?

### Examples

```python
import torch
from torch import nn
from transformers import BertModel
```

```text
class KeyphraseExtractor(nn.Module):

```

super().__init__()
self.bert = BertModel.from_pretrained(bert_model_name)
self.linear = nn.Linear(self.bert.config.hidden_size, 2)  # start & end logits

```python
def forward(self, input_ids, attention_mask):
    outputs = self.bert(input_ids=input_ids, attention_mask=attention_mask)
    sequence_output = outputs.last_hidden_state        # (B, L, H)
    logits = self.linear(sequence_output)              # (B, L, 2)
```

start_logits, end_logits = logits.split(1, dim=-1)

```python
return start_logits.squeeze(-1), end_logits.squeeze(-1)
```

Training step: cross-entropy of start_logits vs start_idx and end_logits vs end_idx, averaged, then backward() / optimizer.step().

## Worked solution

### Solution outline

#### Why is a next-token model trained with shifted targets?

At position t, the model sees tokens through t and predicts token t+1. The target shift makes the training task match autoregressive generation.

1. Given tokens [x0,x1,x2,x3], use inputs [x0,x1,x2] and targets [x1,x2,x3], unless the library performs this shift internally.
2. Apply a causal mask to prevent access to later input positions. Use cross-entropy over vocabulary logits without an extra softmax first.
3. For instruction tuning, mask unwanted target positions after aligning the shift. Divide by the count of supervised targets, not padded sequence length.

#### Fit a baseline on messy tabular data without leakage.

Build a trustworthy split and simple baseline before sophisticated feature engineering.

1. Define the target, prediction time and unit of independence, then split by time or group if required.
2. Fit imputation, scaling and category encodings on training folds only. Start with a dummy baseline and a regularized linear or small tree model.
3. Evaluate slices, missingness patterns and calibration; document features unavailable at decision time and remove them.

### Understand why the approach works

#### Derive a local rule, then apply the chain rule

Treat a layer as a function with a declared input and output shape. Write the scalar loss and its reduction first: a sum, mean over rows and mean over all elements produce different gradient scales. For an affine layer $Y=XW+b$ with upstream gradient $G=\partial L/\partial Y$,

$$
\frac{\partial L}{\partial X}=GW^\top,\qquad
\frac{\partial L}{\partial W}=X^\top G,\qquad
\frac{\partial L}{\partial b}=\sum_i G_{i,:}.
$$

The bias sum is over all leading positions where the same bias was reused. Do not average again if $G$ already contains the mean-loss factor. For example, with one row $x=[2,3]$ and scalar upstream derivative $4$, the weight derivative is $[8,12]$.

Cache the forward values needed by the derivative; compute all gradients before updating parameters. Updating $W$ midway would make the earlier-layer derivative use a different function from the one evaluated forward.

Check a scalar objective using central differences:

$$
\frac{\partial L}{\partial\theta_j}\approx
\frac{L(\theta+h e_j)-L(\theta-h e_j)}{2h}.
$$

Use float64 and several sensible $h$ values. An arbitrarily tiny $h$ loses the difference to rounding, while a large one measures curvature rather than a local derivative. Avoid ReLU's kink at zero during this check, and test inputs, weights and biases separately.

### Apply this question’s exact contract

For span/keyphrase extraction, tokenize with offset mappings, align annotated character spans to token labels, and mask special/padding tokens. Choose token BIO classification or start/end heads explicitly; train the matching loss and decode only valid spans. Score exact and overlap-based span F1 separately. A word-level label copied to every subword without a stated rule changes the task.
