## Question

Concept round on LoRA and its variants — the rank parameterization, how it composes with full fine-tuning, QLoRA quantization, DoRA, AdaLoRA, and practical hyperparameter trade-offs.

## Worked solution

### LoRA: parameterize the update and count the memory

For W:(d_out,d_in), freeze W and train $W'=W+(\alpha/r)BA$ with A:(r,d_in),B:(d_out,r). Count r(d_in+d_out) adapter parameters, not r. A4096×4096 matrix at r8 has65,536 trainable adapter entries versus16,777,216 base entries. Random A/zero B starts with a zero update while allowing B gradients; both zero would stall both factors. Savings mainly concern trainable gradients/optimizer states and checkpoint size; base weights and forward/backprop activations still occupy memory.

LoRA is a constrained alternative to full fine-tuning. A model already fully fine-tuned can be a frozen base for another adapter; a compatible trained adapter can be merged into W for deployment, then later full-tuned if desired. Training W freely alongside BA removes most of the usual optimizer-memory benefit and makes the decomposition nonidentifiable. Several adapters can share one base and be selected per task; merging multiple deltas is possible algebraically but their combined behavior needs evaluation.

### QLoRA, DoRA and AdaLoRA are different changes

[QLoRA](https://arxiv.org/abs/2305.14314) freezes a4-bit quantized base and backpropagates through dequantized computation to adapters; its NF4, double-quantized scales and paged optimizer address memory. It does not mean all activations/gradients/optimizer state are4-bit. Quantization error and kernel/dequantization overhead must be measured; merging may require higher-precision reconstruction and requantization.

[DoRA](https://arxiv.org/abs/2402.09353) separates weight magnitude and direction, learning magnitude plus a low-rank directional update. With output-row normalization as the stated convention, write $W'_j=m_j(V_j+\Delta V_j)/\|V_j+\Delta V_j\|$. It adds trainable magnitude values and normalization overhead during adaptation while a merged dense inference representation can avoid a separate adapter path.

[AdaLoRA](https://arxiv.org/abs/2303.10512) allocates a fixed parameter budget unevenly across matrices using an SVD-like update parameterization and importance-based pruning of singular components. It can spend rank where useful rather than setting identical r everywhere, at the cost of importance estimates, budget schedules and more implementation complexity. It is not automatic proof that a smaller rank is better.

### Practical selection and tests

Tune rank, alpha/scaling, targeted Q/K/V/O/FFN matrices, adapter dropout, learning rate and training tokens on a held-out task set. Larger rank or more targeted layers adds capacity/optimizer state; low rank can underfit a large domain shift. Compare equal token/compute budgets, multiple seeds when feasible, target quality plus retention/safety slices, and end-to-end memory/latency. Verify frozen weights stay frozen, initial delta is zero, adapter gradients exist and merged/unmerged outputs match within the precision tolerance. Track base/tokenizer/quantization/adapter versions together; an adapter trained for one base is not automatically compatible with another.
