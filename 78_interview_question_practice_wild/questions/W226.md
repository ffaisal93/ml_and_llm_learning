## Question

<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">Problem: Implement a Multi-Armed Bandit Policy

You have K arms; choosing an arm yields a stochastic reward. Implement a bandit policy to maximize cumulative reward over T interactions.

Input

Line 1: three integers K T seed

K : number of arms (2 ≤ K ≤ 50)
T : number of rounds (1 ≤ T ≤ 200000)
seed : RNG seed used to generate rewards

Line 2: K floats p[0..K-1] (0 ≤ p[i] ≤ 1), Bernoulli success probabilities (reward is 0/1).

Environment

Initialize RNG with seed.

At round t (1-indexed), if you pick arm a, you get reward 1 with probability p[a], else 0.

Task

Implement UCB1:

Pull each arm at least once.
For t thereafter, pick arm a maximizing:
score(a) = μ̂_a + sqrt( (2 ln t) / n_a )

where μ̂_a is empirical mean reward and n_a is number of pulls for arm a.

Output

Print one integer: the total reward over T rounds.

Constraints
Must run efficiently up to T=200000.
Standard library only.
Sample Tests

See the 5 sample cases in the Chinese version.

Example

Input

3 10 42
0.1 0.5 0.9

Output

## Worked solution

1. Implement an epsilon-greedy multi-armed bandit. Balance learning about uncertain actions with exploiting the best current reward estimate.
2. Maintain each arm's count and mean reward, initializing under an explicit policy.
3. With probability epsilon choose a random arm; otherwise choose the greatest estimated mean with a specified tie rule.
4. Update a chosen arm's mean incrementally as mean+=(reward-mean)/count. Evaluate regret over repeated independent runs.
5. Explain an upper-confidence-bound bandit policy. UCB gives less-sampled arms an uncertainty bonus instead of exploring uniformly at random.
6. Pull each arm initially or define an infinite score for untried arms.
7. Select the arm maximizing empirical_mean+c*sqrt(log(t)/count), with the constant and reward assumptions explicit.
8. Update only the chosen arm and inspect behavior under nonstationary rewards, where the stationary formula can become stale.

### Small example / sanity check

An arm with rewards 1,0,1 has running mean 2/3 after three pulls.

### Common trap

Updating every arm from one arm's observed reward or evaluating only the final estimated winner.
