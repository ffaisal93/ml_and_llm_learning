## Question

Problem: Implement a Multi-Armed Bandit Policy

You have K arms; choosing an arm yields a stochastic reward. Implement a bandit policy to maximize cumulative reward over T interactions.

### Input

Line 1: three integers K T seed

K : number of arms (2 ≤ K ≤ 50)
T : number of rounds (1 ≤ T ≤ 200000)
seed : RNG seed used to generate rewards

Line 2: K floats p[0..K-1] (0 ≤ p[i] ≤ 1), Bernoulli success probabilities (reward is 0/1).

Environment

Initialize RNG with seed.

At round t (1-indexed), if you pick arm a, you get reward 1 with probability p[a], else 0.

Task

Implement UCB1:

Pull each arm at least once.
For t thereafter, pick arm a maximizing:
score(a) = μ̂_a + sqrt( (2 ln t) / n_a )

where μ̂_a is empirical mean reward and n_a is number of pulls for arm a.

### Output

Print one integer: the total reward over T rounds.

### Constraints

Must run efficiently up to T=200000.
Standard library only.
Sample Tests

See the 5 sample cases in the Chinese version.

Example

### Input

```text
3 10 42
0.1 0.5 0.9
```

## Worked solution

### Solution outline

#### Implement an epsilon-greedy multi-armed bandit.

Balance learning about uncertain actions with exploiting the best current reward estimate.

1. Maintain each arm's count and mean reward, initializing under an explicit policy.
2. With probability epsilon choose a random arm; otherwise choose the greatest estimated mean with a specified tie rule.
3. Update a chosen arm's mean incrementally as mean+=(reward-mean)/count. Evaluate regret over repeated independent runs.

#### Explain an upper-confidence-bound bandit policy.

UCB gives less-sampled arms an uncertainty bonus instead of exploring uniformly at random.

1. Pull each arm initially or define an infinite score for untried arms.
2. Select the arm maximizing empirical_mean+c*sqrt(log(t)/count), with the constant and reward assumptions explicit.
3. Update only the chosen arm and inspect behavior under nonstationary rewards, where the stationary formula can become stale.

### Understand why the approach works

#### Separate the environment, policy and value estimate

Define states, actions, transitions, reward timing and terminal behavior before choosing an algorithm. For a finite discounted MDP,

$$
V^*(s)=\max_a\sum_{s'}P(s'\mid s,a)
\bigl[R(s,a,s')+\gamma V^*(s')\bigr].
$$

Value iteration applies this optimality backup; policy iteration alternates evaluation of a fixed policy with greedy improvement. A terminal state should not silently continue generating discounted value. The standard contraction argument uses $0\le\gamma<1$; an undiscounted problem needs additional assumptions.

Bandits have no state-transition planning in their ordinary form. An epsilon-greedy policy maintains each arm's reward estimate and mixes exploration with exploitation. Its incremental sample-mean update is

$$
\hat\mu_n=\hat\mu_{n-1}+\frac{r_n-\hat\mu_{n-1}}n.
$$

Update only the selected arm from its observed reward. Compare repeated-run regret and adaptation, not only the final winning arm. A stationary confidence bonus can become stale when reward distributions drift. In policy optimization, a baseline and clipping can reduce estimation/update problems, but they cannot make an unreliable reward represent the intended task. Evaluate behavior independently of the training reward.

### Work a small example

An arm with rewards 1,0,1 has running mean 2/3 after three pulls.

### Edge cases and common mistakes

Updating every arm from one arm's observed reward or evaluating only the final estimated winner.
