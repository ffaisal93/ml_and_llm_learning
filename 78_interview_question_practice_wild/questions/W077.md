## Question

Given n binary classification samples, true labels y_i ∈ {0,1}, and predicted probabilities p_i for the positive class, implement Binary Focal Loss.

For each sample:

If $y_i = 1$, then $p_t = p_i$ and $\alpha_t = \alpha$.
If $y_i = 0$, then $p_t = 1 - p_i$ and $\alpha_t = 1 - \alpha$.

The per-sample loss is:

```python
loss_i = - alpha_t * (1 - p_t)^gamma * log(p_t)
```

To avoid log(0), clip probabilities to [1e-15, 1 - 1e-15].

### Input Format

n gamma alpha reduction
y_1 y_2 ... y_n
p_1 p_2 ... p_n

Where reduction is one of mean, sum, or none:

mean outputs the average loss.
sum outputs the total loss.
none outputs every sample's loss.
Output Format
If reduction is mean or sum, print one float rounded to 6 decimal places.
If reduction is none, print n floats separated by spaces, each rounded to 6 decimal places.

### Constraints

1 &lt;= n &lt;= 100000
0 &lt;= gamma &lt;= 10
0 &lt;= alpha &lt;= 1
0 &lt;= p_i &lt;= 1
Example

### Input

```text
3 2.0 0.25 mean
1 0 1
0.9 0.1 0.2
```

## Worked solution

### Why the loss changes with confidence

Ordinary binary cross-entropy gives every sample a log penalty. Focal loss multiplies that penalty by $(1-p_t)^\gamma$, so an already-correct confident example contributes much less. The class factor is $\alpha$ for positive labels and $1-\alpha$ for negative labels; it is not always the same multiplier.

$$L_i=-\alpha_t(1-p_t)^\gamma\log p_t.$$

At $\gamma=0$ this becomes alpha-weighted binary cross-entropy. With $p_t=0.9$ and $\gamma=2$, the focusing multiplier is 0.01; with $p_t=0.2$ it is 0.64. This emphasizes difficult examples, which can also emphasize mislabeled data.

### Exact probability-input solution

[Download the complete CLI](../focal_077.py).

```python
"""W077 exact probability-input CLI."""
import math
import sys

def focal_loss(labels,probabilities,gamma=2.,alpha=.25,reduction='mean'):
    if not labels or len(labels)!=len(probabilities):
        raise ValueError('Need matching nonempty inputs')
    if gamma<0 or not 0<=alpha<=1: raise ValueError('Invalid gamma/alpha')
    losses=[]
    for y,p in zip(labels,probabilities):
        if y not in (0,1) or not 0<=p<=1: raise ValueError('Invalid label/probability')
        p=min(max(p,1e-15),1-1e-15)
        pt=p if y else 1-p
        at=alpha if y else 1-alpha
        losses.append(-at*(1-pt)**gamma*math.log(pt))
    if reduction=='none': return losses
    if reduction=='sum': return math.fsum(losses)
    if reduction=='mean': return math.fsum(losses)/len(losses)
    raise ValueError('Unknown reduction')

if __name__=='__main__':
    tokens=sys.stdin.read().split()
    n=int(tokens[0]); gamma=float(tokens[1]); alpha=float(tokens[2]); reduction=tokens[3]
    if len(tokens)!=4+2*n: raise ValueError('Wrong number of inputs')
    result=focal_loss(list(map(int,tokens[4:4+n])),list(map(float,tokens[4+n:])),gamma,alpha,reduction)
    values=result if isinstance(result,list) else [result]
    print(' '.join(f'{value:.6f}' for value in values))

```

Clipping applies to the supplied positive-class probability before constructing $p_t$. This keeps endpoint inputs finite. Mean divides by the number of samples, not by the sum of alpha weights. For the supplied example, the three losses are approximately `0.000263`, `0.000790` and `0.257510`, giving mean `0.086188`. Check all three reductions and endpoints zero/one. Time is $O(n)$; retaining per-example output uses $O(n)$ space.

### Differentiable PyTorch version

For training, prefer raw logits and stable binary cross-entropy:

```python
import torch
from torch.nn import functional as F

def focal_from_logits(logits, labels, gamma=2., alpha=.25, reduction='mean'):
    labels = labels.to(dtype=logits.dtype)
    cross_entropy = F.binary_cross_entropy_with_logits(logits, labels, reduction='none')
    probability = logits.sigmoid()
    pt = torch.where(labels == 1, probability, 1 - probability)
    alpha_t = torch.where(labels == 1, alpha, 1 - alpha)
    losses = alpha_t * (1 - pt).pow(gamma) * cross_entropy
    if reduction == 'none':
        return losses
    if reduction == 'sum':
        return losses.sum()
    if reduction == 'mean':
        return losses.mean()
    raise ValueError('Unknown reduction')
```

This avoids `log(sigmoid(logit))` underflow. At extreme logits it intentionally follows the stable logit loss rather than capping loss at the exercise's clipped probability threshold. Keep that distinction explicit when comparing the implementations. Validate that labels have the same shape as logits, are binary, and gamma/alpha satisfy the stated bounds before training. Check gradients are finite and that gamma zero agrees with weighted BCE on non-extreme inputs.
