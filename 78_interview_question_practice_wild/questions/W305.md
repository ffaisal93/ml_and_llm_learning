## Question

<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">A streaming service logs a watch event whenever a viewer&#x27;s progress through a movie is reported. To judge how well a newly launched movie is landing, the data team wants to know, for every viewer and movie, how far the viewer really got. Write a function that classifies each (viewer, movie) pair into a completion bucket from a raw, messy stream of those events.

What to implement
def classify_completion(events: list[tuple[str, str, float]]) -&gt; list[tuple[str, str, int]]
events: a list of (user_id, movie_id, percent_watched) tuples. user_id and movie_id are strings; percent_watched is a number from 0 to 100 inclusive. Events arrive in any order, and the same user and movie can appear many times (progress is reported repeatedly, and late events are common).
Return a list of (user_id, movie_id, bucket) tuples, where bucket is 30, 50 or 80.
Rules
1.
Deduplicate. For each (user_id, movie_id) pair, only the highest percent_watched over all of its events counts. The order of the events does not matter.
2.
Bucket. A pair belongs to the largest threshold in (30, 50, 80) that its highest percentage reaches or exceeds. So 30 belongs to bucket 30, 79.99 to bucket 50, 80 and 100 to bucket 80.
3.
Below 30. A pair whose highest percentage is below 30 is left out of the result.
4.
Order. Sort the result by movie_id ascending, then user_id ascending (plain string comparison), with exactly one tuple per pair.
5.
No events, or no pair reaching 30, gives an empty list.
Examples

Example 1: deduplication keeps the maximum, not the latest.

events = [(&quot;u1&quot;, &quot;m1&quot;, 20), (&quot;u1&quot;, &quot;m1&quot;, 85), (&quot;u1&quot;, &quot;m1&quot;, 40)]
-&gt; [(&quot;u1&quot;, &quot;m1&quot;, 80)]     (the highest progress is 85, even though the last event says 40)

Example 2: buckets, boundaries, sorting and the cutoff.

events = [(&quot;u2&quot;, &quot;m1&quot;, 50), (&quot;u1&quot;, &quot;m1&quot;, 29.9), (&quot;u3&quot;, &quot;m1&quot;, 30),
(&quot;u1&quot;, &quot;m0&quot;, 79.99), (&quot;u2&quot;, &quot;m0&quot;, 100)]
-&gt; [(&quot;u1&quot;, &quot;m0&quot;, 50), (&quot;u2&quot;, &quot;m0&quot;, 80), (&quot;u2&quot;, &quot;m1&quot;, 50), (&quot;u3&quot;, &quot;m1&quot;, 30)]

(&quot;u1&quot;, &quot;m1&quot;) stays below 30 and is dropped; the rest are sorted by movie, then user.

Constraints
Up to 2 * 10^5 events, and up to 2 * 10^5 distinct pairs.
The function should run in O(n log n) time; comparing every event with every other event is too slow.
Standard library only.</pre>

## Worked solution

1. Classify viewers using movie completion behavior. The definition of completion and the observation window determine the label before modeling begins.
2. Define eligible starts, completion thresholds, replays, partial sessions and late events.
3. Construct user/item/context features available at the intended prediction time and split by time or entity as appropriate.
4. Compare a simple baseline, inspect duration and user-segment effects and evaluate the downstream intervention rather than classification alone.

### Small example / sanity check

Watching 90 minutes means different completion fractions for a 95-minute film and a 180-minute film.

### Common trap

Including the final watched duration as a feature when predicting completion at playback start.
