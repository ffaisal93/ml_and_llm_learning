## Question

Hand-implement the InfoNCE contrastive loss in PyTorch given a batch of query and key embeddings. An Amazon Applied Scientist intern phone-screen round, run alongside Transformer / Adam / RoPE concept questions.

### Requirements

Inputs: query embeddings q of shape (B, D) and key embeddings k of shape (B, D). Positive pair (q_i, k_i); the other B - 1 keys are negatives.
Compute the symmetric InfoNCE loss with temperature tau.
Return a scalar loss tensor compatible with backward().

### Examples

```python
def info_nce(q, k, tau=0.07):
    q = F.normalize(q, dim=-1)
    k = F.normalize(k, dim=-1)
    logits = q @ k.t() / tau            # (B, B)
    labels = torch.arange(q.size(0), device=q.device)
    loss_q = F.cross_entropy(logits, labels)
    loss_k = F.cross_entropy(logits.t(), labels)
    return 0.5 * (loss_q + loss_k)
```

Notes
Normalize before the dot product or temperature loses calibration. Prefer cross_entropy over manual exp(sim/tau) (numerical stability / built-in log-sum-exp). Symmetric variant (SimCLR) averages both directions. Temperature tau 0.05-0.2. Below ~256 batch, negatives are weak - fall back to a memory bank / MoCo queue; .detach() the momentum key branch.

## Worked solution

### Solution outline

#### Implement symmetric InfoNCE loss.

A matched query/key pair should score above other examples in the batch, in both retrieval directions.

1. Normalize q and k along the embedding dimension and require temperature>0.
2. Compute logits=q@kᵀ/temperature; the correct key for query i is index i. Use stable cross-entropy across each row.
3. Average query-to-key and key-to-query cross-entropies. Keep the computation differentiable in a training implementation and define how duplicate positives are treated.

#### Handle multiple positive pairs in a contrastive batch.

A diagonal-only target is wrong when several keys are valid matches for a query.

1. Construct a positive relation mask from task labels or known matches.
2. Choose a documented multi-positive objective, such as log(sum positive exp scores)-log(sum all exp scores), with stable reductions.
3. Define how queries without positives are handled and ensure evaluation measures the same relevance relation.

### Understand why the approach works

#### Derive the diagonal contrastive targets

For matched query/key rows $(q_i,k_i)$, normalize each nonzero vector and form a batch similarity matrix

$$
S_{ij}=\frac{\tilde q_i^\top\tilde k_j}{\tau},\qquad
L_{q\to k}=-\frac1B\sum_i\log\frac{e^{S_{ii}}}{\sum_j e^{S_{ij}}}.
$$

The key-to-query loss uses $S^\top$; the symmetric objective is $(L_{q\to k}+L_{k\to q})/2$. Temperature controls logit sharpness and gradient scale. Normalizing first makes this interpretation independent of arbitrary positive embedding scale.

A batch of one has zero loss because the only key is the positive. That is a warning about absent negatives, not evidence of perfect semantic retrieval. Likewise, repeated or alternative true matches can be wrongly penalized as negatives by a diagonal-only target.

Use stable log-softmax/cross-entropy rather than manually exponentiating large scores. A NumPy implementation is a forward numerical reference; training needs the equivalent differentiable operations so gradients flow into both intended branches. A deliberately detached momentum branch is a different architecture decision, not an accidental conversion to NumPy.

Test swapping $q$ and $k$, positive row scaling, small temperature and zero-norm input policy. If negatives are gathered across workers, adjust each positive index and specify whether gradients cross that collective. More negatives can help discrimination, but label correctness and negative distribution are at least as important as the raw batch count.

### Work a small example

For B=1 there are no in-batch negatives and the loss is zero, which does not mean the embedding model is useful.

### Edge cases and common mistakes

Treating all same-batch non-diagonal examples as valid negatives when some are actually semantically positive.

### Check your reasoning on related cases

**Handle multiple positive pairs in a contrastive batch.** If two captions correctly describe the same image, penalizing one as a negative contradicts the task labels.

Can different multi-positive reductions behave differently? Yes; averaging positive log probabilities and logging their summed probability are different objectives.
