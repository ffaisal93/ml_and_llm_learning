## Question

<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">Hand-implement the InfoNCE contrastive loss in PyTorch given a batch of query and key embeddings. An Amazon Applied Scientist intern phone-screen round, run alongside Transformer / Adam / RoPE concept questions.

Requirements
Inputs: query embeddings q of shape (B, D) and key embeddings k of shape (B, D). Positive pair (q_i, k_i); the other B - 1 keys are negatives.
Compute the symmetric InfoNCE loss with temperature tau.
Return a scalar loss tensor compatible with backward().
Examples
def info_nce(q, k, tau=0.07):
q = F.normalize(q, dim=-1)
k = F.normalize(k, dim=-1)
logits = q @ k.t() / tau            # (B, B)
labels = torch.arange(q.size(0), device=q.device)
loss_q = F.cross_entropy(logits, labels)
loss_k = F.cross_entropy(logits.t(), labels)
return 0.5 * (loss_q + loss_k)
Notes
Normalize before the dot product or temperature loses calibration. Prefer cross_entropy over manual exp(sim/tau) (numerical stability / built-in log-sum-exp). Symmetric variant (SimCLR) averages both directions. Temperature tau 0.05-0.2. Below ~256 batch, negatives are weak - fall back to a memory bank / MoCo queue; .detach() the momentum key branch.</pre>

## Worked solution

1. Implement symmetric InfoNCE loss. A matched query/key pair should score above other examples in the batch, in both retrieval directions.
2. Normalize q and k along the embedding dimension and require temperature>0.
3. Compute logits=q@kᵀ/temperature; the correct key for query i is index i. Use stable cross-entropy across each row.
4. Average query-to-key and key-to-query cross-entropies. Keep the computation differentiable in a training implementation and define how duplicate positives are treated.
5. Handle multiple positive pairs in a contrastive batch. A diagonal-only target is wrong when several keys are valid matches for a query.
6. Construct a positive relation mask from task labels or known matches.
7. Choose a documented multi-positive objective, such as log(sum positive exp scores)-log(sum all exp scores), with stable reductions.
8. Define how queries without positives are handled and ensure evaluation measures the same relevance relation.

### Small example / sanity check

For B=1 there are no in-batch negatives and the loss is zero, which does not mean the embedding model is useful.

### Common trap

Treating all same-batch non-diagonal examples as valid negatives when some are actually semantically positive.
