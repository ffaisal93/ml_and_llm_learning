## Question

Hand-implement the InfoNCE contrastive loss in PyTorch given a batch of query and key embeddings. An Amazon Applied Scientist intern phone-screen round, run alongside Transformer / Adam / RoPE concept questions.

### Requirements

Inputs: query embeddings q of shape (B, D) and key embeddings k of shape (B, D). Positive pair (q_i, k_i); the other B - 1 keys are negatives.
Compute the symmetric InfoNCE loss with temperature tau.
Return a scalar loss tensor compatible with backward().

### Examples

```python
def info_nce(q, k, tau=0.07):
    q = F.normalize(q, dim=-1)
    k = F.normalize(k, dim=-1)
    logits = q @ k.t() / tau            # (B, B)
    labels = torch.arange(q.size(0), device=q.device)
    loss_q = F.cross_entropy(logits, labels)
    loss_k = F.cross_entropy(logits.t(), labels)
    return 0.5 * (loss_q + loss_k)
```

Notes
Normalize before the dot product or temperature loses calibration. Prefer cross_entropy over manual exp(sim/tau) (numerical stability / built-in log-sum-exp). Symmetric variant (SimCLR) averages both directions. Temperature tau 0.05-0.2. Below ~256 batch, negatives are weak - fall back to a memory bank / MoCo queue; .detach() the momentum key branch.

## Worked solution

### A differentiable symmetric InfoNCE implementation

Normalize each nonzero row so arbitrary embedding norm cannot replace meaningful similarity, form $S_{ij}=(q_i^{\mathrm{norm}})^T k_j^{\mathrm{norm}}/\tau$, and use diagonal labels. Minimize

$$L=\tfrac12\left[-\tfrac1B\sum_i\log\frac{e^{S_{ii}}}{\sum_j e^{S_{ij}}}-\tfrac1B\sum_i\log\frac{e^{S_{ii}}}{\sum_j e^{S_{ji}}}\right].$$

Stable cross-entropy retains autograd paths through both inputs. This version rejects zero vectors because their cosine is undefined; an epsilon-normalization convention would be a different explicit policy.

```python
import torch
import torch.nn.functional as F


def info_nce(q, k, tau=0.07):
    if q.ndim != 2 or q.shape != k.shape or not len(q) or tau <= 0:
        raise ValueError("invalid shape/temperature")
    if not torch.isfinite(q).all() or not torch.isfinite(k).all():
        raise ValueError("finite embeddings required")
    # Define zero-vector policy explicitly: reject, rather than assign a cosine.
    if (q.norm(dim=-1) == 0).any() or (k.norm(dim=-1) == 0).any():
        raise ValueError("nonzero vectors required")
    q = F.normalize(q, dim=-1)
    k = F.normalize(k, dim=-1)
    logits = q @ k.T / tau
    labels = torch.arange(len(q), device=q.device)
    return 0.5 * (F.cross_entropy(logits, labels) + F.cross_entropy(logits.T, labels))


if __name__ == "__main__":
    torch.set_num_threads(1)
    torch.manual_seed(7)
    q = torch.randn(4, 3, dtype=torch.float64, requires_grad=True)
    k = torch.randn(4, 3, dtype=torch.float64, requires_grad=True)
    loss = info_nce(q, k)
    loss.backward()
    assert torch.isfinite(q.grad).all() and torch.isfinite(k.grad).all()
    assert torch.allclose(info_nce(q, k), info_nce(k, q))
    assert torch.allclose(info_nce(q * 3, k * 7), loss)
    assert info_nce(q[:1], k[:1]).item() == 0
    assert torch.autograd.gradcheck(
        lambda a, b: info_nce(a, b, 0.2), (q, k), eps=1e-6, atol=1e-5
    )
    eye = torch.eye(3, dtype=torch.float64)
    assert info_nce(eye, eye).item() < info_nce(eye, eye.roll(1, 0)).item()
    print(
        "W015: symmetry, scaling, singleton, gradients and paired-versus-shuffled behavior passed"
    )
```

### Tests, limits and negative quality

Swapping q/k leaves the loss unchanged; positive row scaling leaves normalized similarity unchanged; B=1 has zero loss because no negatives exist. The test checks all these, finite gradients, numerical gradcheck and lower loss for aligned versus shuffled orthogonal pairs. Space O(B²+BD), compute O(B²D).

Diagonal targets assume every other key is a negative. Multiple valid captions/duplicate sources violate that assumption and need a multi-positive objective or masking. A memory bank/momentum queue can add negatives when a batch is small, with detached key targets by design and possibly stale representations; there is no universal “batch<256 fails” cutoff. The supplied symmetric paired-view objective is not identical to full SimCLR's 2B-view negative set, so describe the actual matrix rather than conflating names.
