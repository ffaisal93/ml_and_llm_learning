## Question

You join a timed debugging exercise: a small backend repository with seeded bugs, a test suite, and an AI coding assistant built into the editor that can see only the file currently open. You have 60 minutes to make as many tests pass as you can. This question gives you one concrete repository state and asks how you would work through it, from reading the test output to submitting a minimal fix.

The repository

A product-review service. The task description lists three broken behaviours:
1. A review containing a banned word is saved and returns 201. It must be rejected with 403 and the body {"error": "review contains banned content", "words": [...]} listing the banned words found.
2. The user's violation count does not go up when a review is rejected.
3. A user is not flagged after their third violation.

The README also states the contract the tests check:

A flagged user cannot add or edit reviews: both return 403 with {"error": "user is blocked"} and nothing is saved.
A rejected review or edit is not saved. Each rejection adds 1 to user.violations and appends the banned words to user.violated_words; the user is flagged when violations reaches 3.
The repository object repo returns copies. A change to a User or Review is kept only after repo.save_user(user) or repo.save_review(review). repo.create_review(...) saves the new review itself.

## Worked solution

### Map each failure to its exact cause

| Failing test | Function and cause |
|---|---|
| add_banned_review_returns_403 | add_review creates the review before checking content |
| violation_count_persisted | add/edit must call _record_violation; that method must save the copied user |
| flagged_on_third_strike | _record_violation uses >3 instead of >=3 |
| flagged_user_cannot_post | add_review lacks a blocked-user guard; edit needs the same guard |
| edit_with_banned_word_returns_403 | edit_review never validates content before modifying the copy |
| edit_is_persisted | edit_review never calls save_review |

Blocked-user behavior, rejected edits and persistence of allowed edits extend beyond the three initially listed symptoms. Fix them because the README/test contract explicitly includes them. No test/Repo change is justified.

### Exact prompt to the file-limited assistant

> In the currently open reviews/service.py, localize test_add_banned_review_returns_403: it receives 201 for text containing “scam” but expects 403 and {"error":"review contains banned content","words":["scam"]}. The repository returns copies, create_review saves immediately, and rejected text must never be saved. Read add_review and find_banned_words in this file. Identify the missing guard and the earliest safe place for it; propose the smallest change only, preserving names and (status,body) returns. Do not edit tests or assume other files are visible. Explain why create_review must come after validation.

### Minimal service patch plus independent demonstration checks

The service portion changes only guards, validation, the strike comparison and explicit persistence. find_banned_words retains the given matching semantics. The `check()` function is a separate runnable fixture for this answer, not a proposed addition to the exercise service file.

```python
BANNED_WORDS={'scam','fake','fraud'}
MAX_STRIKES=3


def find_banned_words(text):
    found=[]
    for word in text.lower().split():
        word=word.strip('.,!?')
        if word in BANNED_WORDS and word not in found:found.append(word)
    return found


class ReviewService:
    def __init__(self,repo):self.repo=repo

    def add_review(self,user_id,product_id,text):
        user=self.repo.get_user(user_id)
        if user.flagged:return 403,{'error':'user is blocked'}
        words=find_banned_words(text)
        if words:
            self._record_violation(user,words)
            return 403,{'error':'review contains banned content','words':words}
        review=self.repo.create_review(user_id,product_id,text)
        return 201,{'id':review.id}

    def edit_review(self,user_id,review_id,text):
        user=self.repo.get_user(user_id)
        if user.flagged:return 403,{'error':'user is blocked'}
        words=find_banned_words(text)
        if words:
            self._record_violation(user,words)
            return 403,{'error':'review contains banned content','words':words}
        review=self.repo.get_review(review_id)
        review.text=text
        self.repo.save_review(review)
        return 200,{'id':review.id}

    def _record_violation(self,user,words):
        user.violations+=1
        user.violated_words.extend(words)
        if user.violations>=MAX_STRIKES:user.flagged=True
        self.repo.save_user(user)


def check():
    # A chosen minimal repository fixture honoring the explicitly stated copy contract.
    from dataclasses import dataclass,field
    from copy import deepcopy
    @dataclass
    class User:
        violations:int=0
        violated_words:list=field(default_factory=list)
        flagged:bool=False
    @dataclass
    class Review:
        id:int
        text:str
    class Repo:
        def __init__(self):self.users={1:User()};self.reviews={}
        def get_user(self,i):return deepcopy(self.users[i])
        def save_user(self,u):self.users[1]=deepcopy(u)
        def get_review(self,i):return deepcopy(self.reviews[i])
        def save_review(self,r):self.reviews[r.id]=deepcopy(r)
        def create_review(self,uid,pid,text):
            r=Review(len(self.reviews)+1,text);self.save_review(r);return r
    repo=Repo();service=ReviewService(repo)
    assert service.add_review(1,7,'great')==(201,{'id':1})
    assert service.edit_review(1,1,'great, works well')==(200,{'id':1})
    assert repo.get_review(1).text=='great, works well'
    for text in ['SCAM, scam fake!','fraud','fake']:
        assert service.edit_review(1,1,text)[0]==403
        assert repo.get_review(1).text=='great, works well'
    user=repo.get_user(1)
    assert user.violations==3 and user.flagged
    assert user.violated_words==['scam','fake','fraud','fake']
    assert service.add_review(1,7,'fine')==(403,{'error':'user is blocked'})
    assert service.edit_review(1,1,'fine')==(403,{'error':'user is blocked'})
    assert repo.get_user(1).violations==3 and len(repo.reviews)==1
    repo2=Repo();s2=ReviewService(repo2)
    assert s2.add_review(1,7,'fake!')==(403,{'error':'review contains banned content','words':['fake']})
    assert not repo2.reviews and repo2.get_user(1).violations==1
    print('W137: copy-returning fixture checks passed; original repository tests not supplied')

if __name__=='__main__':check()
```

### Verification and a sixty-minute plan

In the actual supplied repository run `pytest -q` to reproduce, then `pytest -q tests/test_reviews.py::test_add_banned_review_returns_403`, the violation/third-strike tests, then edit and blocked-user tests, then `pytest -q tests/test_reviews.py`, finally full `pytest -q`. Inspect `git diff --check` and `git diff -- reviews/service.py`, and verify only the permitted service file changed. The original repository/tests are not attached here; only the explicit copy-returning fixture checks were executed, so do not claim “14 passed” for an unavailable suite.

Spend minutes 0–8 reading README/tests and reproducing; 8–20 fix add/content/strike persistence; 20–35 fix edit/blocked paths and run targeted checks; 35–48 run all tests and inspect edge cases; 48–60 reserve for diff review and submission. If ten minutes remain and two tests fail, read their exact assertions, prioritize the smallest shared root cause and preserve working fixes. Avoid broad refactoring or changing test expectations; report unresolved failures honestly if necessary. A flagged attempt does not add a fourth strike because it is blocked before content evaluation. Concurrent atomicity/ownership validation might be production concerns, but they are outside this constrained patch and no extra API/return shapes are invented.
