## Question

<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">You join a timed debugging exercise: a small backend repository with seeded bugs, a test suite, and an AI coding assistant built into the editor that can see only the file currently open. You have 60 minutes to make as many tests pass as you can. This question gives you one concrete repository state and asks how you would work through it, from reading the test output to submitting a minimal fix.

The repository

A product-review service. The task description lists three broken behaviours:

1.
A review containing a banned word is saved and returns 201. It must be rejected with 403 and the body {&quot;error&quot;: &quot;review contains banned content&quot;, &quot;words&quot;: [...]} listing the banned words found.
2.
The user&#x27;s violation count does not go up when a review is rejected.
3.
A user is not flagged after their third violation.

The README also states the contract the tests check:

A flagged user cannot add or edit reviews: both return 403 with {&quot;error&quot;: &quot;user is blocked&quot;} and nothing is saved.
A rejected review or edit is not saved. Each rejection adds 1 to user.violations and appends the banned words to user.violated_words; the user is flagged when violations reaches 3.
The repository object repo returns copies. A change to a User or Review is kept only after repo.save_user(user) or repo.save_review(review). repo.create_review(...) saves the new review itself.

The service file, reviews/service.py:

BANNED_WORDS = {&quot;scam&quot;, &quot;fake&quot;, &quot;fraud&quot;}
MAX_STRIKES = 3

def find_banned_words(text):
&quot;&quot;&quot;Banned words in text, lowercased, in order of first appearance.&quot;&quot;&quot;
found = []
for word in text.lower().split():
word = word.strip(&quot;.,!?&quot;)
if word in BANNED_WORDS and word not in found:
found.append(word)
return found

class ReviewService:
def __init__(self, repo):
self.repo = repo

def add_review(self, user_id, product_id, text):
user = self.repo.get_user(user_id)
review = self.repo.create_review(user_id, product_id, text)
return 201, {&quot;id&quot;: review.id}

def edit_review(self, user_id, review_id, text):
review = self.repo.get_review(review_id)
review.text = text
return 200, {&quot;id&quot;: review.id}

def _record_violation(self, user, words):
user.violations += 1
user.violated_words.extend(words)
if user.violations &gt; MAX_STRIKES:
user.flagged = True

## Worked solution

1. Reproduce the failure from a clean checkout and capture the smallest failing input. Read the contract and trace the relevant data/control path before editing.
2. Form one testable hypothesis, inspect logs/stack traces and add a regression case that distinguishes the bug from correct behavior.
3. Make the smallest justified patch, run the regression and relevant surrounding checks, and inspect the diff for unrelated changes. Verify any AI-suggested code against the contract rather than accepting its explanation as evidence.
4. Separate immediate repair from longer-term cleanup: document the underlying invariant, improve interfaces or observability, and prioritize follow-up work by recurrence and impact.

### Small example / sanity check

If one branch passes a stale cache key, a regression must use two distinct model/input versions so the incorrect sharing becomes observable.

### Common trap

Changing several suspected causes at once or replacing the failing assertion instead of fixing the cause.
