## Question

Write SQL statements to implement select, select limit, and select where. Given an example data table where each row contains columns with different data types (such as ID and Name), implement complete SQL code that can perform these operations and design some test cases to verify the correctness of the code. Note: You may need to implement all logic from scratch if the programming language used does not have boilerplate code.

Example

```sql
CREATE TABLE students (id INT, name VARCHAR(255), age INT);
INSERT INTO students VALUES
(1, 'Alice', 22),
(2, 'Bob', 25),
(3, 'Charlie', 30);
SELECT * FROM students; SELECT * FROM students LIMIT 2; SELECT * FROM students WHERE age > 24;
```

## Worked solution

### Solution outline

1. Define the example schema and insert the three rows before querying. SELECT projects columns, WHERE filters rows and LIMIT bounds the returned row count.
2. Use ORDER BY for deterministic limited results; without it SQL does not promise which two rows LIMIT returns.
3. If asked to implement relational operations in a general-purpose language instead of SQL, use independent projection, predicate-filter and limit functions over typed rows; do not claim the exercise requires a full SQL parser.

### Understand why the approach works

#### Establish row grain before writing a join

Say what one output row represents: an event, user, vendor, parent type or time interval. Then inspect the cardinality of every join. Joining two one-to-many relations can multiply rows and inflate both totals and averages; `DISTINCT` is not a general repair because legitimate equal-valued records can also exist.

For mergeable averages store a sum and count:

$$
\bar x_{\rm pooled}=\frac{\sum_g \operatorname{sum}_g}{\sum_g \operatorname{count}_g}.
$$

Do not average subgroup means unless the intended weighting gives each group equal weight. Likewise, daily distinct users cannot be added to obtain monthly distinct users.

Use half-open time windows, such as `timestamp >= start AND timestamp < end`, and name the timezone. For point-in-time training, feature **availability time** must not exceed prediction time; event occurrence and availability can differ.

Choose tie semantics deliberately: `ROW_NUMBER` produces a fixed number of rows under a deterministic secondary order, while `DENSE_RANK` preserves equal primary scores. A predicate on a nullable right-table column in `WHERE` can undo the unmatched-row preservation of a `LEFT JOIN`. Test duplicate events, absent dimension rows, nulls, tied maxima and an empty denominator. These cases explain correctness more convincingly than running only one ordinary example.

### Complete reference query

```sql
SELECT id,name,age FROM students ORDER BY id;
SELECT id,name,age FROM students ORDER BY id LIMIT 2;
SELECT id,name,age FROM students WHERE age>24 ORDER BY id;
```

### Work a small example

The final query returns Bob (25) and Charlie (30); the limited ordered query returns Alice and Bob.

### Edge cases and common mistakes

Treating implicit row storage order as guaranteed SELECT order.
