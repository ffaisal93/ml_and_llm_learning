## Question

Write SQL statements to implement select, select limit, and select where. Given an example data table where each row contains columns with different data types (such as ID and Name), implement complete SQL code that can perform these operations and design some test cases to verify the correctness of the code. Note: You may need to implement all logic from scratch if the programming language used does not have boilerplate code.

Example

```sql
CREATE TABLE students (id INT, name VARCHAR(255), age INT);
INSERT INTO students VALUES
(1, 'Alice', 22),
(2, 'Bob', 25),
(3, 'Charlie', 30);
SELECT * FROM students; SELECT * FROM students LIMIT 2; SELECT * FROM students WHERE age > 24;
```

## Worked solution

### Executable SELECT, LIMIT and WHERE

The supplied students schema is sufficient; use a stable ORDER BY when a limited result must be predictable. SQL row order without ORDER BY is unspecified, even if a tiny fixture happens to return insertion order.

```sql
CREATE TABLE students(id INTEGER PRIMARY KEY,name VARCHAR(255),age INTEGER);
INSERT INTO students VALUES(1,'Alice',22),(2,'Bob',25),(3,'Charlie',30);
SELECT id,name,age FROM students ORDER BY id;
SELECT id,name,age FROM students ORDER BY id LIMIT 2;
SELECT id,name,age FROM students WHERE age>24 ORDER BY id;
```

The first SELECT returns all three rows ordered 1, 2, 3. LIMIT 2 returns Alice and Bob. The WHERE filter returns Bob and Charlie because 25 and 30 exceed 24; Alice does not. Tests create this exact table in SQLite, assert those result sets, add an age-NULL student (excluded by age>24 because the predicate is unknown), test no-match and LIMIT 0, and include a name containing a quote inserted with bound parameters. Use parameterized values (`WHERE age>?`) in an application rather than concatenating user text. If an interviewer actually asks for an in-memory query engine, its grammar/type/null semantics must be specified separately; that is not implied by this explicit SQL deliverable.
