## Question

<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">Given transactions(transaction_id, user_id, vendor_id, transaction_time, transaction_dollars, transaction_type, refund_transaction_id) (transaction_type PURCHASE/REFUND; a REFUND&#x27;s refund_transaction_id points to the original PURCHASE) and vendors(vendor_id, city, state_province, country).

Write a SQL query to: consider only PURCHASE transactions; filter to the last 2 years; aggregate transaction_dollars by vendor_id; return the top 3 vendors by total dollars charged.

Output columns

vendor_id, total_dollars_charged

Sample tests
1.
Example output rows like 3107 | 603.18, 3997 | 600.00, 3140 | 569.00.
2.
No PURCHASE in the last 2 years =&gt; empty result.
3.
Ties in totals =&gt; still return 3 rows (order by total desc, optionally break ties by vendor_id asc).
4.
REFUND rows exist =&gt; ignore them (count only PURCHASE).
5.
transaction_dollars has 0/NULL =&gt; SUM behaves per engine defaults (NULL ignored, 0 included).</pre>

## Worked solution

1. Find the top three vendors by net charge over the last two years. Aggregate at the intended vendor grain before ranking, with refunds and time boundaries defined.
2. Filter transactions using a reproducible as-of timestamp and a half-open date interval.
3. Normalize charge/refund signs or subtract refund amounts according to the schema, then group by vendor id.
4. Sort totals descending with an explicit tie rule; use ROW_NUMBER for exactly three rows or DENSE_RANK when tied ranks should be included.

### Small example / sanity check

A vendor with charges 100 and refunds 30 has net charge 70, not gross charge 100.

### Common trap

Joining a one-to-many vendor table before aggregation and multiplying transaction totals.
