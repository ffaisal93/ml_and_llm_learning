## Question

Write an SQL query to find the winner for each auction item in an auction web service. The query must use GROUP BY and LEFT JOIN to get the highest bidder for each auction lot.

## Worked solution

### State the absent schema and tie policy

The actual tables, auction status and tie-break rule are missing. This is a **demo** using `lots(lot_id,title)` and `bids(bid_id,lot_id,bidder_id,amount)`, with nonnull nonnegative bid amounts. Return all tied highest bidders and every lot, including unbid lots with NULL winner/amount. If only closed auctions should count, add the actual closing/status condition; no such field was supplied.

```sql
-- DEMO schema: lots(lot_id,title), bids(bid_id,lot_id,bidder_id,amount).
WITH maxima AS (
 SELECT lot_id,MAX(amount) winning_amount FROM bids GROUP BY lot_id
), winners AS (
 SELECT DISTINCT b.lot_id,b.bidder_id,b.amount
 FROM bids b JOIN maxima m ON b.lot_id=m.lot_id AND b.amount=m.winning_amount
)
SELECT l.lot_id,w.bidder_id,w.amount AS winning_amount
FROM lots l LEFT JOIN winners w ON w.lot_id=l.lot_id
ORDER BY l.lot_id,w.bidder_id;
```

`GROUP BY` computes each lot's maximum, the join recovers its bidder(s), and the outer LEFT JOIN preserves lots with no bids. Use DISTINCT in winners if the same bidder can submit the same highest amount repeatedly. A deterministic one-winner rule would need time/bid-ID policy, which cannot be inferred from MAX(bidder_id). In the tested fixture, a lot with bids 10 and 15 returns the 15 bidder; a tied 15 returns both, and an empty lot remains. Index `(lot_id,amount DESC)` helps lookups; aggregation still scans relevant bids unless a maintained highest-bid record is authoritative. The unseen original schema is not claimed as executed.
