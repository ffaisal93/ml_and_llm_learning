## Question

Clean Noisy Human Labels by Scoring Annotator Reliability

A team trains a binary classifier that flags identity_attack comments: negative or hateful comments that target someone because of their identity. Each training comment was labelled by several human annotators, and some annotators are careless. Your job is to measure how reliable each annotator is and use that to clean the training labels. Then show that a classifier trained on the cleaned data beats one trained on every raw label.

### What to implement

Every row is a dict {"prompt_id": str, "rater_id": str, "embedding": list[float], "label": 0 or 1}. The train set has one row per annotation, so a prompt appears once per annotator who labelled it, always with the same embedding.
1. dataset_stats(train) -&gt; dict: return {"num_raters": int, "num_prompts": int, "label_counts": {0: int, 1: int}, "embedding_dim": int}. These are the numbers of distinct raters and prompts, the number of rows with each label (both keys always present), and the embedding length (0 for an empty train set).
2. majority_labels(train) -&gt; dict: map each prompt_id to the label given by more than half of its annotations, or None if neither label has more than half (a tie).
3. rater_agreement(train, majority) -&gt; dict: map each rater_id to the share of that rater's rows whose label equals the prompt's majority label. Skip rows whose prompt has majority None; leave out a rater with no rows left.
4. assign_pools(agreement, expert_min=0.90, decent_min=0.70) -&gt; dict: map each rater to "expert" if agreement ≥ expert_min, else "decent" if agreement ≥ decent_min, else "spammer".
5. filter_reliable(train, pools) -&gt; list[dict]: the rows whose rater is "expert" or "decent", in their original order. Raters missing from pools are dropped.
6. weighted_consensus(train, agreement) -&gt; list[dict]: one row per prompt, in order of the prompt's first appearance in train, as {"prompt_id", "rater_id": "consensus", "embedding", "label"}. Give each rater the weight max(0, 2 * agreement - 1) (0 for a rater missing from agreement). The label is 1 if the weighted share of 1-votes is above 0.5, otherwise 0. Drop a prompt whose raters all have weight 0.

None of the functions may modify its inputs.

Given in the starter (do not change them):

make_dataset(seed=0) returns (train, test, true_pool). train has 600 prompts with 5 annotations each from 22 raters; test has 400 prompts with gold labels; true_pool is every rater's hidden pool (use it only to check your work).
train_and_evaluate(train_rows, test_rows) fits a logistic regression on the rows' embeddings and labels and returns {"accuracy": float, "f1": float} on the test rows.

### Examples

Example 1. Raters A, B and C label three prompts:

prompt  A  B  C
p1      1  1  0
p2      0  0  1
p3      1  -  0
majority_labels gives {"p1": 1, "p2": 0, "p3": None}: p3 is a 1-1 tie.
rater_agreement gives {"A": 1.0, "B": 1.0, "C": 0.0}: p3 is skipped, and C disagrees on both remaining prompts.
assign_pools gives A and B "expert" and C "spammer", so filter_reliable keeps the five rows from A and B.
weighted_consensus gives labels 1, 0, 1 for p1, p2, p3. C's weight is max(0, 2 * 0 - 1) = 0, so p3 takes A's label.

Example 2. One prompt, A says 0, B and C say 1, with agreement A = 1.0, B = 0.6, C = 0.6. The weights are 1.0, 0.2 and 0.2, so the weighted share of 1-votes is 0.4 / 1.4 ≈ 0.29 and the label is 0. A plain majority vote would say 1.

Example 3. On make_dataset(0), assign_pools(rater_agreement(train, majority_labels(train))) equals true_pool. The classifier trained on all 3,000 annotations scores accuracy 0.855 and F1 0.772. Trained on filter_reliable rows it scores 0.94 and 0.881, and on weighted_consensus rows 0.94 and 0.882.

### Constraints

Up to 10^5 rows, 10^3 raters and 10^4 prompts; labels are 0 or 1.
Each function should run in O(number of rows) time, apart from building its output.
Follow-up discussion
1. Besides careless annotators, what difficulties come up with human-labelled data (for example ambiguous guidelines, systematic bias of a group of raters, class imbalance, raters who disagree in good faith)?
2. A rater's own vote is part of the majority that rater is scored against. Why does that inflate agreement, and how would you fix it?
3. The pool thresholds were picked by hand. How would you choose them, or avoid them?

## Worked solution

### Compute the requested baseline before improving it

Group annotations by prompt, find an unweighted majority, score each rater against that majority, and filter or reweight their rows. The prescribed agreement is a useful simple proxy, not an independent measurement of truth. Implement the stated rules exactly, including skipping tied prompts and dropping all-zero-weight consensus prompts.

### Complete implementation

[Download the functions and example checks](../annotations_093.py).

```python
"""W093 exact annotation-cleaning contracts."""

from collections import defaultdict
from copy import deepcopy


def dataset_stats(train):
    return dict(
        num_raters=len({r["rater_id"] for r in train}),
        num_prompts=len({r["prompt_id"] for r in train}),
        label_counts={
            label: sum(r["label"] == label for r in train) for label in (0, 1)
        },
        embedding_dim=len(train[0]["embedding"]) if train else 0,
    )


def majority_labels(train):
    counts = {}
    for row in train:
        counts.setdefault(row["prompt_id"], [0, 0])[row["label"]] += 1
    return {p: (None if c[0] == c[1] else int(c[1] > c[0])) for p, c in counts.items()}


def rater_agreement(train, majority):
    totals = defaultdict(lambda: [0, 0])
    for row in train:
        target = majority.get(row["prompt_id"])
        if target is not None:
            record = totals[row["rater_id"]]
            record[0] += int(row["label"] == target)
            record[1] += 1
    return {r: correct / total for r, (correct, total) in totals.items()}


def assign_pools(agreement, expert_min=0.90, decent_min=0.70):
    return {
        r: ("expert" if a >= expert_min else "decent" if a >= decent_min else "spammer")
        for r, a in agreement.items()
    }


def filter_reliable(train, pools):
    return [row for row in train if pools.get(row["rater_id"]) in ("expert", "decent")]


def weighted_consensus(train, agreement):
    prompts = {}
    for row in train:
        pid = row["prompt_id"]
        if pid not in prompts:
            prompts[pid] = [row, 0.0, 0.0]
        weight = max(0.0, 2 * agreement.get(row["rater_id"], 0.0) - 1)
        prompts[pid][1] += weight
        prompts[pid][2] += weight * row["label"]
    output = []
    for pid, (row, total, positive) in prompts.items():
        if total > 0:
            output.append(
                dict(
                    prompt_id=pid,
                    rater_id="consensus",
                    embedding=deepcopy(row["embedding"]),
                    label=int(positive / total > 0.5),
                )
            )
    return output


if __name__ == "__main__":
    rows = []
    for pid, votes in [
        ("p1", {"A": 1, "B": 1, "C": 0}),
        ("p2", {"A": 0, "B": 0, "C": 1}),
        ("p3", {"A": 1, "C": 0}),
    ]:
        rows.extend(
            dict(prompt_id=pid, rater_id=r, embedding=[1.0, 2.0], label=y)
            for r, y in votes.items()
        )
    saved = deepcopy(rows)
    majority = majority_labels(rows)
    agreement = rater_agreement(rows, majority)
    assert majority == dict(p1=1, p2=0, p3=None)
    assert agreement == dict(A=1.0, B=1.0, C=0.0)
    assert len(filter_reliable(rows, assign_pools(agreement))) == 5
    assert [r["label"] for r in weighted_consensus(rows, agreement)] == [1, 0, 1]
    assert rows == saved and dataset_stats([])["embedding_dim"] == 0
    assert weighted_consensus(rows, {}) == []
    print("W093 contract and non-mutation checks passed")
```

Dictionary insertion order preserves the first appearance of each prompt in consensus output. `positive/total > .5` makes an exact weighted tie label zero, as required. Missing raters receive zero weight. Filtering preserves original row order and does not mutate row dictionaries; consensus copies the embedding so its output is independent.

The first illustrated votes produce majorities `{p1:1,p2:0,p3:None}` and agreements `{A:1,B:1,C:0}`. Filtering keeps five rows. In the second example, A's weight one exceeds B/C's combined weight 0.4, so consensus is zero despite the plain majority being one. Each function is linear in annotation count, apart from copying embeddings into its output.

### Address the follow-ups

A rater's vote helps determine the reference majority, inflating agreement—most dramatically on singleton prompts. Compute a leave-one-rater-out consensus or compare with independent adjudicated gold cases. Majority agreement can still reward a systematically biased group and penalize a careful minority. Ambiguous guidelines, language expertise, class imbalance and legitimate disagreement require adjudication and task-specific analysis, not simply removing dissenters.

Tune pool thresholds on independent gold data or downstream validation, with minimum-count uncertainty intervals. A rater with two matches out of two is not as well-established as one with 200/200. Continuous reliability weights or latent-rater/confusion-matrix models avoid sharp handpicked pools but introduce modeling assumptions. Evaluate class-specific reliability because a rater who always chooses the common class can appear superficially reliable.
