## Question

Clean Noisy Human Labels by Scoring Annotator Reliability

A team trains a binary classifier that flags identity_attack comments: negative or hateful comments that target someone because of their identity. Each training comment was labelled by several human annotators, and some annotators are careless. Your job is to measure how reliable each annotator is and use that to clean the training labels. Then show that a classifier trained on the cleaned data beats one trained on every raw label.

### What to implement

Every row is a dict {"prompt_id": str, "rater_id": str, "embedding": list[float], "label": 0 or 1}. The train set has one row per annotation, so a prompt appears once per annotator who labelled it, always with the same embedding.
1. dataset_stats(train) -&gt; dict: return {"num_raters": int, "num_prompts": int, "label_counts": {0: int, 1: int}, "embedding_dim": int}. These are the numbers of distinct raters and prompts, the number of rows with each label (both keys always present), and the embedding length (0 for an empty train set).
2. majority_labels(train) -&gt; dict: map each prompt_id to the label given by more than half of its annotations, or None if neither label has more than half (a tie).
3. rater_agreement(train, majority) -&gt; dict: map each rater_id to the share of that rater's rows whose label equals the prompt's majority label. Skip rows whose prompt has majority None; leave out a rater with no rows left.
4. assign_pools(agreement, expert_min=0.90, decent_min=0.70) -&gt; dict: map each rater to "expert" if agreement ≥ expert_min, else "decent" if agreement ≥ decent_min, else "spammer".
5. filter_reliable(train, pools) -&gt; list[dict]: the rows whose rater is "expert" or "decent", in their original order. Raters missing from pools are dropped.
6. weighted_consensus(train, agreement) -&gt; list[dict]: one row per prompt, in order of the prompt's first appearance in train, as {"prompt_id", "rater_id": "consensus", "embedding", "label"}. Give each rater the weight max(0, 2 * agreement - 1) (0 for a rater missing from agreement). The label is 1 if the weighted share of 1-votes is above 0.5, otherwise 0. Drop a prompt whose raters all have weight 0.

None of the functions may modify its inputs.

Given in the starter (do not change them):

make_dataset(seed=0) returns (train, test, true_pool). train has 600 prompts with 5 annotations each from 22 raters; test has 400 prompts with gold labels; true_pool is every rater's hidden pool (use it only to check your work).
train_and_evaluate(train_rows, test_rows) fits a logistic regression on the rows' embeddings and labels and returns {"accuracy": float, "f1": float} on the test rows.

### Examples

Example 1. Raters A, B and C label three prompts:

prompt  A  B  C
p1      1  1  0
p2      0  0  1
p3      1  -  0
majority_labels gives {"p1": 1, "p2": 0, "p3": None}: p3 is a 1-1 tie.
rater_agreement gives {"A": 1.0, "B": 1.0, "C": 0.0}: p3 is skipped, and C disagrees on both remaining prompts.
assign_pools gives A and B "expert" and C "spammer", so filter_reliable keeps the five rows from A and B.
weighted_consensus gives labels 1, 0, 1 for p1, p2, p3. C's weight is max(0, 2 * 0 - 1) = 0, so p3 takes A's label.

Example 2. One prompt, A says 0, B and C say 1, with agreement A = 1.0, B = 0.6, C = 0.6. The weights are 1.0, 0.2 and 0.2, so the weighted share of 1-votes is 0.4 / 1.4 ≈ 0.29 and the label is 0. A plain majority vote would say 1.

Example 3. On make_dataset(0), assign_pools(rater_agreement(train, majority_labels(train))) equals true_pool. The classifier trained on all 3,000 annotations scores accuracy 0.855 and F1 0.772. Trained on filter_reliable rows it scores 0.94 and 0.881, and on weighted_consensus rows 0.94 and 0.882.

### Constraints

Up to 10^5 rows, 10^3 raters and 10^4 prompts; labels are 0 or 1.
Each function should run in O(number of rows) time, apart from building its output.
Follow-up discussion
1. Besides careless annotators, what difficulties come up with human-labelled data (for example ambiguous guidelines, systematic bias of a group of raters, class imbalance, raters who disagree in good faith)?
2. A rater's own vote is part of the majority that rater is scored against. Why does that inflate agreement, and how would you fix it?
3. The pool thresholds were picked by hand. How would you choose them, or avoid them?

## Worked solution

### Solution outline

Estimate which annotators agree with a provisional consensus, but recognize that the consensus itself can be biased.

1. Group annotations by prompt; form a majority label, marking ties as unresolved.
2. For each rater, measure agreement only on resolved prompts. Assign reliability tiers or continuous weights, then filter or aggregate annotations according to the specified thresholds.
3. Train identical baseline and cleaned-data models and compare on independent gold labels. Include a leave-one-rater-out consensus variant to reduce self-inclusion bias.

### Understand why the approach works

#### Establish what the number actually estimates

Write the population, unit of analysis, outcome window and denominator next to the metric. A per-user mean and a per-impression mean answer different questions. A global mean over unequal batches is

$$
\bar\ell=\frac{\sum_b\sum_{i\in b}\ell_i}{\sum_b n_b},
$$

not generally the unweighted mean of batch means. Workers should reduce numerators and denominators separately when reporting that metric.

Use a comparison with matched examples, mature labels and unchanged definitions. For uncertainty, resample independent units; repeated events within a user or prompt are not automatically independent. A confidence interval measures sampling uncertainty under assumptions, not protection against leaked data or an inappropriate target.

Calibration asks whether predictions around probability $p$ are correct about fraction $p$ of the time. It is not the same as accuracy. A reliability plot should show bin populations, and a calibration-error formula must say whether bins or examples receive equal weight.

When quality regresses, trace data availability, feature freshness, label delays and cohort mix before automatically retraining. For example, a fraud model may look worse on immature labels even when its true behavior has not changed. Report missing/time-out outputs explicitly: dropping them from the denominator can turn an unreliable system into an apparently perfect one.

### Apply this question’s exact contract

For the weighted consensus variant, use w=max(0,2*agreement-1), drop all-zero-weight prompts, predict 1 only when the weighted positive fraction is greater than 0.5, and preserve first-prompt order. Keep tie-majority prompts out of agreement denominators and leave raters with no resolved votes unscored. Never mutate input rows; compare cleaned and raw training on the independent gold test set.

### Work a small example

If A and B vote 1 and C votes 0 on two prompts, C has agreement zero with their majority; that does not prove A and B are correct.

### Edge cases and common mistakes

Evaluating on labels generated by the same consensus used for cleaning, or assuming minority annotators are necessarily careless.
