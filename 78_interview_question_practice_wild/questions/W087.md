## Question

Data Science coding task (leaf dataset, 3 classes). The original assignment is a Jupyter-notebook workflow: load train.csv (feature columns feature_0..feature_2, integer label with 3 classes), split into train/validation, implement KNN from scratch (no built-in KNN trainer), report validation accuracy, predict on test.csv, write predictions.csv preserving row order, then tune K (optionally with cross-validation).

This gradable version isolates the core algorithm — KNN classification from scratch:

Function
knn_predict(train_features, train_labels, test_features, k) -&gt; list[label]
train_features: list of numeric feature vectors.
train_labels: integer class labels aligned with train_features.
test_features: feature vectors to classify.
k: number of neighbours.

Use Euclidean distance. Return the majority label among the k nearest training points for each test row. Tie-breaking: on a voting tie, return the smallest class id.

Example

```text
train_features = [[0,0,0],[1,1,1],[2,2,2]]
train_labels   = [0, 1, 2]
test_features  = [[1,1,1]],  k = 1
```

-&gt; [1]
Notes
Do not use a built-in KNN implementation.
Euclidean distance; smallest-class-id tie-break.

## Worked solution

### Find neighbors, then vote

For each query, compute its distance to every training point, select k nearest points, then count their labels. Squared Euclidean distance preserves the same ordering as Euclidean distance, so square roots are unnecessary. The required voting tie-break is the smallest class ID. For equal-distance neighbors at the k boundary, use training-row order as an explicit deterministic convention because the prompt does not define that tie.

```python
from collections import Counter


def knn_predict(train_features, train_labels, test_features, k):
    if not train_features or len(train_features) != len(train_labels):
        raise ValueError("Training rows and labels must match")
    if not 1 <= k <= len(train_features):
        raise ValueError("k must be between one and training size")
    dimension = len(train_features[0])
    if not dimension or any(
        len(row) != dimension for row in list(train_features) + list(test_features)
    ):
        raise ValueError("All feature rows must have the same positive dimension")
    predictions = []
    for query in test_features:
        neighbors = sorted(
            range(len(train_features)),
            key=lambda i: (
                sum((a - b) ** 2 for a, b in zip(query, train_features[i])),
                i,
            ),
        )[:k]
        counts = Counter(train_labels[i] for i in neighbors)
        predictions.append(min(counts, key=lambda label: (-counts[label], label)))
    return predictions
```

The provided query `[1,1,1]` has zero distance to the row labeled one, so k=1 predicts one. If two selected neighbors vote for classes two and zero, the result is zero. Cost for Q queries and n training rows of d dimensions is $O(Q(nd+n\log n))$ using full sorting; a size-k heap reduces the selection overhead. Empty test input returns an empty list.
