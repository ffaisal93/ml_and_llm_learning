## Question

Data Science coding task (leaf dataset, 3 classes). The original assignment is a Jupyter-notebook workflow: load train.csv (feature columns feature_0..feature_2, integer label with 3 classes), split into train/validation, implement KNN from scratch (no built-in KNN trainer), report validation accuracy, predict on test.csv, write predictions.csv preserving row order, then tune K (optionally with cross-validation).

This gradable version isolates the core algorithm — KNN classification from scratch:

Function
knn_predict(train_features, train_labels, test_features, k) -&gt; list[label]
train_features: list of numeric feature vectors.
train_labels: integer class labels aligned with train_features.
test_features: feature vectors to classify.
k: number of neighbours.

Use Euclidean distance. Return the majority label among the k nearest training points for each test row. Tie-breaking: on a voting tie, return the smallest class id.

Example

```text
train_features = [[0,0,0],[1,1,1],[2,2,2]]
train_labels   = [0, 1, 2]
test_features  = [[1,1,1]],  k = 1
```

-&gt; [1]
Notes
Do not use a built-in KNN implementation.
Euclidean distance; smallest-class-id tie-break.

## Worked solution

### Solution outline

Store the training examples; for a query, predict from the labels of the nearest k examples under a chosen distance.

1. Fit feature transformations on training data only and apply the same transformation to queries.
2. Compute query-to-training squared distances, choose k neighbors, and count their labels or use defined distance weights.
3. Specify tie-breaking and k bounds. For many queries use batching or a search index; the brute-force baseline costs $O(ND)$ per query before selection overhead.

### Understand why the approach works

#### Derive a local rule, then apply the chain rule

Treat a layer as a function with a declared input and output shape. Write the scalar loss and its reduction first: a sum, mean over rows and mean over all elements produce different gradient scales. For an affine layer $Y=XW+b$ with upstream gradient $G=\partial L/\partial Y$,

$$
\frac{\partial L}{\partial X}=GW^\top,\qquad
\frac{\partial L}{\partial W}=X^\top G,\qquad
\frac{\partial L}{\partial b}=\sum_i G_{i,:}.
$$

The bias sum is over all leading positions where the same bias was reused. Do not average again if $G$ already contains the mean-loss factor. For example, with one row $x=[2,3]$ and scalar upstream derivative $4$, the weight derivative is $[8,12]$.

Cache the forward values needed by the derivative; compute all gradients before updating parameters. Updating $W$ midway would make the earlier-layer derivative use a different function from the one evaluated forward.

Check a scalar objective using central differences:

$$
\frac{\partial L}{\partial\theta_j}\approx
\frac{L(\theta+h e_j)-L(\theta-h e_j)}{2h}.
$$

Use float64 and several sensible $h$ values. An arbitrarily tiny $h$ loses the difference to rounding, while a large one measures curvature rather than a local derivative. Avoid ReLU's kink at zero during this check, and test inputs, weights and biases separately.

### Readable reference implementation

Read the explanation first, then trace one small input through these functions. This is the same implementation used by the local checks; its stated simplifications still apply.

```python
import math
from collections import deque
from dataclasses import dataclass
import numpy as np


def knn_predict(x_train, y_train, query, k):
    x_train, query = np.asarray(x_train), np.asarray(query)
    y_train = np.asarray(y_train)
    if x_train.ndim != 2 or query.shape != x_train.shape[1:] or not 1 <= k <= len(x_train):
        raise ValueError("invalid KNN shapes or k")
    if y_train.shape != (len(x_train),):
        raise ValueError("invalid label shape")
    ids = np.argsort(((x_train - query) ** 2).sum(axis=1), kind="stable")[:k]
    labels, counts = np.unique(y_train[ids], return_counts=True)
    # np.unique sorts labels; equal votes choose the smallest comparable label.
    return labels[counts.argmax()]
```

### Work a small example

Neighbors with labels [A,A,B] predict A for k=3. With k=2 and labels [A,B], a deterministic tie rule is required.

### Edge cases and common mistakes

Comparing unscaled features with incompatible units or including the test point as its own training neighbor.
