## Worked solution

### Solution outline

Union intervals before summing if overlapping activity must count only once.

1. Sort intervals by entity and start time after validating endpoints.
2. Merge when the next start is within the current covered interval under the chosen touching-interval convention.
3. Sum merged lengths, using half-open intervals for clear boundary behavior; apply window clipping if the query has a time range.

### Understand why the approach works

#### Establish row grain before writing a join

Say what one output row represents: an event, user, vendor, parent type or time interval. Then inspect the cardinality of every join. Joining two one-to-many relations can multiply rows and inflate both totals and averages; `DISTINCT` is not a general repair because legitimate equal-valued records can also exist.

For mergeable averages store a sum and count:

$$
\bar x_{\rm pooled}=\frac{\sum_g \operatorname{sum}_g}{\sum_g \operatorname{count}_g}.
$$

Do not average subgroup means unless the intended weighting gives each group equal weight. Likewise, daily distinct users cannot be added to obtain monthly distinct users.

Use half-open time windows, such as `timestamp >= start AND timestamp < end`, and name the timezone. For point-in-time training, feature **availability time** must not exceed prediction time; event occurrence and availability can differ.

Choose tie semantics deliberately: `ROW_NUMBER` produces a fixed number of rows under a deterministic secondary order, while `DENSE_RANK` preserves equal primary scores. A predicate on a nullable right-table column in `WHERE` can undo the unmatched-row preservation of a `LEFT JOIN`. Test duplicate events, absent dimension rows, nulls, tied maxima and an empty denominator. These cases explain correctness more convincingly than running only one ordinary example.

### Readable reference implementation

Read the explanation first, then trace one small input through these functions. This is the same implementation used by the local checks; its stated simplifications still apply.

```python
from collections import defaultdict
from functools import lru_cache
import math
import re
import numpy as np


def merge_intervals(intervals):
    result=[]
    for start,end in sorted(intervals):
        if start>=end:raise ValueError('interval must be nonempty')
        if result and start<=result[-1][1]:result[-1]=(result[-1][0],max(end,result[-1][1]))
        else:result.append((start,end))
    return result


def cumulative_deduped_time(rows):
    groups=defaultdict(list)
    for row in rows:
        start,end=row['start_time'],row['end_time']
        if start>end:raise ValueError('negative interval')
        if start<end:groups[row['run_id']].append((start,end))
        else:groups[row['run_id']]
    return {key:sum(end-start for start,end in merge_intervals(value)) for key,value in groups.items()}
```

### Edge cases and common mistakes

Subtracting overlaps pairwise when three or more intervals overlap, which can double-correct coverage.
