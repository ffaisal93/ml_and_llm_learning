## Worked solution

### Merge by run; compare against the maximum earlier endpoint

Treat intervals as half-open `[start,end)` so duration is end-start; touching intervals can merge without changing total. The function assumes comparable numeric times (or timestamps whose differences can be summed with an adapted zero timedelta), rejects end<start, groups only by run_id as requested and ignores other fields. Sort each run, extending the current endpoint on overlap and flushing on a gap.

```python
from collections import defaultdict

def cumulative_deduped_time(data):
    groups=defaultdict(list)
    for row in data:
        start,end=row['start_time'],row['end_time']
        if end<start:raise ValueError('end before start')
        groups[row['run_id']].append((start,end))
    output={}
    for run,intervals in groups.items():
        intervals.sort();start,end=intervals[0];total=0
        for a,b in intervals[1:]:
            if a<=end:end=max(end,b)
            else:total+=end-start;start,end=a,b
        output[run]=total+end-start
    return output
```

The SQL equivalent uses `intervals(run_id,start_time,end_time)` with numeric endpoints. For timestamp columns, return an interval sum or explicitly extract seconds after subtraction:

```sql
WITH distinct_intervals AS (
 SELECT DISTINCT run_id,start_time,end_time FROM intervals
), previous AS (
 SELECT run_id,start_time,end_time,
   MAX(end_time) OVER(PARTITION BY run_id ORDER BY start_time,end_time
      ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING) AS max_previous_end
 FROM distinct_intervals
), starts AS (
 SELECT *,CASE WHEN max_previous_end IS NULL OR start_time>max_previous_end THEN 1 ELSE 0 END AS new_group
 FROM previous
), islands AS (
 SELECT *,SUM(new_group) OVER(PARTITION BY run_id ORDER BY start_time,end_time
       ROWS UNBOUNDED PRECEDING) AS grp FROM starts
), merged AS (
 SELECT run_id,grp,MIN(start_time) lo,MAX(end_time) hi FROM islands GROUP BY run_id,grp
)
SELECT run_id,SUM(hi-lo) AS total_non_overlapping_duration FROM merged GROUP BY run_id;
```

The crucial SQL state is MAX of **all** earlier endpoints, not just LAG(end_time): for `[1,10],[2,3],[4,5]`, the third still overlaps the first even though 4>3. A cumulative sum labels islands, then MIN/MAX computes their union length. The supplied example merges to `[55,72]` and `[80,100]`, totaling 37; the other run totals 19. Tests compare SQL and Python for nested, duplicate, touching, disjoint, zero-length, multi-run and empty cases. Sorting costs O(n log n), with linear scan/state; SQL can benefit from `(run_id,start_time,end_time)` ordering but still must process all relevant intervals.
