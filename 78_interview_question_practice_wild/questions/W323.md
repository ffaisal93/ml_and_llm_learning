## Worked solution

1. Compute cumulative time after deduplicating overlapping intervals. Union intervals before summing if overlapping activity must count only once.
2. Sort intervals by entity and start time after validating endpoints.
3. Merge when the next start is within the current covered interval under the chosen touching-interval convention.
4. Sum merged lengths, using half-open intervals for clear boundary behavior; apply window clipping if the query has a time range.

### Small example / sanity check

Intervals [1,4) and [3,6) cover 5 time units together, not 6.

### Common trap

Subtracting overlaps pairwise when three or more intervals overlap, which can double-correct coverage.
