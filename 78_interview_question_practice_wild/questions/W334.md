## Question

<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">Given:

events(event_id, block_id, user_id, event_type, platform)
users(id, subscription_id, country, created_at)
subscription(id, user_id, plan_type)

Each user may have multiple subscription records.

Task
Find the event_type with the most events (ties: either pick one or return all — state your assumption).
For that event_type, compute the distribution of plan_type among the events&#x27; users, and return the most popular plan_type.

Write a SQL query to accomplish this.

Output: event_type, plan_type, event_count

Note: Since a user can have multiple subscriptions, you must define the joining logic (e.g., join via users.subscription_id, or pick a current/any subscription if no temporal fields exist).</pre>

## Worked solution

1. Find the most frequent event type and its most popular plan. Solve the two ranking stages at their own aggregation grain.
2. Count events by event type over the specified population and period, resolving ties explicitly.
3. Restrict to the chosen event type or types, then count by plan type.
4. Rank plans with a documented row or tie-preserving rule and handle null/unknown plans consistently.

### Small example / sanity check

The globally most popular plan need not be the most popular plan inside the most frequent event type.

### Common trap

Ranking plans globally and joining afterward as if conditional and marginal popularity were the same.
