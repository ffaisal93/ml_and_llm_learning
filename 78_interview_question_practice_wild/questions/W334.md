## Question

Given:

events(event_id, block_id, user_id, event_type, platform)
users(id, subscription_id, country, created_at)
subscription(id, user_id, plan_type)

Each user may have multiple subscription records.

Task
Find the event_type with the most events (ties: either pick one or return all — state your assumption).
For that event_type, compute the distribution of plan_type among the events' users, and return the most popular plan_type.

Write a SQL query to accomplish this.

Output: event_type, plan_type, event_count

Note: Since a user can have multiple subscriptions, you must define the joining logic (e.g., join via users.subscription_id, or pick a current/any subscription if no temporal fields exist).

## Worked solution

### Pick one subscription per user before counting event facts

Return all tied top event types and all tied most-popular plans within each. Use `users.subscription_id` as the authoritative current subscription, requiring subscription.id unique and matching its user_id. No temporal fields exist, so this is **current-plan attribution**, not the plan held when an event occurred. Missing/dangling subscriptions enter an UNKNOWN group instead of disappearing. Count events, not distinct people; a heavy user's repeated events carry repeated weight by this chosen interpretation.

```sql
WITH event_totals AS (
 SELECT event_type,COUNT(*) AS event_count FROM events GROUP BY event_type
), top_types AS (
 SELECT event_type FROM event_totals WHERE event_count=(SELECT MAX(event_count) FROM event_totals)
), distribution AS (
 SELECT e.event_type,COALESCE(s.plan_type,'UNKNOWN') AS plan_type,COUNT(*) AS event_count
 FROM events e JOIN top_types t ON (t.event_type=e.event_type OR (t.event_type IS NULL AND e.event_type IS NULL))
 LEFT JOIN users u ON u.id=e.user_id
 LEFT JOIN subscription s ON s.id=u.subscription_id AND s.user_id=u.id
 GROUP BY e.event_type,COALESCE(s.plan_type,'UNKNOWN')
), ranked AS (
 SELECT *,DENSE_RANK() OVER(PARTITION BY event_type ORDER BY event_count DESC) AS rnk FROM distribution
)
SELECT event_type,plan_type,event_count FROM ranked WHERE rnk=1;
```

The first CTE counts all event types before any subscription join, so a many-to-many join cannot change the winning type. The distribution then follows one users → subscription pointer, and DENSE_RANK retains tied plans. If a user has three historical subscription rows but subscription_id points to one, their two events count twice, not six times. If “distribution among users” means unique people instead, dedup `(event_type,user_id)` before counting and state that different metric. Tests use multiple subscription records, repeated events, missing plans and event/plan ties. Index user/subscription primary keys and event_type/user_id; at 1e8 events consider partial preaggregation by `(event_type,user_id)` while preserving event counts and current-versus-event-time attribution.
