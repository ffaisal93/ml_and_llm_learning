## Question

Write a single SQL query that merges CPU and memory utilization into one unified view for a cloud resource dashboard.

Result columns
resource_type - the literal CPU or Memory indicating which metric the row describes.
application_id - the application with recorded metrics.
average_usage_percentage - the average usage as a percentage, rounded to two decimal places including trailing zeros (e.g. 35.00).

### Rules

Include only metrics recorded in February 2024.
Include only applications whose average usage for that specific resource type is greater than 50%.
Sort ascending by application_id, then ascending by resource_type.
Schema (both tables share the same shape)
cpu_metrics(application_id INT, dt VARCHAR(19), usage_percentage DECIMAL(5,2))
memory_metrics(application_id INT, dt VARCHAR(19), usage_percentage DECIMAL(5,2))

## Worked solution

### Aggregate each resource independently, then format

Assume dt stores valid canonical ISO `YYYY-MM-DD HH:MM:SS` strings. Their lexical order matches timestamp order; malformed/noncanonical strings should be quarantined or migrated to a timestamp column. The half-open range includes February 29, 2024 and excludes March 1. CPU and Memory remain separate groups; averaging them together would violate the resource-specific threshold.

```sql
WITH combined AS (
 SELECT 'CPU' AS resource_type,application_id,usage_percentage
 FROM cpu_metrics WHERE dt>='2024-02-01 00:00:00' AND dt<'2024-03-01 00:00:00'
 UNION ALL
 SELECT 'Memory' AS resource_type,application_id,usage_percentage
 FROM memory_metrics WHERE dt>='2024-02-01 00:00:00' AND dt<'2024-03-01 00:00:00'
)
SELECT resource_type,application_id,
 TO_CHAR(ROUND(AVG(usage_percentage),2),'FM999990.00') AS average_usage_percentage
FROM combined GROUP BY application_id,resource_type
HAVING AVG(usage_percentage)>50
ORDER BY application_id,resource_type;
```

HAVING tests the **unrounded** average >50, then TO_CHAR produces text with exactly two decimals/trailing zeros. An average 50.004 qualifies and displays 50.00; exactly 50 does not qualify. Returning a numeric ROUND alone cannot force every client to display trailing zeros. UNION ALL preserves all facts rather than deduplicating identical readings. ORDER BY puts application first, then CPU before Memory. Tests use a portable SQLite `printf('%.2f',AVG(...))` equivalent with boundary/leap-day/50.004/two-resource fixtures; the PostgreSQL formatting syntax is reviewed, not claimed executed against a missing server. Index dt or partition by recorded time for range pruning; consider weighted averages if future samples have unequal intervals, which is not the current row-average contract.
