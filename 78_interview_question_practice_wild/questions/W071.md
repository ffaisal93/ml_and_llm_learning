## Question

eBay uses multimodal intelligence (image + text) to retrieve relevant products for a user's text query. Build a simplified image-text retrieval model training and evaluation pipeline.

What you are given
A dataset of product images (assume one image per product)
Product title/description text for each product
Query text with associated positive product IDs
Image encoder: resnet50
Text encoder: sentence-transformers/all-MiniLM-L6-v2

### What to implement

Image and text embedding models

Use resnet50 to extract image features, then a trainable projection head to map them into a shared embedding space of dimension D.
Use all-MiniLM-L6-v2 to extract text features, then a trainable projection head to map them into the same embedding space.
Apply L2 normalization to the final embeddings so cosine similarity can be used for retrieval.

A joint-embedding loss function

Implement a contrastive objective that aligns query text with its positive product (image and/or product text representation).
Must support in-batch negatives.
You may choose InfoNCE / softmax cross-entropy / triplet loss, etc., but provide a runnable implementation.

Retrieval evaluation

Given a query text, score all products by similarity (e.g., cosine similarity) and return Top-K product IDs.
Implement an offline evaluation over a set of queries, computing Top-K quality such as Recall@K.
Constraints / requirements
Use Python (PyTorch recommended).
Include a training loop (forward, loss, backprop, optimizer step).
Evaluation must be callable independently and return Top-K results.
Describe/implement how you build training batches (at minimum query-positive-product pairs).
Deliverables
Clean code structure (clear classes/functions).
A minimal runnable example (you may mock data with random tensors; the interfaces and data flow must be realistic).
Example

```text
Input:  query="red nike shoes", k=5, (products: precomputed embeddings)
Output: top_k=[103, 998, 42, 77, 501]
```

## Worked solution

### Put queries and products in the same space

A query is text; a product has an image and title/description. Their original encoder outputs have different dimensions, so train projections into a shared $D$-dimensional space. Freeze the supplied backbones for a simple first implementation, cache their outputs, and train only the projection heads. This is a genuine training pipeline, but not full backbone fine-tuning.

For product $j$, normalize each projected modality, average them, then normalize again. For query $i$, normalize its projected text vector. Their dot product is cosine similarity. With temperature $\tau$, the single-positive loss is

$$L_i=-\log\frac{\exp(q_i^\top v_i/\tau)}{\sum_j\exp(q_i^\top v_j/\tau)}.$$

Other products in the batch provide negatives. Repeated positive product IDs must not become false negatives; the implementation sums probability over all matching columns. Additional known positives outside that ID require an expanded positive mask.

### Complete PyTorch implementation

[Download and run the training/evaluation example](../multimodal_retrieval_071.py).

```python
"""W071: frozen backbone features, trainable image/text projections."""

import torch
from torch import nn
from torch.nn import functional as F


def load_backbones(device="cpu"):
    # Optional: downloads pretrained weights on first use; not needed by demo.
    from torchvision.models import resnet50, ResNet50_Weights
    from sentence_transformers import SentenceTransformer

    weights = ResNet50_Weights.IMAGENET1K_V2
    image_model = resnet50(weights=weights)
    image_model.fc = nn.Identity()
    image_model = image_model.to(device).eval().requires_grad_(False)
    text_model = SentenceTransformer(
        "sentence-transformers/all-MiniLM-L6-v2", device=device
    )
    text_model.eval().requires_grad_(False)
    return image_model, text_model, weights.transforms()


@torch.no_grad()
def extract_features(image_model, text_model, image_batch, product_texts, queries):
    # image_batch must already use the returned weights.transforms().
    image_model.eval()
    text_model.eval()
    image = image_model(image_batch)
    title = text_model.encode(product_texts, convert_to_tensor=True)
    query = text_model.encode(queries, convert_to_tensor=True)
    return image.detach(), title.detach(), query.detach()


class JointEmbedding(nn.Module):
    def __init__(self, image_dim=2048, text_dim=384, dimension=128):
        super().__init__()
        self.image_projection = nn.Linear(image_dim, dimension)
        self.text_projection = nn.Linear(text_dim, dimension)

    def queries(self, features):
        return F.normalize(self.text_projection(features), dim=-1)

    def products(self, image, text):
        image = F.normalize(self.image_projection(image), dim=-1)
        text = F.normalize(self.text_projection(text), dim=-1)
        return F.normalize((image + text) / 2, dim=-1)


def contrastive_loss(query, product, product_ids, temperature=0.1):
    if temperature <= 0:
        raise ValueError("Temperature must be positive")
    logits = query @ product.T / temperature
    # Same product may appear twice: both columns are positives, not negatives.
    positive = product_ids[:, None].eq(product_ids[None, :])
    positive_logits = logits.masked_fill(~positive, float("-inf"))
    return (
        torch.logsumexp(logits, dim=1) - torch.logsumexp(positive_logits, dim=1)
    ).mean()


def train_epoch(model, batches, optimizer):
    model.train()
    total = 0.0
    count = 0
    for query, image, text, product_ids in batches:
        optimizer.zero_grad(set_to_none=True)
        loss = contrastive_loss(
            model.queries(query), model.products(image, text), product_ids
        )
        loss.backward()
        optimizer.step()
        total += loss.item() * len(query)
        count += len(query)
    return total / count


@torch.no_grad()
def evaluate(model, query_features, images, texts, catalog_ids, positive_sets, k=5):
    if len(set(catalog_ids)) != len(catalog_ids) or not catalog_ids or k < 1:
        raise ValueError("Need unique catalog IDs and positive k")
    if len(positive_sets) != len(query_features) or any(not p for p in positive_sets):
        raise ValueError("Each query needs at least one positive ID")
    was_training = model.training
    try:
        model.eval()
        scores = model.queries(query_features) @ model.products(images, texts).T
        indices = scores.topk(min(k, len(catalog_ids)), dim=1).indices.cpu().tolist()
        top_ids = [[catalog_ids[j] for j in row] for row in indices]
        recall = sum(
            len(set(row) & set(pos)) / len(set(pos))
            for row, pos in zip(top_ids, positive_sets)
        ) / len(top_ids)
        return top_ids, recall
    finally:
        model.train(was_training)


if __name__ == "__main__":
    torch.manual_seed(7)
    torch.set_num_threads(1)
    # Random, frozen feature fixtures simulate encoder outputs, not actual images.
    n = 8
    query = torch.randn(n, 384)
    image = torch.randn(n, 2048)
    text = query.clone()
    ids = torch.arange(n)
    model = JointEmbedding(dimension=16)
    optimizer = torch.optim.Adam(model.parameters(), lr=0.01)
    batch = [(query, image, text, ids)]
    first = train_epoch(model, batch, optimizer)
    for _ in range(79):
        last = train_epoch(model, batch, optimizer)
    top, recall = evaluate(
        model, query, image, text, list(range(n)), [{i} for i in range(n)], k=1
    )
    assert last < first and recall == 1.0
    assert (
        contrastive_loss(torch.eye(2), torch.eye(2), torch.tensor([1, 1])).item() == 0
    )
    print("Fixture loss", first, "->", last, "Recall@1", recall)
```

`load_backbones` uses ResNet-50 without its classification head (2048 features) and the specified MiniLM text encoder (384 features). Apply the returned image transform to every image, concatenate each product's title and description as text, and call `extract_features`. The first pretrained run needs the optional libraries and cached/downloadable weights; the included random-feature demo is offline and does not download anything.

Build training rows as `(query, positive_product_id)`, look up that product's cached image/text features, and shuffle pairs into batches with several distinct products. Split queries/products appropriately before tuning, and keep test relevance labels out of training. During real evaluation, project the complete unique product catalog once and reuse it; the simple function recomputes it for clarity. For very large catalogs use chunked exact scoring or an ANN index and measure approximation recall separately.

### Read the output correctly

`evaluate` returns actual catalog IDs for each query plus mean Recall@K. With several relevant products, a query's recall is the fraction of its relevant IDs present in the returned set; it is not simply a binary hit. A positive ID absent from the available catalog cannot be retrieved and lowers recall under this definition.

The executable fixture overfits eight synthetic pairs and checks Recall@1 equals one, decreasing training loss and duplicate-positive handling. This validates shapes, gradients and data flow. It does not establish retrieval quality on real product images. Use held-out queries, hard negatives, category/language slices and an actual relevance set to establish that.
