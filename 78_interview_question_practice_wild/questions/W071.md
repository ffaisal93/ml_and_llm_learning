## Question

eBay uses multimodal intelligence (image + text) to retrieve relevant products for a user's text query. Build a simplified image-text retrieval model training and evaluation pipeline.

What you are given
A dataset of product images (assume one image per product)
Product title/description text for each product
Query text with associated positive product IDs
Image encoder: resnet50
Text encoder: sentence-transformers/all-MiniLM-L6-v2

### What to implement

Image and text embedding models

Use resnet50 to extract image features, then a trainable projection head to map them into a shared embedding space of dimension D.
Use all-MiniLM-L6-v2 to extract text features, then a trainable projection head to map them into the same embedding space.
Apply L2 normalization to the final embeddings so cosine similarity can be used for retrieval.

A joint-embedding loss function

Implement a contrastive objective that aligns query text with its positive product (image and/or product text representation).
Must support in-batch negatives.
You may choose InfoNCE / softmax cross-entropy / triplet loss, etc., but provide a runnable implementation.

Retrieval evaluation

Given a query text, score all products by similarity (e.g., cosine similarity) and return Top-K product IDs.
Implement an offline evaluation over a set of queries, computing Top-K quality such as Recall@K.
Constraints / requirements
Use Python (PyTorch recommended).
Include a training loop (forward, loss, backprop, optimizer step).
Evaluation must be callable independently and return Top-K results.
Describe/implement how you build training batches (at minimum query-positive-product pairs).
Deliverables
Clean code structure (clear classes/functions).
A minimal runnable example (you may mock data with random tensors; the interfaces and data flow must be realistic).
Example

```text
Input:  query="red nike shoes", k=5, (products: precomputed embeddings)
Output: top_k=[103, 998, 42, 77, 501]
```

## Worked solution

### Solution outline

#### Design image-text retrieval.

Learn or use embeddings that place matched images and text near each other, then search and rerank efficiently.

1. Build cleaned matched-pair data with duplicate and entity-aware evaluation splits.
2. Train dual encoders with an appropriate contrastive objective, then precompute catalog embeddings and build an index.
3. Evaluate recall@K, hard-negative behavior, latency and subgroup performance; use a stronger reranker if the quality gain justifies cost.

#### Implement symmetric InfoNCE loss.

A matched query/key pair should score above other examples in the batch, in both retrieval directions.

1. Normalize q and k along the embedding dimension and require temperature>0.
2. Compute logits=q@kᵀ/temperature; the correct key for query i is index i. Use stable cross-entropy across each row.
3. Average query-to-key and key-to-query cross-entropies. Keep the computation differentiable in a training implementation and define how duplicate positives are treated.

#### Choose hard negatives for a retrieval model.

Useful negatives are challenging non-matches, not mislabeled positives selected for looking similar.

1. Start with in-batch or random negatives as a baseline.
2. Mine high-scoring incorrect candidates, filter known duplicates and alternative valid answers, and control the negative mixture.
3. Evaluate on unseen queries and inspect whether the model learns real distinctions or shortcuts from mining artifacts.

### Understand why the approach works

#### Derive the diagonal contrastive targets

For matched query/key rows $(q_i,k_i)$, normalize each nonzero vector and form a batch similarity matrix

$$
S_{ij}=\frac{\tilde q_i^\top\tilde k_j}{\tau},\qquad
L_{q\to k}=-\frac1B\sum_i\log\frac{e^{S_{ii}}}{\sum_j e^{S_{ij}}}.
$$

The key-to-query loss uses $S^\top$; the symmetric objective is $(L_{q\to k}+L_{k\to q})/2$. Temperature controls logit sharpness and gradient scale. Normalizing first makes this interpretation independent of arbitrary positive embedding scale.

A batch of one has zero loss because the only key is the positive. That is a warning about absent negatives, not evidence of perfect semantic retrieval. Likewise, repeated or alternative true matches can be wrongly penalized as negatives by a diagonal-only target.

Use stable log-softmax/cross-entropy rather than manually exponentiating large scores. A NumPy implementation is a forward numerical reference; training needs the equivalent differentiable operations so gradients flow into both intended branches. A deliberately detached momentum branch is a different architecture decision, not an accidental conversion to NumPy.

Test swapping $q$ and $k$, positive row scaling, small temperature and zero-norm input policy. If negatives are gathered across workers, adjust each positive index and specify whether gradients cross that collective. More negatives can help discrimination, but label correctness and negative distribution are at least as important as the raw batch count.

### Work a small example

A text query retrieves candidate images by embedding similarity, while a pairwise reranker checks the top candidates more carefully.

### Edge cases and common mistakes

Splitting near-duplicate images across training and test or interpreting false negatives as unrelated pairs automatically.

### Check your reasoning on related cases

**Implement symmetric InfoNCE loss.** For B=1 there are no in-batch negatives and the loss is zero, which does not mean the embedding model is useful.

What changes with distributed negatives? Gather representations with the intended gradient semantics and adjust positive indices by worker offset.

**Choose hard negatives for a retrieval model.** A near-duplicate product listing may be a valid substitute rather than a true negative, depending on the task.

Why refresh mined negatives? The model's failure boundary changes during training.
