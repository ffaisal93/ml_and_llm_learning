## Question

<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">eBay uses multimodal intelligence (image + text) to retrieve relevant products for a user&#x27;s text query. Build a simplified image-text retrieval model training and evaluation pipeline.

What you are given
A dataset of product images (assume one image per product)
Product title/description text for each product
Query text with associated positive product IDs
Image encoder: resnet50
Text encoder: sentence-transformers/all-MiniLM-L6-v2
What to implement

Image and text embedding models

Use resnet50 to extract image features, then a trainable projection head to map them into a shared embedding space of dimension D.
Use all-MiniLM-L6-v2 to extract text features, then a trainable projection head to map them into the same embedding space.
Apply L2 normalization to the final embeddings so cosine similarity can be used for retrieval.

A joint-embedding loss function

Implement a contrastive objective that aligns query text with its positive product (image and/or product text representation).
Must support in-batch negatives.
You may choose InfoNCE / softmax cross-entropy / triplet loss, etc., but provide a runnable implementation.

Retrieval evaluation

Given a query text, score all products by similarity (e.g., cosine similarity) and return Top-K product IDs.
Implement an offline evaluation over a set of queries, computing Top-K quality such as Recall@K.
Constraints / requirements
Use Python (PyTorch recommended).
Include a training loop (forward, loss, backprop, optimizer step).
Evaluation must be callable independently and return Top-K results.
Describe/implement how you build training batches (at minimum query-positive-product pairs).
Deliverables
Clean code structure (clear classes/functions).
A minimal runnable example (you may mock data with random tensors; the interfaces and data flow must be realistic).
Example
Input:  query=&quot;red nike shoes&quot;, k=5, (products: precomputed embeddings)
Output: top_k=[103, 998, 42, 77, 501]</pre>

## Worked solution

1. Design image-text retrieval. Learn or use embeddings that place matched images and text near each other, then search and rerank efficiently.
2. Build cleaned matched-pair data with duplicate and entity-aware evaluation splits.
3. Train dual encoders with an appropriate contrastive objective, then precompute catalog embeddings and build an index.
4. Evaluate recall@K, hard-negative behavior, latency and subgroup performance; use a stronger reranker if the quality gain justifies cost.
5. Implement symmetric InfoNCE loss. A matched query/key pair should score above other examples in the batch, in both retrieval directions.
6. Normalize q and k along the embedding dimension and require temperature>0.
7. Compute logits=q@kᵀ/temperature; the correct key for query i is index i. Use stable cross-entropy across each row.
8. Average query-to-key and key-to-query cross-entropies. Keep the computation differentiable in a training implementation and define how duplicate positives are treated.
9. Choose hard negatives for a retrieval model. Useful negatives are challenging non-matches, not mislabeled positives selected for looking similar.
10. Start with in-batch or random negatives as a baseline.
11. Mine high-scoring incorrect candidates, filter known duplicates and alternative valid answers, and control the negative mixture.
12. Evaluate on unseen queries and inspect whether the model learns real distinctions or shortcuts from mining artifacts.

### Small example / sanity check

A text query retrieves candidate images by embedding similarity, while a pairwise reranker checks the top candidates more carefully.

### Common trap

Splitting near-duplicate images across training and test or interpreting false negatives as unrelated pairs automatically.
