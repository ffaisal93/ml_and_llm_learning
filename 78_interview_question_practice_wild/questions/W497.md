## Question

Fee Calculation with Boolean Flag and Numeric Parameter

Suppose there are only two parameters: one can be a T/F flag and the other can be any number X. Under this condition, how would you design a mechanism to calculate three different fee schedules? The fee per share increases with longevity; let's say 0.2, 0.3, 0.4. The cap is 1.5.

## Worked solution

### Two arguments are insufficient until their meanings are defined

The prompt gives three per-share rates .2/.3/.4 and cap 1.5, but omits longevity thresholds, what the boolean means, whether X is quantity or tenure, and whether the cap is per share/order/day. There is no unique fee formula. A boolean alone distinguishes two states, but the numeric input or configured policy can distinguish three or more schedules.

One explicit **demonstration contract** is: each schedule has a configured per-share rate selected from a known external longevity tier; the two runtime arguments are `(cap_enabled: bool,X: nonnegative share quantity)`. The fee is `min(rate*X,1.50)` when capped and `rate*X` otherwise, rounded to cents. A factory supplies three schedules without adding a third runtime argument:

```python
from decimal import Decimal, InvalidOperation, ROUND_HALF_UP


def make_fee_schedule(rate):
    """Configured rate; two runtime args: cap_enabled bool and quantity X."""
    rate = Decimal(str(rate))

    def fee(cap_enabled, X):
        if not isinstance(cap_enabled, bool):
            raise ValueError("boolean cap flag required")
        try:
            quantity = Decimal(str(X))
        except InvalidOperation:
            raise ValueError("numeric quantity required")
        if not quantity.is_finite() or quantity < 0:
            raise ValueError("finite nonnegative quantity required")
        total = rate * quantity
        if cap_enabled:
            total = min(total, Decimal("1.50"))
        return total.quantize(Decimal(".01"), rounding=ROUND_HALF_UP)

    return fee


fee_young, fee_middle, fee_old = (make_fee_schedule(r) for r in (".2", ".3", ".4"))
```

At X=4 with cap enabled, the three configured schedules return .80, 1.20, 1.50; with cap disabled they return .80, 1.20, 1.60. The 1.50 cap is per invocation in this demo. Tests verify those numbers, zero, invalid/nonfinite quantity and boolean validation.

This code does **not** infer tenure from quantity: selecting young/middle/old requires the missing longevity policy or preconfigured account context. If X instead means tenure, define two thresholds and return .2/.3/.4 piecewise; a total order fee still needs quantity from somewhere, and a 1.5 per-share cap never binds those three rates. If the interviewer demands a stateless two-input function where X simultaneously means an unconstrained quantity and a separate unconstrained tenure, that information is absent and cannot be recovered. State the missing contract rather than encode unexplained magic ranges or pretend one boolean selects three independent tiers.
