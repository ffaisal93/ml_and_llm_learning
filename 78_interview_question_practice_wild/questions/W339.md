## Question

<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">A Data Engineer technical screen built around SQL over an employee / project / budget schema. Two prompts:

1.
Return the names of employees who have completed a project that lasted more than 90 days.
2.
Return the average budget per employee per project. Each project has multiple employees and its budget is divided across them, so compute each employee&#x27;s share and aggregate.
Notes
Exact schema not published. Expect an employees table, a projects table (with start/end dates and a budget column), and an assignment/membership table linking employees to projects.
Duration filtering (DATEDIFF / date subtraction &gt; 90) and per-project allocation (budget / COUNT(employees)) are the core skills; no window functions strictly required.
The same round also included a Python data-manipulation task; the second technical round added a data-modeling / pipeline-design exercise.</pre>

## Worked solution

1. Calculate project duration and budget per employee. Prevent assignment joins from duplicating project-level amounts before computing employee summaries.
2. Define duration units, inclusive/exclusive endpoints and open-project treatment.
3. Aggregate assignment allocations under a documented rule: equal share, hours or explicit percentages.
4. Then summarize by employee, preserving project ids to audit double counts and overlapping periods.

### Small example / sanity check

A 1000-unit project assigned equally to four employees contributes 250 units each, not 1000 each, if allocation rather than participation totals is requested.

### Common trap

Adding full project budgets once per employee without stating that duplication is intentional.
