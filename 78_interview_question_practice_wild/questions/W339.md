## Question

A Data Engineer technical screen built around SQL over an employee / project / budget schema. Two prompts:
1. Return the names of employees who have completed a project that lasted more than 90 days.
2. Return the average budget per employee per project. Each project has multiple employees and its budget is divided across them, so compute each employee's share and aggregate.
Notes
Exact schema not published. Expect an employees table, a projects table (with start/end dates and a budget column), and an assignment/membership table linking employees to projects.
Duration filtering (DATEDIFF / date subtraction &gt; 90) and per-project allocation (budget / COUNT(employees)) are the core skills; no window functions strictly required.
The same round also included a Python data-manipulation task; the second technical round added a data-modeling / pipeline-design exercise.

## Worked solution

### Use a declared schema and allocate before averaging

The exact schema and meaning of “average per employee per project” are absent. Choose the demonstration schema shown in the SQL and interpret the second output as **each employee's mean allocated project budget** across their assigned projects. Every project's budget is divided equally among its distinct assigned employees. If the interviewer instead wants one row per employee/project, return the shares CTE directly.

```sql
-- DEMO schema employees(employee_id,name), projects(project_id,start_date,end_date,budget,status),
-- assignments(employee_id,project_id), with a unique membership pair.
SELECT e.employee_id,e.name FROM employees e WHERE EXISTS (
 SELECT 1 FROM assignments a JOIN projects p USING(project_id)
 WHERE a.employee_id=e.employee_id AND p.status='completed'
   AND p.end_date::date-p.start_date::date>90
);

WITH membership AS (
 SELECT DISTINCT employee_id,project_id FROM assignments
), sizes AS (
 SELECT project_id,COUNT(*) AS employees FROM membership GROUP BY project_id
), shares AS (
 SELECT m.employee_id,m.project_id,p.budget::numeric/s.employees AS allocated_budget
 FROM membership m JOIN projects p USING(project_id) JOIN sizes s USING(project_id)
)
SELECT employee_id,AVG(allocated_budget) AS average_budget_per_project
FROM shares GROUP BY employee_id;
```

EXISTS returns an employee once even if they completed multiple qualifying projects; completed status and end date are both checked. `end-start>90` excludes exactly 90 days; timestamps versus dates need a business day/time definition. In the second query, dedup memberships, count all project members before any employee filter, allocate with noninteger division, then average. Project P with budget 120 and three people gives each 40; an employee also assigned to project Q budget 100/two people has mean(40, 50)=45. Averaging the full project budgets would be wrong. Unassigned employees have no average here; use a LEFT JOIN to employees if NULL rows are required. Tests execute portable date/numeric equivalents, duplicate membership and threshold fixtures; no original hidden schema results are claimed.
