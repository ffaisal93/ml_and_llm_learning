## Question

<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">You may not use any third-party libraries.

Given an array x of n real numbers, implement the softmax function:

softmax(x_i) = exp(x_i) / sum(exp(x_j)), j = 0..n-1

To avoid overflow, use the equivalent form:

softmax(x_i) = exp(x_i - max(x)) / sum(exp(x_j - max(x)))

Print every softmax value rounded to 6 decimal places.

Input Format
n
x_0 x_1 ... x_{n-1}
Output Format

Print one line containing n decimal values.

Constraints
1 &lt;= n &lt;= 1000
-1000 &lt;= x_i &lt;= 1000
Example

Input:

3
1 2 3

Output:

0.090031 0.244728 0.665241</pre>

## Worked solution

1. Implement stable softmax and log-softmax. A common logit shift leaves the probability distribution unchanged, so subtract a maximum before exponentiation.
2. Convert finite logits to a floating array and choose the class axis explicitly.
3. Set z=x-max(x), then softmax=exp(z)/sum(exp(z)). Compute log-softmax directly as z-log(sum(exp(z))).
4. Test shift invariance, normalization and very large logits. Define a separate policy for negative-infinity masks rather than silently accepting an all-masked row.
5. Derive the softmax cross-entropy gradient. The fused gradient is predicted probability minus target probability.
6. Write L=-sum(y_j*logp_j), with targets summing to one.
7. Differentiate logp_j=z_j-logsumexp(z), yielding dL/dz_i=p_i-y_i.
8. Apply the chosen batch or mask reduction afterward and preserve zero gradients for excluded examples.

### Small example / sanity check

Logits [1000,1001] give the same probabilities as [0,1], approximately [0.269,0.731].

### Common trap

Computing log(softmax) when tiny probabilities may underflow to zero.
