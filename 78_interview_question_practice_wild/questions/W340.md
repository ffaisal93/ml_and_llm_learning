## Question

Given a user login log table user_login_log(user_id, login_date), write SQL (and describe the output schema) to compute:
1. Consecutive login days within any rolling 15-day window — for each user, the maximum consecutive-day streak that occurs within any rolling 15-day window.
2. Maximum consecutive login days — for each user, the longest consecutive-day streak over the entire timeline.
3. Users with at least 2 active days — count each user's distinct login days (multiple logins on the same day count once) and return users with active_days &gt;= 2.
Requirements / constraints
Deduplicate to distinct days per user before computing streaks.
A streak is consecutive if the date difference between adjacent login days is exactly 1.
Clearly define output columns (e.g. user_id, max_streak, max_streak_in_15_days, active_days).
Assume the table can have tens of millions of rows; the SQL should be executable and scalable.
Example
User A logs in on 2024-01-01, 01-02, 01-04, 01-05, 01-06
=&gt; max_streak = 3 (01-04..01-06), max_streak_in_15_days = 3, active_days = 5

## Worked solution

### Consecutive-day islands make the fifteen-day maximum simple

Deduplicate user/day first. Subtract the consecutive row number from each date: consecutive dates share the same island key, while a gap changes it. Count each island and take the user's maximum. The maximum consecutive streak that can occur within **any** rolling 15-day window is simply `min(longest_streak,15)`: no such window contains more than 15 distinct days, and any longer streak contains a 15-day sub-streak. This is different from asking for the streak metric for every rolling window endpoint.

```sql
WITH days AS (
 SELECT DISTINCT user_id,login_date::date AS day FROM user_login_log WHERE login_date IS NOT NULL
), numbered AS (
 SELECT *,day-(ROW_NUMBER() OVER(PARTITION BY user_id ORDER BY day))::int AS island
 FROM days
), streaks AS (
 SELECT user_id,island,COUNT(*) AS length FROM numbered GROUP BY user_id,island
), longest AS (
 SELECT user_id,MAX(length) AS max_streak FROM streaks GROUP BY user_id
), active AS (
 SELECT user_id,COUNT(*) AS active_days FROM days GROUP BY user_id
)
SELECT l.user_id,l.max_streak,LEAST(l.max_streak,15) AS max_streak_in_15_days,a.active_days
FROM longest l JOIN active a USING(user_id);

SELECT user_id,COUNT(DISTINCT login_date::date) AS active_days
FROM user_login_log GROUP BY user_id HAVING COUNT(DISTINCT login_date::date)>=2;
```

The first output is `(user_id,max_streak,max_streak_in_15_days,active_days)` for users with at least one login. The second separately returns `(user_id,active_days)` only when count>=2. A's dates Jan 1, 2, 4, 5, 6 give 3, 3, 5. A 20-day streak gives 20 and 15 even with many duplicate logins per day. Cast timestamps to a declared timezone's date if the source is not already a date; missing login dates should be excluded/flagged before island construction. Tests use SQLite julianday minus ROW_NUMBER equivalents for the supplied case, duplicates, a long streak and single-day users. `(user_id,login_date)` indexing/preaggregated user-day presence supports tens of millions of rows, though global sorting/aggregation still costs work.
