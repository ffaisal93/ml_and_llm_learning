## Question

<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">Given a user login log table user_login_log(user_id, login_date), write SQL (and describe the output schema) to compute:

1.
Consecutive login days within any rolling 15-day window — for each user, the maximum consecutive-day streak that occurs within any rolling 15-day window.
2.
Maximum consecutive login days — for each user, the longest consecutive-day streak over the entire timeline.
3.
Users with at least 2 active days — count each user&#x27;s distinct login days (multiple logins on the same day count once) and return users with active_days &gt;= 2.
Requirements / constraints
Deduplicate to distinct days per user before computing streaks.
A streak is consecutive if the date difference between adjacent login days is exactly 1.
Clearly define output columns (e.g. user_id, max_streak, max_streak_in_15_days, active_days).
Assume the table can have tens of millions of rows; the SQL should be executable and scalable.
Example
User A logs in on 2024-01-01, 01-02, 01-04, 01-05, 01-06
=&gt; max_streak = 3 (01-04..01-06), max_streak_in_15_days = 3, active_days = 5</pre>

## Worked solution

1. Find each user's consecutive login-day streaks. Convert repeated events into distinct user-days before detecting consecutive dates.
2. Choose timezone and deduplicate (user_id,login_date).
3. Order each user's dates and assign ROW_NUMBER; consecutive runs share a key like login_date minus row_number days.
4. Group by user and run key, then compute length and boundaries with deterministic handling of ties.

### Small example / sanity check

Days 1,2,4,5,6 contain streaks of lengths 2 and 3; multiple logins on day 5 do not lengthen either streak.

### Common trap

Applying row numbers to raw events, so duplicates shift the sequence.
