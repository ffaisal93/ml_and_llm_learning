### Frame a coaching decision before wrangling

A virtual coaching business might want to offer a reminder to clients likely to disengage. Choose the prospective target “any attended session in the next seven days,” at a weekly decision cutoff, among clients already known before that cutoff. Use historical attendance, recent session counts and recency available at the cutoff. Predictive churn risk does not identify who benefits from a reminder; that later requires randomized intervention/uplift evidence. Evaluate probability quality, recall within reminder capacity, opt-outs and eventual attendance; avoid optimizing clicks alone.

Only a placeholder file path is supplied; no real schema/file exists here. The code below therefore uses an **explicit demonstration session-event contract**, not assumed hidden columns in the original CSV. For real input first read header/types and map the required meanings. It makes one row per eligible client at one cutoff, validates identities/timestamps/labels, deduplicates event ids, separates past features from future labels and refuses immature outcomes.

```python
"""Demonstration schema ONLY: client_id, session_id, session_at, attended.
One decision at cutoff t; label=any attendance in [t,t+7d).
"""
import pandas as pd


def coaching_table(events,cutoff,observed_through):
    required={'client_id','session_id','session_at','attended'}
    if not required<=set(events):raise ValueError(f'missing columns: {required-set(events)}')
    e=events.copy()
    if e[['client_id','session_id']].isna().any().any():raise ValueError('missing identity')
    e['session_at']=pd.to_datetime(e.session_at,utc=True,errors='raise')
    if not e.attended.isin([0,1]).all():raise ValueError('attended must be 0/1')
    # Same id with conflicting payload is not silently accepted.
    if (e.groupby('session_id').nunique().max(axis=1)>1).any():raise ValueError('conflicting duplicate session')
    e=e.drop_duplicates('session_id')
    t=pd.Timestamp(cutoff);t=t.tz_localize('UTC') if t.tzinfo is None else t.tz_convert('UTC')
    observed=pd.Timestamp(observed_through);observed=observed.tz_localize('UTC') if observed.tzinfo is None else observed.tz_convert('UTC')
    if observed<t+pd.Timedelta(days=7):raise ValueError('future label window has not matured')
    # Eligibility: only clients known BEFORE the prediction cutoff.
    clients=pd.Index(e.loc[e.session_at<t,'client_id'].unique(),name='client_id')
    past=e[(e.session_at>=t-pd.Timedelta(days=28)) & (e.session_at<t)]
    features=past.groupby('client_id').agg(sessions_28d=('session_id','size'),attended_28d=('attended','sum'))
    result=features.reindex(clients,fill_value=0)
    last=past.groupby('client_id').session_at.max()
    result['days_since_session']=(t-last.reindex(clients)).dt.total_seconds()/86400
    future=e[(e.session_at>=t)&(e.session_at<t+pd.Timedelta(days=7))]
    result['return_7d']=future.groupby('client_id').attended.max().reindex(clients,fill_value=0).astype(int)
    return result.reset_index()

if __name__=='__main__':
    events=pd.DataFrame({'client_id':['a','a','b','b','new'], 'session_id':[1,2,3,4,5],
        'session_at':['2026-01-30','2026-02-03','2026-01-20','2026-02-02','2026-02-04'],
        'attended':[1,1,1,0,1]})
    out=coaching_table(events,'2026-02-01','2026-02-08')
    assert out.client_id.tolist()==['a','b'] and out.return_7d.tolist()==[1,0]
    assert out.sessions_28d.tolist()==[1,1] and out.days_since_session.tolist()==[2.,12.]
    assert coaching_table(pd.concat([events,events.iloc[:1]]),'2026-02-01','2026-02-08').equals(out)
    try:coaching_table(events,'2026-02-01','2026-02-05')
    except ValueError:pass
    else:raise AssertionError('immature labels accepted')
    print(out.to_string(index=False))
```

### Example output and production considerations

The fixture returns a with one historical session, recency 2 days and return_7d=1; b has one historical session, recency 12 days and return_7d=0. The new client first appearing after cutoff is excluded. A duplicate input event cannot double a count, and an incomplete future week cannot be labeled “did not return.” The negative label assumes complete event capture through observed_through; a logging outage invalidates it. Historical features may be missing when no recent event exists; impute only within training and preserve missingness semantics.

Use `pd.read_csv(actual_path)` only after the actual schema is mapped. For multiple cutoffs, include client/time keys, ensure outcome windows are mature, and use temporal/group validation according to deployment. Record source hashes, UTC rules, cleaning counts and feature/label versions. Minimize identifiers and coaching text, respect retention, and test feature freshness and online/offline parity.
