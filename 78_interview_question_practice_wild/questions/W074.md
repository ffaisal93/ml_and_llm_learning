## Question

Part 1: Implement a llm sampler class that consists of tokenize, detokenize, sampler function, and think of strategies to parallelize the task. This part aims to test your ability to write clear classes, and your understanding of parallel computing such as processes and threads.

Part 2: Implement a function that computes the rewards given the samples, the reward function is given as the function with string input and output integers. Find a way to calculate the mean reward and the bootstrapped 99% confidence interval.

## Worked solution

### Solution outline

1. Separate tokenize, model sampling, detokenize and reward evaluation behind explicit interfaces, with seeds and generation limits in configuration.
2. Batch model work where supported; use threads for independent I/O calls and processes only when CPU-bound work and serialization costs justify them. Preserve the association between prompt, sample, seed and reward.
3. Compute the sample mean over the stated unit. For a bootstrap 99% percentile interval, resample independent units with replacement, recompute the mean many times, and use empirical 0.5% and 99.5% quantiles.
4. If several samples share one prompt, cluster-resample prompts when inference targets variability across prompts. Report the number of prompts/samples, seed, bootstrap convention and limitations of tiny or dependent data.

### Understand why the approach works

#### Define the candidate set before sampling

Sampling has three operations: choose retained tokens, normalize their scores, and draw a vocabulary id. With temperature $\tau>0$ and retained set $S$,

$$
P(i\mid i\in S)=\frac{\exp(z_i/\tau)}{\sum_{j\in S}\exp(z_j/\tau)}.
$$

Top-$k$ defines $S$ as the $k$ largest logits. Temperature changes the distribution within that fixed set but does not change its ordering for positive $\tau$. With logits $[1,2,0.5,4]$ and $k=2$, only original ids 1 and 3 may be returned. A local index zero in the two-element candidate array is not necessarily vocabulary id zero.

For top-$p$, first sort probabilities $p_{(1)}\ge\cdots\ge p_{(V)}$ and choose

$$
k^*=\min\left\{k:\sum_{j=1}^k p_{(j)}\ge p\right\}.
$$

Include the token that crosses the threshold, then renormalize. For $[0.6,0.25,0.15]$ and threshold $0.8$, retain the first two tokens, whose mass is $0.85$. Keeping only the first would fail the requested coverage.

A readable reference sorts in $O(V\log V)$; partial selection can improve top-$k$ selection cost but needs a deliberate equal-score rule. Use an explicit random generator to reproduce experiments. Test $k=1$, $k=V$, $p=1$, very small positive $p$ and tied logits. A fixed seed does not guarantee identical sequences after a change in floating-point reduction or the number/order of random draws.

### Work a small example

Rewards [0,1,1,0] have mean 0.5. The interval depends on sample size and resampling unit; taking the mean of per-thread means can be wrong when thread sample counts differ.

### Edge cases and common mistakes

Treating generated samples from the same prompt as unrelated independent tasks without checking the inferential target.

### Check your reasoning on related cases

**Implement top-k sampling from logits.** For logits [1,2,0.5,4] and k=2, only token indices 1 and 3 can be returned.

What happens at k=1? Greedy decoding, apart from the specified handling of exact ties.

**Implement nucleus, or top-p, sampling.** For probabilities [0.6,0.25,0.15] and p=0.8, keep the first two tokens because their combined mass is 0.85.

Why does candidate count vary? A sharp distribution reaches p with fewer tokens than a flat one.

**Estimate a confidence interval for a paired model comparison.** If the same difficult examples fool both models, treating the two accuracy estimates as independent discards useful covariance information.

What if the final metric is nonlinear? Recompute that metric on each paired bootstrap sample rather than averaging inappropriate per-example surrogates.
