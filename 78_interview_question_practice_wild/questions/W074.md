## Question

Part 1: Implement a llm sampler class that consists of tokenize, detokenize, sampler function, and think of strategies to parallelize the task. This part aims to test your ability to write clear classes, and your understanding of parallel computing such as processes and threads.

Part 2: Implement a function that computes the rewards given the samples, the reward function is given as the function with string input and output integers. Find a way to calculate the mean reward and the bootstrapped 99% confidence interval.

## Worked solution

### Separate generation from reward evaluation

A sampler owns tokenization, one sequence's autoregressive loop and decoding. The tokenizer and model are injected because their actual implementations are not provided. Each next-token decision depends on the already generated prefix, so tokens **within one sequence** cannot simply be generated in parallel. Independent sequences can be.

### Runnable implementation

[Download the sampler and bootstrap routines](../sampling_074.py).

```python
"""W074: injected tokenizer/model and reproducible empirical bootstrap."""

from concurrent.futures import ThreadPoolExecutor
import numpy as np


class Sampler:
    def __init__(self, encode, decode, next_logits, eos_id):
        self.encode = encode
        self.decode = decode
        self.next_logits = next_logits
        self.eos_id = eos_id

    def tokenize(self, text):
        return list(self.encode(text))

    def detokenize(self, tokens):
        return self.decode(tokens)

    def sample(self, prompt, max_new_tokens=32, temperature=1.0, seed=0):
        if max_new_tokens < 0 or temperature <= 0:
            raise ValueError("Need nonnegative limit and positive temperature")
        rng = np.random.default_rng(seed)
        prefix = self.tokenize(prompt)
        generated = []
        for _ in range(max_new_tokens):
            logits = np.asarray(self.next_logits(prefix + generated), dtype=float)
            if logits.ndim != 1 or not len(logits) or not np.isfinite(logits).all():
                raise ValueError("Expected a finite vocabulary logit vector")
            scaled = (logits - logits.max()) / temperature
            probabilities = np.exp(scaled)
            probabilities /= probabilities.sum()
            token = int(rng.choice(len(logits), p=probabilities))
            if token == self.eos_id:
                break
            generated.append(token)
        return self.detokenize(generated)


def reward_interval(samples, reward, replicates=10000, seed=0):
    if not samples or replicates < 1:
        raise ValueError("Need samples and positive replicate count")
    values = np.asarray([reward(sample) for sample in samples], dtype=float)
    if values.ndim != 1 or not np.isfinite(values).all():
        raise ValueError("Rewards must be finite scalar values")
    rng = np.random.default_rng(seed)
    means = np.empty(replicates)
    # One replicate at a time avoids an enormous replicates × samples allocation.
    for b in range(replicates):
        means[b] = rng.choice(values, size=len(values), replace=True).mean()
    low, high = np.quantile(means, [0.005, 0.995])
    return float(values.mean()), (float(low), float(high))


def sample_many(sampler, prompts, seeds, workers=4):
    if len(prompts) != len(seeds):
        raise ValueError("One seed per sample")
    with ThreadPoolExecutor(max_workers=workers) as pool:
        return list(
            pool.map(
                lambda pair: sampler.sample(pair[0], seed=pair[1]), zip(prompts, seeds)
            )
        )
```

`next_logits(prefix)` returns one score per vocabulary token. Divide scores by temperature, normalize stably, sample one token, append it, and stop at EOS or the length limit. Each sample has its own seeded RNG; a shared mutable RNG across threads would make results depend on scheduling. The implementation decodes newly generated tokens only, excluding the prompt and EOS.

### Choose parallelism for the actual bottleneck

For remote inference, a bounded thread pool overlaps network waiting; enforce provider rate/concurrency limits and timeouts. The included `sample_many` applies only when the injected tokenizer/model adapter is thread-safe. For a local GPU, prefer batched model inference with per-sequence masks, EOS flags and independent random streams, keeping one model resident. Running one GPU model copy per Python process can exhaust memory. CPU-heavy pure-Python rewards can use processes with top-level picklable functions; vectorized NumPy or GPU rewards often benefit more from batching. Measure end-to-end throughput rather than assuming more workers always helps.

### Understand the confidence interval

For sampled strings $s_i$, compute integer rewards $r_i=f(s_i)$ and mean $\bar r=\sum_i r_i/n$. A nonparametric bootstrap repeatedly samples **n rewards with replacement**, computes each resampled mean, and takes the 0.5th and 99.5th percentiles for a nominal 99% percentile interval. The code fixes the bootstrap seed and bounds memory by storing only one resample at a time; work is $O(Bn)$ for B bootstrap replicates.

For a quick check, constant rewards of seven produce mean seven and interval `[7,7]`. Empty samples are rejected. With very small samples or rare rewards, a narrow empirical interval can be misleading because unobserved outcomes cannot appear in bootstrap resamples. More replicates reduce bootstrap Monte Carlo error, not uncertainty from too few original samples.

The ordinary bootstrap assumes samples are independent draws from the target distribution. If several completions share a prompt, report whether the target is mean completion reward or mean performance across prompts. To generalize over prompts, sample prompts as clusters (and optionally completions within each prompt), rather than treating every completion as an unrelated task. A 99% interval is a repeated-sampling procedure, not a 99% posterior probability that this one fixed interval contains the mean.
