## Question

A discussion question on equity quantitative research: validating alpha factors, then reasoning about the noise of an LLM-based signal. Answer all six parts.

### Questions

1. How do you detect whether a factor uses future (look-ahead) data?
2. How do you set Information Coefficient (IC) and IC information ratio (ICIR) thresholds for factor selection?
3. How do you train a factor model, and what is the training objective?
4. How do you prevent overfitting when many candidate factors are tested?
5. Walk through an end-to-end alpha-research workflow, from hypothesis to live monitoring.
6. Case study, LLM inference stability. An LLM labels each day's news with a sentiment class using temperature &gt; 0, so its output is non-deterministic. Day 1 gives labels y1 and day 2 gives labels y2 for the same items, with corr(y1, y2) = 0.95. Two independent aggregates are each built by averaging the labels of N independent days. State your noise model, then find the smallest integer N for which the correlation between the two N-day aggregates is at least 0.99.
Deliverable

For each part, give a concrete, defensible answer. For part 6, derive N from stated assumptions and show the arithmetic.

## Worked solution

### 1. Detect look-ahead data

Define the decision timestamp, exchange calendar, forecast horizon and realistic execution time. Every feature needs both event/effective time and **first actually available** time. Replay using point-in-time fundamentals/news releases, original revisions and a universe including delisted names; shift after-hours releases to the next tradable decision. Fit winsorization, neutralization, imputation and scaling only with information available then. Audit sample trades back to raw releases and forbid same-close execution using a close only known afterward. A promising IC that vanishes after a realistic availability lag is a leakage warning, not automatic proof of fraud.

### 2. Set IC/ICIR criteria conditionally

Define IC_t as cross-sectional Spearman correlation of factor scores with next-horizon returns (Pearson is a different chosen metric). ICIR is mean(IC_t)/sd(IC_t); annualize by sqrt(K) only under appropriate independent-period assumptions. Overlapping horizons and serial correlation require block bootstrap/HAC uncertainty and an effective sample size. There is no universal defensible threshold without horizon, costs, turnover, breadth and selection count. Predeclare a practically useful after-cost effect, confidence/robustness requirement and incremental value against existing factors, then select on training/validation only. Report signed/absolute conventions, subperiods, sectors and capacity rather than cherry-pick one favorable ICIR.

### 3. Train a stated model

For a concrete baseline, predict forward risk-adjusted returns r_i,t+h from point-in-time factor vector x_i,t using ridge regression:

$$\min_\beta\sum_{t,i}w_{i,t}(r_{i,t+h}-\beta^Tx_{i,t})^2+\lambda\|\beta\|_2^2.$$

Choose weights/neutralization to match universe/risk intent and tune λ in forward validation. A ranking loss is an alternative if only order matters. Portfolio construction then separately trades expected return against covariance risk, transaction costs, turnover and exposure limits. Low MSE alone does not establish tradable alpha.

### 4. Many factors create selection bias

Record **all** tested features/configurations, group correlated hypotheses and reserve a final untouched forward test. Use nested walk-forward selection, purge/embargo overlapping label intervals, multiplicity/FDR controls or appropriate selection-adjusted backtest analysis. Repeatedly inspecting the holdout turns it into training data. Simpler/shrunk models, economic hypotheses, stability across regimes and transaction-cost stress tests reduce—but do not eliminate—overfitting. The [original probability-of-backtest-overfitting research](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf) explains why selecting among many backtests is itself a risk; a high in-sample Sharpe is not independent evidence.

### 5. Research through live monitoring

Specify a causal/economic hypothesis and null, license/version data, build the point-in-time universe/features, evaluate a simple baseline, run controlled ablations and walk-forward tests, then simulate realistic fills/costs/latency/borrow constraints. Inspect capacity/exposures and paper/shadow trade before a limited risk-approved deployment. Pin data/code/model/LLM prompt versions and log every signal/trade decision. Monitor feature freshness, realized IC after maturity, exposures, turnover, slippage and drawdown with predeclared stop/review criteria; diagnose data or execution changes before automatically retraining. This is a research-validation design, not a claimed profitable strategy.

### 6. Derive the inference-noise averaging result

For the **same fixed set of items/latent sentiment**, assume numeric label encoding y_d=S+ε_d, Var(S)=v>0, independent zero-mean equal-variance errors Var(ε)=e, independent across runs/days and independent of S. Two independent repeated inferences have correlation v/(v+e)=0.95=19/20, so e/v=1/19. Each N-run average retains S and has error variance e/N; two independent averages have

$$\rho_N=\frac{v}{v+e/N}=\frac1{1+1/(19N)}.$$

Require ρ_N≥0.99: 1/(19N)≤1/99, so N≥99/19≈5.21053 and **smallest integer N=6**. At N=5, ρ=95/96≈0.989583<0.99; at N=6, ρ=114/115≈0.991304.

If “N independent days” means averaging **different independent latent daily signals** and each aggregate observes the same day set with independent inference errors, both signal and error variances shrink by N, so correlation remains 0.95 and no finite N reaches 0.99. Correlated errors also leave a noise floor. Thus 0.95 alone does not identify a universal N: six is conditional on the fixed-signal repeated-measurement model, which fits rerunning the same items. Sentiment class codes must have a justified numeric meaning; Pearson correlation changes with arbitrary encodings and does not establish predictive alpha.
