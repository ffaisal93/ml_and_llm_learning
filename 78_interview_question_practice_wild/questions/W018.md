## Worked solution

### PPO, reference KL and reward learning

For token ratio $r_t=\pi_\theta(a_t|s_t)/\pi_{old}(a_t|s_t)$ and detached advantage A_t, maximize $E\min(r_tA_t,\operatorname{clip}(r_t,1-\epsilon,1+\epsilon)A_t)$. Add a critic regression loss and entropy bonus with their respective minimized/maximized signs. A reference penalty $-\beta D_{KL}(\pi_\theta\|\pi_{ref})$ discourages losing useful behavior; it is separate from the rollout-policy ratio. With A=2,r=1.5,epsilon=.2 the clipped contribution is2.4 rather than3. Clipping does not strictly bound global KL.

Train a reward model on independently collected, rubric-labeled preference pairs with $-\log\sigma(R_\psi(x,y_w)-R_\psi(x,y_l))$. Split by prompt/source families, audit disagreement, balance lengths/styles and evaluate on held-out human labels/adversarial outputs. For checkable code/math, a sandboxed checker can provide a more direct outcome reward, but tests can be incomplete and need time/resource limits. Maintain separate safety and quality evaluations rather than equating reward with truth.

### GRPO versus GSPO: the actual ratio changes

GRPO generates G completions per prompt and uses $A_i=(R_i-\bar R)/(s_R+\delta)$ instead of a learned critic; outcome-reward A_i is shared across that completion's tokens. Its usual clipped surrogate averages **token** ratios $r_{it}=\exp(\log\pi_\theta(y_{it}|x,y_{i,<t})-\log\pi_{old}(y_{it}|x,y_{i,<t}))$ against A_i. Equal rewards give no centered advantage, and unreliable rewards are magnified by group normalization. See the [original GRPO formulation](https://arxiv.org/abs/2402.03300).

GSPO instead defines a length-normalized **sequence** ratio $s_i=\exp[\frac1{T_i}\sum_t(\log\pi_\theta-\log\pi_{old})]$ and maximizes $E_i\min(s_iA_i,\operatorname{clip}(s_i,1-\epsilon,1+\epsilon)A_i)$ under its declared variant. One ratio/clipping decision aligns with one sequence reward and avoids a single token's extreme ratio dominating an update. It is a geometric-mean ratio, not the raw product ratio; sequence clipping bounds and gradients differ from tokenwise clipping. The [GSPO paper](https://arxiv.org/abs/2507.18071) reports improved stability/efficiency, particularly for its MoE setup; that evidence is not a universal statement that every reasoning model prefers it. Compare matched checkpoints, rollouts, budgets and independent outcomes.

### Diagnose reward hacking and tune control

Failure examples include verbose rubric mimicry, repeating rewarded phrases, gaming a weak math parser, insecure code that passes visible tests, and judge-specific styles. Defenses are high-quality/held-out rewards, multiple checks, randomized hidden cases, human audits of high-reward samples, explicit length/cost treatment and frozen regression/safety sets. Monitor reward against external accuracy/human preference, length, entropy, refusal and mode collapse. Stronger optimization can increase the reward–quality gap.

Too-small beta allows rapid drift; too-large beta can prevent learning. Set a target KL range on a validation pilot, track empirical KL and clipping fraction, adapt beta conservatively or stop/reduce update steps when drift spikes. Reward scaling changes the relative effective KL weight, so log both. A reward poisoned by bias is not repaired merely by more KL.

### System topology and choice

Rollouts can dominate compute because autoregressive generation is serial across tokens and several answers/prompt multiply KV memory. Run tensor-parallel inference actors within fast-link groups, data-parallel rollout replicas for prompts, and FSDP/tensor/pipeline-parallel trainers for updates; colocate/freeze reference/reward where memory permits and batch their scoring. Pin actor weight version and store behavior log probabilities/rewards/masks with every rollout. Refresh weights atomically; too-stale queued rollouts are off-policy, and clipped ratios do not excuse unlimited staleness. Bound lag, discard/resample or use an explicitly justified off-policy correction.

Use PPO when multi-step credit assignment and a useful critic justify its cost; use GRPO for reliable group-comparable verifiable rewards; pilot GSPO when sequence-reward alignment/ratio instability is the bottleneck. Critic-free saves critic memory but not reward reliability or rollout expense. Track end-to-end useful-token throughput, cost per externally correct task, synchronization/checkpoint overhead and evaluator failures, not training loss alone.
