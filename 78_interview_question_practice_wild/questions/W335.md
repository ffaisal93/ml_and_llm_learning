## Question

<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">Given:

blocks(workspace_id, block_id, parent_id, block_type)
events(event_id, block_id, user_id, event_type, platform)

where events.block_id = blocks.block_id.

Definition: a block is &quot;never edited&quot; if its block_id has never appeared in any edit-type event (if the exact edit event type is known, filter by it, e.g. event_type = &#x27;edit_text&#x27;).

Write a SQL query to compute the percentage of blocks that have never been edited.

Output: never_edited_percentage (a number between 0 and 100).

Note: A block can have many events.

Example

Input: blocks: 4 blocks; edit events hit 1 block

Output: 75.0</pre>

## Worked solution

1. Use one output contribution per block, with NOT EXISTS to test the presence of an edit event rather than joining every event row.
2. Filter only the defined edit event type and divide the never-edited count by the total number of blocks. Use floating arithmetic and an explicit empty-table policy; this example returns zero for no blocks.
3. Assume block_id is globally unique in the event relation as supplied. If ids are workspace-local, the event schema must include workspace_id and the predicate must join both keys.

### Reference query

```sql
SELECT COALESCE(100.0 * SUM(CASE WHEN NOT EXISTS (
  SELECT 1 FROM events e
  WHERE e.block_id=b.block_id AND e.event_type='edit_text'
) THEN 1 ELSE 0 END) / NULLIF(COUNT(*),0),0) AS never_edited_percentage
FROM blocks b;
```

### Small example / sanity check

Four blocks with edits on exactly one produce 75%, regardless of how many edit events that one block has.

### Common trap

Using COUNT of joined event rows as the denominator.
