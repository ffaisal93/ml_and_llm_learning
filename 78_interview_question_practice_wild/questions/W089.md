## Question

<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">You are given a tabular dataset for a binary classification task, loaded into a pandas DataFrame df with a label column target. The data is deliberately messy: some numeric columns have missing values, some categorical columns spell the same category in several ways (for example &quot;NY&quot;, &quot;ny &quot;, &quot;New York&quot;), one column mixes numbers and strings, and an identifier column is present. Build a clean, working baseline classifier end to end and explain your choices.

What to deliver
1.
Profile the data. Inspect types, missing-value counts, cardinality of each categorical column and the class balance of target. State which columns you will drop, which you will fix and why (including any column that must not be a feature).
2.
Clean the data. Handle missing values by column type, normalise inconsistent category spellings, and coerce the mixed-type column to a single type. Say what you do with values that cannot be converted.
3.
Split before transforming. Create a train/test split first (stratified when the classes are imbalanced), and fit every imputer, encoder and scaler on the training part only.
4.
Train the simplest sufficient model. Use a model such as logistic regression or a shallow decision tree on a small, justified set of features. Explain why you did not start with a larger ensemble or a grid search.
5.
Evaluate on the held-out set. Report accuracy, a confusion matrix and precision and recall for the minority class. Say which number you would lead with and why accuracy alone can mislead.
6.
Justify and extend. Explain what each pitfall would have cost (leakage, an ID column used as a feature, mean-imputing a categorical column), and what you would add next for a setting where interpretability and monitoring matter.
Constraints
Use pandas and scikit-learn only; the whole pipeline should run top to bottom on the dataset.
Report numbers from the held-out split, never from the training data.</pre>

## Worked solution

1. Fit a baseline on messy tabular data without leakage. Build a trustworthy split and simple baseline before sophisticated feature engineering.
2. Define the target, prediction time and unit of independence, then split by time or group if required.
3. Fit imputation, scaling and category encodings on training folds only. Start with a dummy baseline and a regularized linear or small tree model.
4. Evaluate slices, missingness patterns and calibration; document features unavailable at decision time and remove them.
5. How should you split data for reliable model selection? The validation procedure must imitate which information will be available when the model is used.
6. Use a final held-out test set and tune only within training/validation data.
7. Use grouped splits for repeated entities and forward-looking splits for time-dependent prediction. Stratification preserves class proportions when compatible with those constraints.
8. Fit the complete preprocessing and model pipeline inside each fold; reserve nested validation for unbiased evaluation of an extensive selection procedure.
9. Why can high accuracy hide failure on imbalanced data? A model can achieve high accuracy by predicting the common class while missing nearly all important rare events.
10. Inspect class prevalence, the confusion matrix and per-class precision/recall.
11. Choose a metric connected to the decision: PR behavior for rare-event retrieval, calibration for probability-based decisions, and explicit cost curves for thresholds.
12. Try class weights, resampling or focal loss carefully, validating on the natural deployment distribution and recalibrating when needed.

### Small example / sanity check

A “refund issued” field may predict churn extremely well but be recorded after the churn decision, making it unusable for a prospective model.

### Common trap

Fitting preprocessing on all rows before cross-validation, even when labels were not directly used.
