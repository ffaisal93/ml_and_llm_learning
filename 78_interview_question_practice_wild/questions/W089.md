## Question

You are given a tabular dataset for a binary classification task, loaded into a pandas DataFrame df with a label column target. The data is deliberately messy: some numeric columns have missing values, some categorical columns spell the same category in several ways (for example "NY", "ny ", "New York"), one column mixes numbers and strings, and an identifier column is present. Build a clean, working baseline classifier end to end and explain your choices.

What to deliver
1. Profile the data. Inspect types, missing-value counts, cardinality of each categorical column and the class balance of target. State which columns you will drop, which you will fix and why (including any column that must not be a feature).
2. Clean the data. Handle missing values by column type, normalise inconsistent category spellings, and coerce the mixed-type column to a single type. Say what you do with values that cannot be converted.
3. Split before transforming. Create a train/test split first (stratified when the classes are imbalanced), and fit every imputer, encoder and scaler on the training part only.
4. Train the simplest sufficient model. Use a model such as logistic regression or a shallow decision tree on a small, justified set of features. Explain why you did not start with a larger ensemble or a grid search.
5. Evaluate on the held-out set. Report accuracy, a confusion matrix and precision and recall for the minority class. Say which number you would lead with and why accuracy alone can mislead.
6. Justify and extend. Explain what each pitfall would have cost (leakage, an ID column used as a feature, mean-imputing a categorical column), and what you would add next for a setting where interpretability and monitoring matter.

### Constraints

Use pandas and scikit-learn only; the whole pipeline should run top to bottom on the dataset.
Report numbers from the held-out split, never from the training data.

## Worked solution

### Profile first, then freeze an honest evaluation

Inspect column types, missingness, category cardinality, duplicate IDs and target prevalence. Drop the target from features, keep the identifier only for joining/output, and investigate any feature produced after the outcome. Do not assume every integer column is a meaningful numerical predictor. A high-cardinality identifier can memorize rows while looking predictive.

The real DataFrame/schema is not included, so the runnable function accepts explicit feature lists and column names. It returns profile information, the fitted pipeline and metrics computed only on the held-out split. Deterministic normalization rules use domain knowledge; learned imputers, category vocabularies and scaling fit only on training rows.

### Complete pandas/scikit-learn pipeline

```python
"""W089: deterministic cleaning + train-only learned preprocessing."""

import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import OneHotEncoder, StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import (
    accuracy_score,
    confusion_matrix,
    precision_recall_fscore_support,
)


def baseline(df, numeric, categorical, mixed_column, identifier, aliases=None):
    features = list(numeric) + list(categorical)
    if (
        len(set(features)) != len(features)
        or "target" in features
        or identifier in features
    ):
        raise ValueError("Features must be unique and exclude target/ID")
    if mixed_column not in numeric:
        raise ValueError("Mixed column must be declared numeric")
    if df["target"].isna().any() or set(df["target"].unique()) != {0, 1}:
        raise ValueError("Need nonmissing binary target with both classes")
    profile = {
        "types": df.dtypes.astype(str).to_dict(),
        "missing": df.isna().sum().to_dict(),
        "categorical_cardinality": df[categorical].nunique(dropna=False).to_dict(),
        "target_counts": df["target"].value_counts().to_dict(),
    }
    X_train, X_test, y_train, y_test = train_test_split(
        df[features],
        df["target"],
        test_size=0.25,
        random_state=7,
        stratify=df["target"],
    )

    def clean(frame):
        frame = frame.copy()
        frame[mixed_column] = pd.to_numeric(frame[mixed_column], errors="coerce")
        for col in categorical:
            values = frame[col].astype("string").str.strip().str.casefold()
            values = values.replace((aliases or {}).get(col, {}))
            # Use ordinary object values and None for consistent sklearn missing handling.
            frame[col] = values.astype(object).where(values.notna(), None)
        return frame

    numeric_pipe = Pipeline(
        [
            ("impute", SimpleImputer(strategy="median", add_indicator=True)),
            ("scale", StandardScaler()),
        ]
    )
    category_pipe = Pipeline(
        [
            ("impute", SimpleImputer(strategy="most_frequent", missing_values=None)),
            ("onehot", OneHotEncoder(handle_unknown="ignore")),
        ]
    )
    prep = ColumnTransformer(
        [("numeric", numeric_pipe, numeric), ("category", category_pipe, categorical)]
    )
    model = Pipeline(
        [("preprocess", prep), ("classifier", LogisticRegression(max_iter=1000))]
    )
    model.fit(clean(X_train), y_train)
    predicted = model.predict(clean(X_test))
    minority = int(y_train.value_counts().idxmin())
    precision, recall, _, _ = precision_recall_fscore_support(
        y_test, predicted, labels=[minority], average=None, zero_division=0
    )
    metrics = {
        "accuracy": float(accuracy_score(y_test, predicted)),
        "confusion_matrix_labels": [0, 1],
        "confusion_matrix": confusion_matrix(y_test, predicted, labels=[0, 1]).tolist(),
        "minority_label": minority,
        "minority_precision": float(precision[0]),
        "minority_recall": float(recall[0]),
        "test_rows": len(y_test),
    }
    return model, profile, metrics, clean


if __name__ == "__main__":
    # A declared fixture, not the unavailable interview dataset.
    rows = []
    for i in range(80):
        rows.append(
            dict(
                id=i,
                income=None if i % 9 == 0 else i,
                balance="bad" if i % 13 == 0 else str(i % 17),
                city=["NY", "ny ", "New York", None][i % 4],
                target=int(i % 5 == 0),
            )
        )
    data = pd.DataFrame(rows)
    model, profile, metrics, clean = baseline(
        data,
        ["income", "balance"],
        ["city"],
        "balance",
        "id",
        aliases={"city": {"ny": "new york"}},
    )
    assert metrics["test_rows"] == 20 and "id" not in model.feature_names_in_
    assert (
        clean(pd.DataFrame({"income": [1], "balance": ["bad"], "city": [" NY "]}))[
            "city"
        ][0]
        == "new york"
    )
    print("Synthetic held-out metrics:", metrics)
```

For the real data, supply its numeric columns, categorical columns, mixed numeric/string column and identifier name. For a city column, `aliases={'city': {'ny': 'new york'}}` unifies the three illustrated spellings after stripping/case folding. Alias mappings should be curated, not inferred from held-out target outcomes. Mixed values that cannot be parsed become missing and receive the training median plus an indicator. Categorical missing values receive a learned common category; use an explicit missing category instead if missingness has meaningful semantics.

### Explain the baseline and its limits

Logistic regression provides a quick, interpretable reference and exposes data problems before expensive ensemble tuning. One-hot encoding avoids inventing order among categories. Scaling makes numerical coefficients/regularization more comparable. `handle_unknown='ignore'` allows a new test category without fitting a new vocabulary. Never mean-impute city strings or scale the target.

The included 80-row synthetic fixture produces a 20-row held-out confusion matrix `[[16,0],[4,0]]`, accuracy 0.8 and minority precision/recall both zero. That is a useful failure: predicting every row as the majority class gives a superficially good accuracy while missing every minority example. These are fixture results, not metrics for the unavailable dataset. Lead with minority recall/precision and business error cost rather than accuracy alone.

Use grouped or chronological splits instead of a random split if rows share entities or represent future predictions. Choose thresholds and any class weighting on a separate validation set/cross-validation, leaving test data untouched. Next add calibration, coefficient stability checks, a documented feature schema and monitors for unknown categories, parsing failures, missingness, class/score drift and delayed-label quality. All-missing columns require an explicit drop/default policy; the small sample assumes usable observations remain for each declared feature.
