## Question

Fill in the TODOs of a tiny PyTorch skeleton so a feed-forward (no recurrence, no attention) model trains for next-token prediction conditioned only on the current token.
1. DataLoader — wrap SyntheticDataset(num_samples, seq_len, vocab_size) with DataLoader(dataset, batch_size=32, shuffle=True).
2. Model — Embedding(vocab_size, hidden_dim) → Linear(hidden_dim, hidden_dim) → ReLU → Linear(hidden_dim, vocab_size).
3. forward(x) — return logits of shape (batch, seq_len, vocab_size).
4. Input/target prep — given sequences (batch, seq_len), set inputs = sequences[:, :-1], targets = sequences[:, 1:]; flatten so cross-entropy sees (batch·(seq_len-1), vocab_size) and (batch·(seq_len-1),).
5. Training loop — forward, cross-entropy, backward, optimizer step (Adam is fine).

Hidden tests check that loss strictly decreases on a fixed seed and that the input/target shift is correct.

## Worked solution

### 1. What are we actually building?

For every input token, predict the token immediately after it. This exercise deliberately uses **only the current token**. It does not ask for a Transformer, attention, a recurrent network or a causal mask.

For the sequence `[2, 3, 4, 0]`, the training pairs are:

| Current token | Next-token target |
|---|---|
| 2 | 3 |
| 3 | 4 |
| 4 | 0 |

Feed `[2, 3, 4]` and supervise `[3, 4, 0]`. The model estimates $p(x_{t+1}\mid x_t)$, not a distribution conditioned on the whole prefix. The same current token always produces the same logits under fixed weights, regardless of its neighboring tokens.

### 2. The exact model implementation

`nn.Embedding` turns an integer token id into a trainable feature vector. The first linear layer and ReLU transform that vector; the final linear layer produces one raw score per vocabulary token.

```text
integer tokens (B, L)
    → embedding (B, L, H)
    → hidden linear + ReLU (B, L, H)
    → vocabulary linear (B, L, V)
```

Use these imports for the code below:

```python
import torch
from torch import nn
from torch.nn import functional as F
from torch.utils.data import Dataset, DataLoader
```

```python
class TinyNextTokenModel(nn.Module):
    def __init__(self, vocab_size, hidden_dim):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, hidden_dim)
        self.hidden = nn.Linear(hidden_dim, hidden_dim)
        self.output = nn.Linear(hidden_dim, vocab_size)

    def forward(self, token_ids):
        embeddings = self.embedding(token_ids)  # (B, L, H)
        hidden_states = torch.relu(self.hidden(embeddings))
        return self.output(hidden_states)
```

For one position, the computation is

$$
e_t=E[x_t],\qquad h_t=\operatorname{ReLU}(W_1e_t+b_1),\qquad
z_t=W_2h_t+b_2.
$$

There is no operation combining different positions. `nn.Linear` transforms the final dimension and leaves batch and sequence dimensions intact. Consequently, a full input of shape `(B, T)` produces `(B, T, V)`; the shifted training input has length `T-1` and produces `(B, T-1, V)`.

### 3. Shift once, then calculate the actual loss

```python
def next_token_loss(model, sequences):
    if sequences.ndim != 2 or sequences.size(1) < 2:
        raise ValueError("sequences must have shape (batch, length >= 2)")
    inputs = sequences[:, :-1]
    targets = sequences[:, 1:]
    logits = model(inputs)
    vocabulary_size = logits.size(-1)
    return F.cross_entropy(
        logits.reshape(-1, vocabulary_size),
        targets.reshape(-1),
    )
```

The first slice removes the last input token. The second removes the first target token. Flattening preserves the pair order:

```text
inputs:  [[2, 3, 4], [0, 1, 2]]
targets: [[3, 4, 0], [1, 2, 3]]

logits.reshape(-1, V): 6 rows, each containing V class scores
targets.reshape(-1):  [3, 4, 0, 1, 2, 3]
```

Use `reshape` because sliced tensors can be noncontiguous. Pass raw logits directly to `F.cross_entropy`; it already computes the needed log-probabilities. Labels are integer class ids, not one-hot vectors.

With batch size $B$ and original sequence length $T$, the loss is

$$
\mathcal L=-\frac{1}{B(T-1)}\sum_{b=1}^{B}\sum_{t=0}^{T-2}
\log\operatorname{softmax}(z_{b,t})_{x_{b,t+1}}.
$$

A causal mask is unnecessary: this architecture cannot read any other position in the first place.

### 4. DataLoader and the completed training loop

When the interview skeleton supplies `SyntheticDataset`, retain that implementation and construct the loader exactly as requested:

```python
# Run after the supplied SyntheticDataset class has been defined.
dataset = SyntheticDataset(num_samples=256, seq_len=9, vocab_size=8)
loader = DataLoader(dataset, batch_size=32, shuffle=True)
```

Each batch must be a tensor of integer sequences shaped `(B, T)`. If a different provided dataset returns a tuple, unpack it according to that actual contract rather than guessing. The training function performs all five required operations in order:

```python
def train_one_epoch(model, loader, optimizer, device="cpu"):
    model.train()
    total_loss = 0.0
    total_targets = 0
    for sequences in loader:
        sequences = sequences.to(device)
        optimizer.zero_grad(set_to_none=True)
        loss = next_token_loss(model, sequences)
        loss.backward()
        optimizer.step()

        count = sequences.size(0) * (sequences.size(1) - 1)
        total_loss += loss.item() * count
        total_targets += count
    if total_targets == 0:
        raise ValueError("loader contains no target tokens")
    return total_loss / total_targets
```

`zero_grad` clears gradients from the previous minibatch, `backward` computes new ones, and `step` updates the registered parameters. `model.train()` selects training mode. On a GPU, move the model to the same device passed to this function; the batch is moved inside the loop.

### 5. A complete, reproducible demonstration

**The exercise does not include its `SyntheticDataset` implementation.** The following is a clearly chosen demonstration fixture, not a reconstruction of hidden data. Its rule is `next = (current + 1) % vocab_size`, which this current-token-only architecture can learn. If the supplied data has independent random next tokens, there is no such predictable rule; its population optimum is the next-token marginal, uniform loss $\log V$ when that marginal is uniform.

Define this fixture **before** constructing its DataLoader if you run the examples outside the original skeleton:

```python
class SyntheticDataset(Dataset):
    def __init__(self, num_samples, seq_len, vocab_size, seed=0):
        if num_samples < 1 or seq_len < 2 or vocab_size < 2:
            raise ValueError("need samples > 0, sequence length >= 2 and vocabulary >= 2")
        random = torch.Generator().manual_seed(seed)
        starts = torch.randint(vocab_size, (num_samples, 1), generator=random)
        offsets = torch.arange(seq_len).unsqueeze(0)
        # Demonstration rule: after token k comes (k + 1) modulo vocab_size.
        self.sequences = (starts + offsets) % vocab_size

    def __len__(self):
        return len(self.sequences)

    def __getitem__(self, index):
        return self.sequences[index]
```

Compare checkpoints on the same complete dataset, weighting by target count so a short last batch does not receive the same weight as a full batch:

```python
def evaluate_loss(model, loader, device="cpu"):
    was_training = model.training
    model.eval()
    total_loss = 0.0
    total_targets = 0
    with torch.no_grad():
        for sequences in loader:
            sequences = sequences.to(device)
            count = sequences.size(0) * (sequences.size(1) - 1)
            total_loss += next_token_loss(model, sequences).item() * count
            total_targets += count
    model.train(was_training)
    if total_targets == 0:
        raise ValueError("loader contains no target tokens")
    return total_loss / total_targets


def run_demo(seed=7, epochs=6):
    torch.manual_seed(seed)
    vocabulary_size = 8
    dataset = SyntheticDataset(num_samples=256, seq_len=9,
                               vocab_size=vocabulary_size, seed=seed)
    loader = DataLoader(dataset, batch_size=32, shuffle=True,
                        generator=torch.Generator().manual_seed(seed))
    evaluation_loader = DataLoader(dataset, batch_size=32, shuffle=False)
    model = TinyNextTokenModel(vocabulary_size, hidden_dim=32)
    optimizer = torch.optim.Adam(model.parameters(), lr=0.02)
    history = [evaluate_loss(model, evaluation_loader)]
    for _ in range(epochs):
        train_one_epoch(model, loader, optimizer)
        history.append(evaluate_loss(model, evaluation_loader))
    return model, history
```

```python
model, losses = run_demo(seed=7, epochs=6)
print([round(loss, 6) for loss in losses])
# One tested CPU run:
# [2.177346, 0.043959, 0.000115, 0.000011, 0.000004, 0.000003, 0.000002]

with torch.no_grad():
    predictions = model(torch.arange(8).unsqueeze(0)).argmax(dim=-1)
print(predictions.squeeze(0).tolist())  # [1, 2, 3, 4, 5, 6, 7, 0]
assert losses[-1] < losses[0]
```

Small numerical differences can occur across versions and devices. The important checks are that the final loss decreases on this fixed learnable fixture, the shape and shift are correct, and the model learns the stated transition. Minibatch SGD is not guaranteed to improve on every individual update; comparing unrelated minibatch losses is not a reliable correctness test.
