## Question

A language model generates text one token at a time. Greedy decoding always takes the single most likely next token, which can miss a sequence that is more likely overall. Beam search keeps the beam_width best partial sequences at every step instead of one. Implement beam search over a given language model.

### What to implement

```text
def beam_search(
```

lm_predict: Callable[[List[int]], np.ndarray],
start_token: int,
beam_width: int,
num_steps: int,
vocab_size: int,
) -&gt; List[Tuple[List[int], float]]:
lm_predict(tokens): given the token ids decoded so far, returns a NumPy array of shape (vocab_size,) with the probability of each next token (token ids 0 .. vocab_size - 1). It is deterministic.
start_token: the token every sequence begins with.
beam_width: how many sequences to keep after each step.
num_steps: how many tokens to append after the start token.
vocab_size: the number of token ids.
Returns a list of (sequence, score) pairs, best first.

### Rules

1. Every sequence starts with start_token; each step appends exactly one token, so every returned sequence has length num_steps + 1.
2. The score of a sequence is the sum of the natural logs of the probabilities of its appended tokens, accumulated step by step in float64: new_score = old_score + log(p). The start token adds nothing. Use the exact log with no smoothing; a probability of 0 gives a score of -inf, and that sequence is still a valid candidate.
3. At each step, extend every kept sequence by every token id, then keep the beam_width best candidates (all of them if there are fewer).

```text
4. "Best" means the higher score. Candidates with exactly equal scores are ordered by their sequence, lexicographically smaller first.
```

5. The returned list follows the same order. If num_steps is 0 the result is [([start_token], 0.0)].
6. Call lm_predict with the full sequence so far, start token included, and give it a fresh list each time (it may modify the list it receives).
7. Raise ValueError if beam_width &lt; 1, num_steps &lt; 0 or vocab_size &lt; 1.

You may use NumPy and the Python standard library.

-&gt; [([0, 1, 2], -0.9039702474861145),

Explanation: after step 1 the beams are [0, 1] (score log(7/11)) and [0, 0], which wins the four-way tie at log(1/11) because it is lexicographically smallest. At step 2, [0, 1, 2] scores 2·log(7/11). Five candidates tie at log(7/11) + log(1/11), among them [0, 0, 1] and [0, 1, 0]; the smallest, [0, 0, 1], is kept.

## Worked solution

### Solution outline

Beam search keeps several strong partial sequences; it is a search procedure rather than a random sampler.

1. Store each beam's tokens and sum of token log probabilities. Expand only unfinished beams.
2. Combine candidate expansions and retain the best beam_width sequences under the chosen ranking rule; keep finished hypotheses separately or carry them without further tokens.
3. Stop when the chosen stopping criterion is satisfied, and state whether length normalization is used. A minimal reference implementation is in the coding lab.

### Understand why the approach works

#### Track complete hypothesis state

A beam consists of token ids, accumulated log probability and completion status. Its raw score is

$$
s(y_{1:t})=\sum_{j=1}^t\log P(y_j\mid x,y_{<j}).
$$

Expand only unfinished hypotheses. Combine their continuations, compare them under the declared score and retain at most the beam width. A finished hypothesis must not acquire arbitrary tokens after EOS; it can be carried unchanged or stored in a separate completed set under a compatible stopping rule.

Multiplying probabilities directly underflows for long sequences; sums of logs avoid this problem. Raw likelihood often favors shorter completions because each added log probability is nonpositive. Length penalties change the ranking and stopping logic, so specify their formula rather than quietly dividing scores by length.

For example, two tokens with conditional probabilities $0.5$ and $0.5$ have joint probability $0.25$ and log score $\log0.25\approx-1.3863$. Their average probability is not a valid sequence likelihood. A width-one beam behaves like greedy search under the same constraints; a finite wider beam still is not exhaustive maximum-probability search.

Use a tiny callback model with known probabilities, enumerate its short possible completions, and compare behavior. Test immediate EOS, no EOS within the limit, equal scores and a prefix that initially looks weaker but later produces a stronger completion. This last case illustrates why pruning is approximate and why a larger beam is not a universal guarantee of better subjective answers.

### Readable reference implementation

Read the explanation first, then trace one small input through these functions. This is the same implementation used by the local checks; its stated simplifications still apply.

```python
import math
from collections import deque
from dataclasses import dataclass
import numpy as np


def beam_search(next_log_probs, start, eos, beam_width, max_new_tokens):
    """No length normalization. Callback returns a finite 1D log-probability array.

    Finished hypotheses remain in the beam with unchanged scores. This is a
    readable baseline; width pruning is approximate search, not exhaustive MAP.
    """
    if beam_width < 1 or max_new_tokens < 0:
        raise ValueError("invalid search limits")
    beams = [(tuple(start), 0.0, False)]
    for _ in range(max_new_tokens):
        candidates = []
        for tokens, score, done in beams:
            if done:
                candidates.append((tokens, score, True))
                continue
            lp = np.asarray(next_log_probs(tokens), dtype=float)
            if lp.ndim != 1 or not len(lp) or not np.isfinite(lp).all():
                raise ValueError("callback must return finite log probabilities")
            for token in np.argsort(-lp, kind="stable")[:beam_width]:
                candidates.append((tokens + (int(token),), score + float(lp[token]), token == eos))
        beams = sorted(candidates, key=lambda x: (-x[1], x[0]))[:beam_width]
        if all(done for _, _, done in beams):
            break
    best = max(beams, key=lambda x: x[1])
    return list(best[0]), best[1]
```

### Work a small example

A sequence with token probabilities 0.5 and 0.5 has probability 0.25 and log score log(0.25), not the average probability 0.5.

### Edge cases and common mistakes

Multiplying many probabilities, appending tokens after EOS, or assuming a wider beam always improves subjective quality.
