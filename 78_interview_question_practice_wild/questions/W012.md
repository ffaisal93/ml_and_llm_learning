## Question

<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">A language model generates text one token at a time. Greedy decoding always takes the single most likely next token, which can miss a sequence that is more likely overall. Beam search keeps the beam_width best partial sequences at every step instead of one. Implement beam search over a given language model.

What to implement
def beam_search(
lm_predict: Callable[[List[int]], np.ndarray],
start_token: int,
beam_width: int,
num_steps: int,
vocab_size: int,
) -&gt; List[Tuple[List[int], float]]:
lm_predict(tokens): given the token ids decoded so far, returns a NumPy array of shape (vocab_size,) with the probability of each next token (token ids 0 .. vocab_size - 1). It is deterministic.
start_token: the token every sequence begins with.
beam_width: how many sequences to keep after each step.
num_steps: how many tokens to append after the start token.
vocab_size: the number of token ids.
Returns a list of (sequence, score) pairs, best first.
Rules
1.
Every sequence starts with start_token; each step appends exactly one token, so every returned sequence has length num_steps + 1.
2.
The score of a sequence is the sum of the natural logs of the probabilities of its appended tokens, accumulated step by step in float64: new_score = old_score + log(p). The start token adds nothing. Use the exact log with no smoothing; a probability of 0 gives a score of -inf, and that sequence is still a valid candidate.
3.
At each step, extend every kept sequence by every token id, then keep the beam_width best candidates (all of them if there are fewer).
4.
&quot;Best&quot; means the higher score. Candidates with exactly equal scores are ordered by their sequence, lexicographically smaller first.
5.
The returned list follows the same order. If num_steps is 0 the result is [([start_token], 0.0)].
6.
Call lm_predict with the full sequence so far, start token included, and give it a fresh list each time (it may modify the list it receives).
7.
Raise ValueError if beam_width &lt; 1, num_steps &lt; 0 or vocab_size &lt; 1.

You may use NumPy and the Python standard library.

Examples

Both examples use this model with vocab_size = 5: the token after t is (t + 1) % 5 with probability 7/11; each of the other four tokens has probability 1/11.

def dummy_lm(tokens):
probs = np.full(5, 0.1)
probs[(tokens[-1] + 1) % 5] += 0.6
return probs / probs.sum()

Example 1

beam_search(dummy_lm, start_token=0, beam_width=2, num_steps=2, vocab_size=5)
-&gt; [([0, 1, 2], -0.9039702474861145),
([0, 0, 1], -2.8498803965414274)]

Explanation: after step 1 the beams are [0, 1] (score log(7/11)) and [0, 0], which wins the four-way tie at log(1/11) because it is lexicographically smallest. At step 2, [0, 1, 2] scores 2·log(7/11). Five candidates tie at log(7/11) + log(1/11), among them [0, 0, 1] and [0, 1, 0]; the smallest, [0, 0, 1], is kept.

Example 2

beam_search(dummy_lm, start_token=0, beam_width=1, num_steps=3, vocab_size=5)
-&gt; [([0, 1, 2, 3], -1.355955371229172)]

Explanation: with one beam, beam search is greedy decoding: it takes the 7/11 token three times, for a score of 3·log(7/11).

Example 3

beam_search(dummy_lm, start_token=3, beam_width=4, num_steps=0, vocab_size=5)
-&gt; [([3], 0.0)]

Explanation: no tokens are decoded, so the only sequence is the start token with score 0.

Constraints
1 &lt;= vocab_size &lt;= 500, 1 &lt;= beam_width &lt;= 50, 0 &lt;= num_steps &lt;= 50, and beam_width * vocab_size * num_steps &lt;= 2 * 10^5.
Every array that lm_predict returns has non-negative entries that sum to 1 (up to rounding).
Follow-up: stop at an end token

Add an eos_token argument. A sequence that ends with it is finished: it is no longer extended but keeps competing for a place in the beam with its score. How do you compare finished and unfinished sequences fairly, given that every extra token lowers the score?</pre>

## Worked solution

1. Implement beam search with correct scores and end-of-sequence handling. Beam search keeps several strong partial sequences; it is a search procedure rather than a random sampler.
2. Store each beam's tokens and sum of token log probabilities. Expand only unfinished beams.
3. Combine candidate expansions and retain the best beam_width sequences under the chosen ranking rule; keep finished hypotheses separately or carry them without further tokens.
4. Stop when the chosen stopping criterion is satisfied, and state whether length normalization is used. A minimal reference implementation is in the coding lab.

### Small example / sanity check

A sequence with token probabilities 0.5 and 0.5 has probability 0.25 and log score log(0.25), not the average probability 0.5.

### Common trap

Multiplying many probabilities, appending tokens after EOS, or assuming a wider beam always improves subjective quality.
