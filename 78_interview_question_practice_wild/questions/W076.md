3. Implement ACE

ACE measures how well the confidence of the model matches its accuracy.

1.
The confidence of an example is exp(logprob), a number in (0, 1].
2.
Split [0, 1] into m_bins equal-width bins: bin m covers [m/m_bins, (m+1)/m_bins). A confidence of exactly 1.0 belongs to the last bin.
3.
For every non-empty bin B, acc(B) is the mean accuracy and conf(B) the mean confidence of the examples in it.
4.
ACE = mean over the non-empty bins of |acc(B) - conf(B)|. Empty bins are skipped: they are not counted as zero and they are not in the denominator.
5.
With no examples, return 0.0.

Implement:

def ace_calc(logprobs: np.ndarray, accs: np.ndarray, m_bins: int = 15) -&gt; float:

logprobs and accs are arrays of the same length n; logprobs[i] &lt;= 0 and accs[i] is 0 or 1. The function returns a Python float.

Examples

Example 1: m_bins = 5, confidences [0.9, 0.95, 1.0, 0.5, 0.55] (so logprobs = np.log(confidences)), accs = [1, 1, 1, 0, 1] returns 0.0375. The first three fall in bin 4 (acc 1.0, conf 0.95, gap 0.05). The last two fall in bin 2 (acc 0.5, conf 0.525, gap 0.025). The other three bins are empty, so ACE = (0.05 + 0.025) / 2.

Example 2: m_bins = 15 (the default), confidences [0.99, 0.30], accs = [1, 0] returns 0.155. The confidences fall in bins 14 and 4 (gaps 0.01 and 0.30), so ACE = (0.01 + 0.30) / 2.

Example 3: logprobs = [0.0, 0.0], accs = [1, 1] returns 0.0. Both confidences are exactly 1.0, they share the last bin, and acc = conf = 1.

## Worked solution

1. Why can cross-entropy worsen while accuracy stays unchanged? Accuracy uses the chosen class; cross-entropy also measures how much probability the model assigns to the true class.
2. Separate correct and incorrect predictions and inspect confidence changes.
3. For a true-class probability p, loss is -log(p), which grows without bound as p approaches zero.
4. Track validation loss, accuracy and calibration together; consider early stopping or calibration using a separate validation set.
5. Bound cross-entropy when a prediction is correct or incorrect. The label probability is constrained by whether it is the largest class probability, not merely by the number of classes.
6. For C classes and a correct argmax, p_true>=1/C, so 0<=loss<=log(C), subject to tie conventions.
7. For an incorrect argmax, p_true<=1/2 and loss>=log(2), with the lower bound an infimum when strict inequality is required.
8. There is no finite upper bound for an incorrect prediction as p_true approaches zero. For N examples with k errors, the mean-loss lower bound is (k/N)*log(2). If k=0 the upper bound is log(C); if k>0 there is no finite upper bound.
9. Calculate average calibration error from confidence bins. Calibration compares predicted confidence with observed correctness; it is different from classification accuracy.
10. Convert predicted-class log probabilities to confidence with exp(logprob), then assign equal-width bins in [0,1].
11. Put confidence exactly 1 in the last bin. For each non-empty bin compute abs(mean_accuracy-mean_confidence).
12. For this ACE definition, average gaps equally across non-empty bins and return zero for no examples. A sample-weighted version is a different metric.

### Small example / sanity check

An already-wrong example whose true-class probability falls from 0.1 to 0.001 keeps the same error count while loss grows from 2.303 to 6.908.
