3. Implement ACE

ACE measures how well the confidence of the model matches its accuracy.
1. The confidence of an example is exp(logprob), a number in (0, 1].
2. Split [0, 1] into m_bins equal-width bins: bin m covers [m/m_bins, (m+1)/m_bins). A confidence of exactly 1.0 belongs to the last bin.
3. For every non-empty bin B, acc(B) is the mean accuracy and conf(B) the mean confidence of the examples in it.
4. ACE = mean over the non-empty bins of |acc(B) - conf(B)|. Empty bins are skipped: they are not counted as zero and they are not in the denominator.

## Worked solution

### 1–2. Derive the tight loss bounds

For ten classes and a correct argmax, $p_c\ge1/10$, so $0\le-\log p_c\le\log10$. Zero is a limiting infimum for finite softmax logits. The upper endpoint depends on tie-breaking: uniform probabilities attain it only if the chosen argmax is the true class; otherwise it is a supremum approached with a small perturbation.

If the prediction is wrong, some other probability is at least $p_c$, hence $p_c\le1/2$ and $-\log p_c\ge\log2$. This is again a tight boundary with ties/limits; there is no finite upper bound because $p_c$ can approach zero.

With exactly $k$ errors among $n$ examples, the mean-loss infimum is $k\log2/n$. For $k=0$, the upper bound is $\log10$. For **any** $k\ge1$, there is no finite upper bound: even one confidently wrong example can dominate the mean. Thus $k=1$ has lower bound $\log2/n$, and $k=n-1$ has lower bound $(n-1)\log2/n$ (assuming $n>1$). Accuracy alone cannot upper-bound loss once an error exists.

### 3–5. Interpret training, test and calibration curves

Typically training loss decreases and training accuracy approaches one. Test accuracy improves then plateaus or degrades with overfitting, while test loss may rise as remaining errors become more confident. These are expectations, not guaranteed epoch-by-epoch monotonic curves. After training **stops**, a fixed model on a fixed test set does not keep changing; the rising test-loss description refers to later training epochs.

For a memorized training set, confidence approaches one and accuracy is one, so training ACE approaches zero. Test ACE often grows when confidence rises without matching accuracy, but this is not a theorem. Confidence and correctness can change in offsetting ways.

The exercise defines an **unweighted mean across occupied equal-width bins**. Moving a single prediction across a boundary can change both bin means and the number of occupied bins. That discontinuity, finite samples and stochastic optimization can make ACE spiky. It need not track cross-entropy smoothly.

### Implement the exact ACE definition

```python
import numpy as np
def ace_calc(logprobs, accs, m_bins=15):
    logprobs,accs = np.asarray(logprobs),np.asarray(accs)
    if logprobs.ndim!=1 or accs.shape!=logprobs.shape or not 1<=m_bins<=1000:
        raise ValueError('Expected matching vectors and valid bin count')
    if np.any(logprobs>0) or np.any(~np.isfinite(logprobs)) or not np.all((accs==0)|(accs==1)):
        raise ValueError('Expected finite log confidences <=0 and binary correctness')
    if logprobs.size==0:
        return 0.0
    confidences = np.exp(logprobs)
    bins = np.minimum((confidences*m_bins).astype(int),m_bins-1)
    counts = np.bincount(bins,minlength=m_bins)
    conf_sum = np.bincount(bins,weights=confidences,minlength=m_bins)
    acc_sum = np.bincount(bins,weights=accs,minlength=m_bins)
    occupied = counts>0
    return float(np.mean(np.abs(acc_sum[occupied]-conf_sum[occupied])/counts[occupied]))


```

[Download the implementation and related numerical routines](../exact_numeric_51_100.py). `bincount` computes bin totals in $O(n+m)$ time with $O(m)$ auxiliary aggregates; vector inputs/indices use $O(n)$ memory. Clamping the index puts confidence exactly one into the last bin. Empty input returns zero before any averaging.

The first example has gaps 0.05 and 0.025, so ACE is 0.0375. It is **not** weighted by bin population. The second gives 0.155; confidence-one correct predictions give zero.
