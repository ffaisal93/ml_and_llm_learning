## Question

Build a sampler for a labelled dataset that is stored in one bucket of examples per class. A draw must return a class label together with one example of that class, and every class must be equally likely to be the one returned, however many examples its bucket holds. This is the sampler you would use to build class-balanced training batches.

### What to implement

stratified_sample(training, rng=None) -&gt; tuple[str, object]

training: a dict that maps a class label (str) to the list of examples of that class, for example {"cat": [...], "dog": [...], "fox": [...]}.
rng: an optional random.Random instance. Use it for every random choice, so a seeded generator makes the draw repeatable. When it is None, use the module-level random.
Return (class_label, example).

### Rules

1. The probability that the returned label is a given class is the same for every class that has at least one example (1/K for K such classes), whatever the bucket sizes.
2. Given the class, every example in its bucket is equally likely.
3. A class whose bucket is empty is never returned and does not count towards K.
4. If no class has any example (including an empty dict), raise ValueError.
5. Do not modify training.

### Examples

```text
1. {"cat": [1, 2, 3, 4], "dog": ["d"]}: the label is "cat" with probability 1/2 and "dog" with probability 1/2. If it is "cat", each of 1, 2, 3, 4 has probability 1/4; if it is "dog", the example is "d". Drawing uniformly over all five examples would instead return "cat" 80% of the time, which is not what is wanted here.
2. {"a": [], "b": [7], "c": []} always returns ("b", 7).
3. {"a": [], "b": []} raises ValueError.
```

### Constraints

Up to 10^3 classes and 10^6 examples per class; each draw takes O(K) time and O(K) extra space, where K is the number of classes.

## Worked solution

### Solution outline

Sampling rules must specify desired class proportions, replacement and rounding behavior.

1. Compute class quotas from target proportions and requested size using a deterministic remainder-allocation rule.
2. Sample within buckets using a seeded generator, respecting available counts or explicitly allowing replacement.
3. Preserve or record inclusion probabilities if the sample will be used for population estimation.

### Understand why the approach works

#### Establish what the number actually estimates

Write the population, unit of analysis, outcome window and denominator next to the metric. A per-user mean and a per-impression mean answer different questions. A global mean over unequal batches is

$$
\bar\ell=\frac{\sum_b\sum_{i\in b}\ell_i}{\sum_b n_b},
$$

not generally the unweighted mean of batch means. Workers should reduce numerators and denominators separately when reporting that metric.

Use a comparison with matched examples, mature labels and unchanged definitions. For uncertainty, resample independent units; repeated events within a user or prompt are not automatically independent. A confidence interval measures sampling uncertainty under assumptions, not protection against leaked data or an inappropriate target.

Calibration asks whether predictions around probability $p$ are correct about fraction $p$ of the time. It is not the same as accuracy. A reliability plot should show bin populations, and a calibration-error formula must say whether bins or examples receive equal weight.

When quality regresses, trace data availability, feature freshness, label delays and cohort mix before automatically retraining. For example, a fraud model may look worse on immature labels even when its true behavior has not changed. Report missing/time-out outputs explicitly: dropping them from the denominator can turn an unreliable system into an apparently perfect one.

### Work a small example

For 10 examples at proportions [0.55,0.45], quotas cannot both be exact; a stated tie/rounding rule must allocate the final unit.

### Edge cases and common mistakes

Assuming an intentionally balanced sample has the original population prevalence.
