## Question

You are given transactions(transaction_id INT, vendor_id INT, amount_charged INT, transaction_type VARCHAR, refund_transaction_id INT NULL, timestamp DATETIME) where transaction_type is PURCHASE or REFUND (a REFUND's refund_transaction_id points to the original purchase transaction_id) and vendors(vendor_id INT, city VARCHAR, state VARCHAR, country VARCHAR).

Write a SQL query to: compute each vendor's net total charged amount in the last 2 years (relative to CURRENT_DATE), where PURCHASE is positive and REFUND is negative; return the Top 3 vendors by net total amount (descending).

Suggested output columns: vendor_id, net_amount.

Assumptions/constraints
Refund rows are counted based on the refund timestamp and must be within the 2-year window to be included.
amount_charged is a positive integer.
transaction_id is unique.
Example

Current date assumed 2025-04-01. Output: vendor_id=3 net_amount=500; vendor_id=2 net_amount=300; vendor_id=1 net_amount=150 (101 and 103 cancel out, +102 = 150).

## Worked solution

### Count refund rows by their own date

Each transaction is already the accounting fact. Add PURCHASE and subtract REFUND amounts inside the last-two-years filter; do not require its referenced original purchase to also fall inside the window. The reference is useful for validation/fraud/reconciliation, but joining the purchase into this sum would change the specified event-time metric.

```sql
SELECT vendor_id,
 SUM(CASE WHEN transaction_type='PURCHASE' THEN amount_charged
          WHEN transaction_type='REFUND' THEN -amount_charged ELSE 0 END) AS net_amount
FROM transactions
WHERE timestamp>=CURRENT_DATE-INTERVAL '2 years' AND timestamp<CURRENT_DATE+INTERVAL '1 day'
GROUP BY vendor_id ORDER BY net_amount DESC,vendor_id LIMIT 3;
```

Choose exactly three rows with vendor_id as deterministic tie-break (or fewer if fewer vendors have transactions). Use the end of today as the upper bound relative to CURRENT_DATE, excluding future-dated transactions. A purchase 150 and a purchase 100/refund 100 pair net 150; a refund 40 today of a three-year-old purchase contributes -40 today. Vendors with only refunds may have negative totals and remain eligible. `vendors` is unnecessary unless geographic filters/labels are needed, so avoid its join and possible row multiplication. Tests use fixed date bounds, refunds of old purchases, exact cutoff and ties. Index timestamp for a selective time range or partition fact data by time; large windows still scan/aggregate many rows and may merit daily vendor net rollups.
