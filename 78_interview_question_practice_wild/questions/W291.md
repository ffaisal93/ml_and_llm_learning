## Worked solution

### Solution outline

1. Functional programming emphasizes functions, explicit data flow and often immutability; it does not forbid all state. NP-complete decision problems are in NP and every NP problem polynomially reduces to them; this is not a proof that no polynomial algorithm exists.
2. Integration by parts is integral u dv=uv-integral v du. Mutual information is sum p(x,y)log[p(x,y)/(p(x)p(y))], or the analogous density integral; it is nonnegative under the usual existence conditions.
3. Entropy is -sum p log p; on a fixed n-element support, KL(p||uniform)=log n-H(p)>=0, so uniform maximizes it. An MGF is E[exp(tX)] where finite near zero; derivatives give moments when justified.
4. Insertion sort inserts each next item into an ordered prefix: $O(n^2)$ worst/average, $O(n)$ on already ordered data with a standard implementation, $O(1)$ extra array space. The iid finite-variance CLT states sqrt(n)*(mean-mu)/sigma tends in distribution to Normal(0,1).

### Understand why the approach works

#### Eliminate the probability vector algebraically

Choose $m=\max_i z_i$ and define shifted weights $w_i=e^{z_i-m}$ and $Z=\sum_iw_i$. Then $p_i=w_i/Z$ and

$$
H(p)=-\sum_i p_i\log p_i
=\log Z-\frac{\sum_iw_i(z_i-m)}{Z}.
$$

This identity requires only a maximum and two scalar sums. First scan the indexed input to validate values and find $m$; scan again to accumulate $Z$ and the weighted shifted sum. A block controls each inner loop's index range; no slice or block array is needed, so auxiliary memory remains $O(1)$.

For logits $[1000,999]$, shifting gives $[0,-1]$, $Z=1+e^{-1}$, and the weighted sum is $-e^{-1}$. The entropy is approximately $0.582203109$ nats. Computing huge unshifted exponentials would overflow even though the answer is ordinary-sized.

A negative-infinity logit has zero probability and should be skipped in the weighted sum: evaluating $0\cdot(-\infty)$ gives NaN. Empty input, nonpositive block size, NaN, positive infinity and an all-negative-infinity sequence violate the stated contract. Validate before publishing a result.

Test an object that supports only integer indexing and `len`: this catches accidental slicing or iteration hidden in convenient NumPy conversion. Changing block size must not change the mathematical result apart from harmless floating-point accumulation effects.

### Work a small example

For a fair binary variable, entropy is log 2 nats. Independent X and Y have zero mutual information, even when each individually has positive entropy.

### Edge cases and common mistakes

Saying the CLT makes raw observations Gaussian or that an MGF exists for every distribution.

### Check your reasoning on related cases

**Compute softmax entropy with constant auxiliary memory.** For [0,0], Z=2 and S=0, so entropy is log(2). For one finite logit and the rest negative infinity, entropy is zero.

Why skip negative infinity explicitly? Zero times negative infinity is NaN in floating-point arithmetic.

**Design a Monte Carlo estimate and quantify its error.** Reducing Monte Carlo standard error by a factor of two generally requires four times as many independent samples.

What if the distribution has infinite variance? Ordinary square-root-N error reasoning may fail.
