Strong answers connect formulas to hardware.

Matmul M x K by K x N costs O(MKN); GPU optimization comes from tiling, data reuse, and minimizing slow global-memory traffic.
Shared memory / SRAM is much faster but smaller than HBM; tiling brings submatrices close to the compute units.

## Worked solution

1. Why do prefill and decode have different bottlenecks? Prefill processes many prompt tokens together; decode repeatedly produces the next token for each active request.
2. Prefill uses larger matrix operations and can often exploit substantial parallel compute.
3. Decode at small batch sizes frequently rereads large weights for relatively little work and also reads a growing KV cache.
4. Measure arithmetic intensity, batch size, sequence length and hardware. The bottleneck can change; “prefill compute-bound, decode bandwidth-bound” is a useful tendency, not a universal law.
5. Explain continuous batching and paged KV storage. Continuous batching changes the active set between generation steps; paged storage makes growing caches easier to allocate.
6. Admit new requests as capacity becomes available and remove finished requests instead of waiting for a fixed batch to complete.
7. Store each request's KV sequence in fixed-size blocks referenced by a logical block table, allowing physical blocks to be non-contiguous.
8. Track live-token memory, fragmentation, eviction and scheduler fairness. Paged allocation changes storage management; it does not change what attention means.
9. Estimate an LLM serving capacity budget. Capacity is constrained by memory, computation, memory traffic and arrival patterns, so one parameter count is insufficient.
10. Estimate weight bytes, KV bytes for the live-token budget, temporary buffers and runtime overhead.
11. Benchmark prefill and decode at representative lengths and concurrency; measure throughput and tail latency together.
12. Set admission limits below the measured saturation point and handle overload with bounded queues, rejection or a stated fallback.

### Small example / sanity check

One request with a long prompt can have high time-to-first-token, while a large active batch can increase inter-token latency.

### Common trap

Reporting only tokens per second while hiding slow first responses or poor tail latency.
