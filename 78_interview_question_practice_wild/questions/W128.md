## Question

<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">QR Data Analysis Prediction Case

Open-ended data-analysis round: define features, targets, models, and evaluation for a prediction problem such as housing prices, CitiBike demand, rental price, stock price from search/social data, or alpha testing.

Requirements

You receive a prediction problem and must reason through the full modeling plan. Reported domains include:

Predict housing prices from historical data.
Predict CitiBike demand or station inventory at a specific location.
Predict rental price.
Use six years of Google search data with timestamp, device id, location, query, and URL to predict a company&#x27;s stock price at arbitrary times.
Use Twitter / social data to predict stock price.
Test whether a momentum alpha works.

Interviewers probe:

Feature and outcome definition.
Model choice: linear regression, random forest, nonlinear alternatives, and why each may work.
Missing values, outliers, data cleaning, and special shocks such as COVID.
Nonlinear relationships, heteroskedasticity, multicollinearity, seasonality, data drift, and variance drift.
Data leakage and overfitting.
Train / validation / test split.
Evaluation metrics such as MSE, MAE, accuracy, ROC-AUC, or domain-specific performance metrics.
Notes
This is not a coding-heavy round. It is a structured statistical reasoning interview.
Candidates who only give high-level ML names struggle; the interviewer asks for assumptions, failure modes, and exact evaluation logic.
Several candidates observe that traditional statistics and linear-model reasoning are valued more than generic ML framing.</pre>

## Worked solution

1. Fit a baseline on messy tabular data without leakage. Build a trustworthy split and simple baseline before sophisticated feature engineering.
2. Define the target, prediction time and unit of independence, then split by time or group if required.
3. Fit imputation, scaling and category encodings on training folds only. Start with a dummy baseline and a regularized linear or small tree model.
4. Evaluate slices, missingness patterns and calibration; document features unavailable at decision time and remove them.
5. Explain multicollinearity and stable least squares. Correlated predictors can make coefficient estimates unstable even when predictions remain useful.
6. Write the least-squares objective ||Xw-y||²; inspect rank or singular values of X.
7. Use QR or SVD-based least squares rather than explicitly inverting XᵀX. Centering and scaling can help conditioning.
8. Use ridge if shrinkage is appropriate, and distinguish predictive stability from interpretation of individual coefficients.
9. How should you split data for reliable model selection? The validation procedure must imitate which information will be available when the model is used.
10. Use a final held-out test set and tune only within training/validation data.
11. Use grouped splits for repeated entities and forward-looking splits for time-dependent prediction. Stratification preserves class proportions when compatible with those constraints.
12. Fit the complete preprocessing and model pipeline inside each fold; reserve nested validation for unbiased evaluation of an extensive selection procedure.
13. Separate correlation, prediction and causation. A useful predictive association need not describe the effect of intervening on a feature.
14. State whether the goal is forecasting, explanation or estimating an intervention effect.
15. List plausible confounders and timing relationships; check selection and measurement mechanisms.
16. Use randomization or a defensible causal identification strategy for causal claims, with explicit assumptions and sensitivity checks.

### Small example / sanity check

A “refund issued” field may predict churn extremely well but be recorded after the churn decision, making it unusable for a prospective model.

### Common trap

Fitting preprocessing on all rows before cross-validation, even when labels were not directly used.
