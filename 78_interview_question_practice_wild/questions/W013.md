## Question

Problem: Implement a BPE Tokenizer

Implement a simplified Byte Pair Encoding tokenizer with three operations:

train(text: str, threshold: int) -&gt; None
encode(text: str) -&gt; List[int]
decode(embedding: List[int]) -&gt; str

### Rules

Initially, the training text text is split into single-character tokens.

train(text, threshold) repeatedly performs the following steps:

Count all adjacent token pairs in the current token sequence. For example, in ["a","b","a","b"], pair ("a","b") appears 2 times and pair ("b","a") appears 1 time.
If every pair appears fewer than threshold times, stop training.
Otherwise, choose the pair with the highest frequency.
If multiple pairs have the same frequency, choose the lexicographically smallest pair. Compare pairs as string tuples (left_token, right_token).
Merge the selected pair into a new token by concatenating the two token strings. For example, ("ab","c") becomes "abc".
In one round, merge all non-overlapping occurrences of the selected pair from left to right.
Record every selected merge rule for use in encode.
Token ID Rules

To make the output deterministic:

All distinct single-character tokens in the training text are assigned ids 0, 1, 2, ... in lexicographical order.
New tokens created during training are assigned subsequent ids in creation order.
The input to encode is guaranteed to contain only characters seen in the training text.
encode

encode(text):

Split the input text into single-character tokens.
Apply the merge rules learned during train, in order.
For each merge rule, merge all non-overlapping occurrences from left to right.
Return the ids of the final token sequence.
decode

decode(embedding):

Convert each token id back to its token string and concatenate them.

## Worked solution

### Train merges by frequency threshold, then replay them by rank

Initialize lexicographically sorted character ids, not first-appearance ids. Count adjacent pairs, choose maximum count then lexical pair, stop when that count is below threshold, and merge all nonoverlapping occurrences left-to-right. New token strings get ids in creation order; if a string already exists, reuse its id. Every round reduces token count, so positive-threshold training terminates. Training resets state rather than unintentionally accumulating an old alphabet.

```python
from collections import Counter


class BPETokenizer:
    def __init__(self):
        self.vocab = {}
        self.inv_vocab = {}
        self.merges = []

    @staticmethod
    def _merge(tokens, pair):
        out = []
        i = 0
        while i < len(tokens):
            if i + 1 < len(tokens) and (tokens[i], tokens[i + 1]) == pair:
                out.append(tokens[i] + tokens[i + 1])
                i += 2
            else:
                out.append(tokens[i])
                i += 1
        return out

    def train(self, text, threshold):
        if threshold < 1:
            raise ValueError("positive frequency threshold required")
        self.vocab = {c: i for i, c in enumerate(sorted(set(text)))}
        self.merges = []
        tokens = list(text)
        while len(tokens) > 1:
            counts = Counter(zip(tokens, tokens[1:]))
            pair = min(counts, key=lambda p: (-counts[p], p))
            if counts[pair] < threshold:
                break
            merged = "".join(pair)
            if merged not in self.vocab:
                self.vocab[merged] = len(self.vocab)
            self.merges.append(pair)
            tokens = self._merge(tokens, pair)
        self.inv_vocab = {i: t for t, i in self.vocab.items()}

    def encode(self, text):
        tokens = list(text)
        for pair in self.merges:
            tokens = self._merge(tokens, pair)
        return [self.vocab[t] for t in tokens]

    def decode(self, embedding):
        return "".join(self.inv_vocab[i] for i in embedding)


t = BPETokenizer()
t.train("abab", 2)
assert t.vocab == {"a": 0, "b": 1, "ab": 2} and t.encode("abab") == [2, 2]
assert t.decode(t.encode("baba")) == "baba"
t.train("aaaaa", 2)
assert t.merges[0] == ("a", "a") and t.decode(t.encode("aaaaa")) == "aaaaa"
# Equal counts ab and bc: lexical pair ab wins.
t.train("abc", 1)
assert t.merges == [("a", "b"), ("ab", "c")]
assert t.encode("abc") == [4] and t.decode([4]) == "abc"
t.train("", 1)
assert t.encode("") == [] and t.decode([]) == ""
print(
    "W013: frequency threshold, exact ids, lexical ties, nonoverlap and roundtrip passed"
)
```

### A deterministic worked trace

For “abab” and threshold2, character ids are a=0,b=1; pair (a,b) has count2 and creates ab=2. The remaining pair (ab,ab) has count1 and stops, so encode gives `[2,2]` and decode restores “abab”. For “abc” threshold1 the tied initial pairs choose (a,b), then (ab,c), yielding abc id4. Counts include overlapping occurrences (aa occurs four times in aaaaa), while actual replacement is nonoverlapping. These are different operations and the tests cover both.

Encoding never recounts pairs or performs arbitrary longest-prefix vocabulary matching; it applies the frozen learned rules in their learned order. Known-character input is guaranteed. Empty text roundtrips. With R merges and text length n the simple reference costs O(Rn) time and O(n+vocab) storage; optimizing pair updates/neighbor lists can improve large corpora without changing ties or ids. This is character BPE, not a byte fallback or whitespace tokenizer.
