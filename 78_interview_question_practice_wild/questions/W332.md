## Worked solution

### Pick a small explicit data contract and preserve rejected rows

The source schema is deliberately open. This **demonstration** reads CSV `id,name,amount`, keeps IDs as strings, collapses internal name whitespace and parses nonnegative exact-cent Decimal amounts. Missing required fields, invalid/nonfinite/negative amounts and duplicate IDs are quarantined; first valid occurrence wins. A malformed header fails fast because row interpretation is unsafe. A rejected first occurrence does not reserve its ID, so a later valid row can be accepted.

```python
import csv
import json
from decimal import Decimal,InvalidOperation
from pathlib import Path
import os
import tempfile

def run_etl(source,destination,reject_path):
    """Demo CSV schema id,name,amount; first valid ID wins; exact decimal cents."""
    seen=set();accepted=[];rejects=[]
    with open(source,newline='',encoding='utf-8') as f:
        reader=csv.DictReader(f)
        if not {'id','name','amount'}<=set(reader.fieldnames or []):
            raise ValueError('missing required columns')
        for line,row in enumerate(reader,2):
            try:
                key=row['id'].strip();name=' '.join(row['name'].split())
                amount=Decimal(row['amount'])
                if not key or not name or not amount.is_finite() or amount<0 or amount!=amount.quantize(Decimal('.01')):
                    raise ValueError('required fields or nonnegative cent amount invalid')
                if key in seen:raise ValueError('duplicate id: first valid row wins')
                seen.add(key);accepted.append({'id':key,'name':name,'amount':str(amount.quantize(Decimal('.01')))})
            except (ValueError,InvalidOperation,TypeError,AttributeError) as e:
                rejects.append({'line':line,'raw':row,'reason':str(e)})
    # Each destination is atomically replaced. A crash between them needs a manifest
    # or transactional sink if the two files must form one atomic publication.
    for path,rows in [(destination,accepted),(reject_path,rejects)]:
        path=Path(path);path.parent.mkdir(parents=True,exist_ok=True)
        fd,temp=tempfile.mkstemp(dir=path.parent,prefix='.etl-')
        try:
            with os.fdopen(fd,'w') as out:
                for row in rows:out.write(json.dumps(row)+'\n')
                out.flush();os.fsync(out.fileno())
            os.replace(temp,path)
        finally:
            if os.path.exists(temp):os.unlink(temp)
    return {'accepted':len(accepted),'rejected':len(rejects)}
```

Call `run_etl("input.csv","clean.jsonl","rejects.jsonl")`. For `001, Alice  Smith ,12.30` followed by another valid 001 and `002,Bob,bad`, output has one row with name `Alice Smith`/amount `12.30`, with two detailed rejects. Re-running replaces outputs deterministically instead of appending duplicates. Each file is fsynced and atomically renamed; publishing the accepted and rejected files together would need a manifest/transactional destination because two renames are not one atomic transaction.

Time is O(rows) expected, memory O(unique IDs + output rows). For truly large input, stream accepted/reject output to temporary files and store dedup keys in a database/external sort; the current small ETL is honest about buffering. Separate extract/validation/sink functions as more formats or rules arrive, preserve schema/rule versions and reconcile input=accepted+rejected. Tests verify normalization, decimal exactness, duplicate policy, invalid/header handling and deterministic reruns.
