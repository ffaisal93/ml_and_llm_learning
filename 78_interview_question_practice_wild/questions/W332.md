## Question

<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">Problem: Implement a Simple ETL Pipeline (Write Runnable Code).

Implement a small ETL (Extract-Transform-Load) pipeline in a local editor (e.g., VSCode) that extracts raw data, cleans/transforms it, and loads the result to a destination.

Requirements
Extract: Read raw input data (you may assume CSV/JSON text input).
Transform: Clean and transform the data (e.g., normalize fields, filter invalid records, type casting, deduplication).
Load: Write the processed data to an output destination (e.g., a file or stdout).
Constraints / Edge Cases (you should define and justify them)
What constitutes an invalid record (e.g., missing required fields, invalid formats).
Deduplication rule (which fields define uniqueness).
Error handling strategy (skip bad rows, log and continue, or fail fast).
Deliverables
Runnable code.
A short explanation of your data-cleaning rules, error handling, and extensibility considerations.</pre>

## Worked solution

1. Design an ETL job that can safely rerun. A rerun should converge to the intended data state rather than duplicate outputs.
2. Define source partitions, stable row keys, transformations and a validation contract.
3. Write to staging, validate row counts and constraints, then publish atomically or with a controlled merge/upsert.
4. Track checkpoints and source watermarks; define late-data reprocessing and schema-evolution policies.

### Small example / sanity check

Rerunning yesterday's partition should replace or reconcile that partition, not append it a second time.

### Common trap

Marking the job complete before its output is durably visible.
