## Question

You are given a table of time-stamped market data (prices and a few candidate predictors) and asked to build a predictive model of future returns, then explain and defend the work to a panel of reviewers. Describe how you would carry out the whole project and which choices you would defend.

### Requirements

1. Frame the problem: state the prediction target, the horizon, the evaluation metric, and your assumptions about the data.
2. Prepare the data with pandas: resample or align timestamps, compute returns, build lagged and rolling features, and join sources. Explain how each step avoids look-ahead bias.
3. Choose a model and justify it. A simple, interpretable baseline such as linear regression is acceptable if you can explain why it is enough.
4. Validate honestly: use time-ordered (walk-forward or expanding-window) splits, report out-of-sample performance, and compare against a naive benchmark such as predicting zero or the mean.
5. Present the result: problem, data and cleaning, features, model, validation, limitations and next steps.
Follow-ups
Follow-up 1: implementation detail. Walk through one pandas transformation line by line, and say what would break if the index were unsorted or the time zones misaligned.
Follow-up 2: signal or overfit. Explain how you would decide whether the signal is real: out-of-sample stability, robustness across periods, sensitivity to transaction costs, and significance of coefficients.
Follow-up 3: limitations. Name the main limitations: regime dependence, sample size, selection effects in the data, and costs left unmodeled.

### Constraints

Every feature needs a stated rationale.
Features at time t may use only information available at or before t.

## Worked solution

### Define the prediction and demonstrate timestamp-safe preparation

Choose next observed session log return $y_t=\log(P_{t+1}/P_t)$ for one asset, decided immediately after close t; use MSE/MAE and out-of-sample R² relative to zero and a training-mean benchmark. The closing-price execution itself is not guaranteed after observing the close: a tradable strategy needs next-available execution prices and a correspondingly shifted label/cost model. No actual table is supplied, so the following UTC daily example is a **synthetic preparation/evaluation fixture**, not measured market alpha.

The features have stated rationales: current completed return measures short-horizon behavior, five-return sum measures momentum, five-return volatility measures risk/regime. An optional already-available external signal is joined backward by publication time. All transformations below use current/past information for X; only target and label_end look forward.

```python
import numpy as np
import pandas as pd
from sklearn.linear_model import Ridge
from sklearn.pipeline import make_pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler
from sklearn.metrics import mean_squared_error


def prepare(prices,predictors=None):
    # Chosen schema: UTC-convertible timestamp and positive close for ONE asset.
    p=prices.copy();p['timestamp']=pd.to_datetime(p.timestamp,utc=True,errors='raise')
    p=p.sort_values('timestamp')
    if p.timestamp.duplicated().any():raise ValueError('conflicting bar timestamps require resolution')
    p=p.set_index('timestamp')
    if (p.close<=0).any():raise ValueError('positive prices required')
    # Daily UTC is only a demonstration calendar. Production uses market sessions.
    p=p[['close']].resample('1D').last().dropna()
    r=np.log(p.close).diff()
    # Decision is just AFTER this close, execution assumptions discussed in answer.
    p['return_now']=r
    p['momentum_5']=r.rolling(5,min_periods=5).sum()
    p['volatility_5']=r.rolling(5,min_periods=5).std()
    p['target']=np.log(p.close.shift(-1)/p.close)
    p['label_end']=p.index.to_series().shift(-1)
    if predictors is not None:
        q=predictors.copy();q['available_at']=pd.to_datetime(q.available_at,utc=True,errors='raise')
        q=q.sort_values('available_at')
        p=pd.merge_asof(p.reset_index().sort_values('timestamp'),q,on=None,
                        left_on='timestamp',right_on='available_at',direction='backward').set_index('timestamp')
    return p


def evaluate(table,min_train=30,test_size=10):
    features=['return_now','momentum_5','volatility_5']
    if 'signal' in table:features+=['signal']
    t=table.dropna(subset=features+['target','label_end'])
    results=[]
    for start in range(min_train,len(t),test_size):
        test=t.iloc[start:start+test_size]
        cutoff=test.index[0]
        # A label ending at cutoff is observable after that close; exclude equality
        # conservatively to avoid overlapping the new decision boundary.
        train=t.iloc[:start];train=train[train.label_end<cutoff]
        model=make_pipeline(SimpleImputer(strategy='median'),StandardScaler(),Ridge(alpha=1.))
        model.fit(train[features],train.target)
        pred=model.predict(test[features]);y=test.target.to_numpy()
        results.append({'test_start':str(cutoff),'n':len(y),'model_mse':mean_squared_error(y,pred),
                        'zero_mse':float(np.mean(y*y)),
                        'train_mean_mse':float(np.mean((y-train.target.mean())**2))})
    return pd.DataFrame(results)

if __name__=='__main__':
    rng=np.random.default_rng(6);dates=pd.date_range('2026-01-01',periods=100,tz='UTC')
    prices=pd.DataFrame({'timestamp':dates,'close':100*np.exp(np.cumsum(rng.normal(0,.01,100)))})
    t=prepare(prices);stats=evaluate(t)
    assert np.isclose(t.iloc[0].target,np.log(prices.close.iloc[1]/prices.close.iloc[0]))
    changed=prices.copy();changed.loc[80:,'close']*=2
    assert np.allclose(prepare(changed).iloc[:79][['return_now','momentum_5','volatility_5']],
                       t.iloc[:79][['return_now','momentum_5','volatility_5']],equal_nan=True)
    q=pd.DataFrame({'available_at':[dates[20]+pd.Timedelta(hours=1)],'signal':[99.]})
    joined=prepare(prices,q)
    assert pd.isna(joined.loc[dates[20],'signal']) and joined.loc[dates[21],'signal']==99
    print('SYNTHETIC no-signal fixture; not claimed investment performance:\n',stats.to_string(index=False))
```

### Explain and defend the transformations

`r=np.log(p.close).diff()` gives a return ending at each observed close. `r.rolling(5,min_periods=5).sum()` uses only that row and the previous four completed returns; `.shift(-1)` appears solely in the target. Sorted timestamps are essential: rolling acts in row order, and merge_asof requires sorted keys. UTC conversion prevents an apparent earlier local timestamp from joining future information; calendar resampling must use the asset's actual trading sessions, not the demonstration's daily UTC clock. Do not forward-fill missing source observations unless their stale-age policy is explicit.

The backward merge ensures available_at≤decision time; an event occurring earlier but published one hour after close first appears at the next eligible decision. The executable specifically tests this and verifies that modifying future prices cannot alter earlier features. Duplicate timestamps raise rather than silently choosing a revision. Point-in-time corporate-action adjustments, data revisions and survivorship require additional source contracts.

Ridge is an interpretable stable baseline for correlated lag/volatility features; fit imputation/scaling and coefficients anew within every expanding training period. The code purges labels ending at or after each test cutoff, reports forward-block model/zero/mean MSE, and never trains on test targets. Aggregate block squared errors weighted by n, not an unweighted average of different-size blocks. Reserve the last chronological block for final evaluation after model selection and add MAE, coefficient stability and residual plots.

Present: target/execution timing → data/calendar/cleaning → features/rationale → baseline/model → walk-forward table/plots → error analysis → limitations. Decide signal versus overfit through repeated future-period stability, sensitivity to hyperparameters/universe, block/HAC uncertainty for serial dependence, corrected multiple-testing claims and net costs including turnover/spread/slippage. Coefficient significance alone is not economic value; no-signal synthetic data need not favor the model. Limitations include regimes, small effective sample, selection/survivorship, publication lags and unmodeled impact. The actual panel-ready numeric findings require the absent market table.
