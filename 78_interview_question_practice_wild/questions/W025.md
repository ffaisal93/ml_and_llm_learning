## Question

A GPU has a peak FP16 throughput of 312 TFLOP/s and an HBM bandwidth of 1.5 TB/s. Use the roofline model to analyse matrix multiplications on it, then reason about the gradient of a residual connection and about where casting from FP32 to FP16 causes trouble.

### Questions

1. Roofline for a matmul. For (M,K)·(K,N) in FP16 (2 bytes per element, each matrix moved once), derive the FLOP count, the bytes moved, the arithmetic intensity, and the roofline time bound max(compute_time, memory_time). Compute the ridge point of this GPU.
2. Two shapes. Apply this to M = K = N = 4096 and to M = 1, K = N = 4096 (a matrix-vector product). Classify each as compute-bound or memory-bound and give both time estimates.
3. Residual gradient. For y = x + f(x), derive dL/dx in terms of dL/dy and explain why the identity branch keeps the gradient from vanishing as depth grows.
4. FP32 to FP16. Name where casting to FP16 hurts (gradient underflow, normalisation denominators, accumulation, weight updates) and give the standard mitigation for each. Explain why bf16 often needs no loss scaling.
Expected deliverable

Worked arithmetic with units for parts 1 and 2, a short derivation for part 3, and a list of pitfalls with their mitigations for part 4.

## Worked solution

### Derive and apply the roofline

For FP16 matmul, F=2MKN and B=2(MK+KN+MN) bytes under the specified once-read/once-write assumption. I=F/B FLOP/byte; compute time=F/(312×10¹²), memory time=B/(1.5×10¹²), lower-bound time=max of the two. Ridge=312/1.5=**208 FLOP/byte**.

For M=K=N=4096: F=137,438,953,472, B=100,663,296, I=1365.33>208, so **compute-bound**. Compute time=.440509ms, memory time=.0671089ms, roofline=.440509ms.

For M=1,K=N=4096: F=33,554,432, B=33,570,816, I=.999512<208, so **memory-bound**. Compute=.000107546ms=.107546microseconds; memory=.0223805ms=22.3805microseconds; roofline=.0223805ms. The matrix-vector operation does far less work but still rereads almost the same weights. Batching improves their reuse; real tiny-kernel latency also includes launch overhead.

### Residual gradient: a useful direct path, not an absolute guarantee

For y=x+f(x), column-vector upstream g=dL/dy gives $dL/dx=(I+J_f(x))^Tg=g+J_f(x)^Tg$. Across depth, products of `(I+J)` include identity paths, so information/gradients need not pass only through a long product of small branch derivatives. This makes learning corrections easier. It does **not** mathematically prevent vanishing: J_f=-I cancels the direct derivative, and other spectra can still explode. Initialization/normalization/residual scale remain important.

### Where FP16 casting hurts and what to do

| Failure point | Mechanism | Mitigation |
|---|---|---|
| Tiny gradients | Values below representable subnormal/normal ranges round toward zero | Dynamic loss scaling before backward; unscale before clipping/update, detect nonfinite gradients and skip/reduce scale |
| Normalization/loss denominator | Squaring/reduction/epsilon may overflow or lose precision; small epsilon can round away | Compute mean/variance/log-sum-exp/denominator in FP32 with suitable epsilon and stable formulas |
| Accumulation | Many low-precision additions lose increments or overflow | FP32 matmul/reduction/gradient accumulation where supported and verify kernel behavior |
| Weight updates | Small update disappears when added directly to a large FP16 weight | FP32 master parameters/optimizer moments, update in FP32 then cast a compute copy |
| Large values | FP16 maximum finite magnitude65504 can be exceeded | Monitor activations/gradients, correct scaling/initialization, keep sensitive paths FP32 or use BF16 |

FP16 has5 exponent bits and10 fraction bits, BF16 has8 exponent bits and7 fraction bits. BF16's exponent range is similar to FP32, making gradient underflow/overflow much less common and often removing the need for loss scaling; its mantissa is coarser, so it still needs careful accumulation and master/update precision. Loss scaling does not cure an already-overflowing forward or a wrong derivative. Benchmark convergence and task quality against a higher-precision baseline before claiming a mixed-precision win.
