## Question

<pre class="question-text" style="white-space:pre-wrap;font-family:inherit;line-height:1.55">A GPU has a peak FP16 throughput of 312 TFLOP/s and an HBM bandwidth of 1.5 TB/s. Use the roofline model to analyse matrix multiplications on it, then reason about the gradient of a residual connection and about where casting from FP32 to FP16 causes trouble.

Questions
1.
Roofline for a matmul. For (M,K)·(K,N) in FP16 (2 bytes per element, each matrix moved once), derive the FLOP count, the bytes moved, the arithmetic intensity, and the roofline time bound max(compute_time, memory_time). Compute the ridge point of this GPU.
2.
Two shapes. Apply this to M = K = N = 4096 and to M = 1, K = N = 4096 (a matrix-vector product). Classify each as compute-bound or memory-bound and give both time estimates.
3.
Residual gradient. For y = x + f(x), derive dL/dx in terms of dL/dy and explain why the identity branch keeps the gradient from vanishing as depth grows.
4.
FP32 to FP16. Name where casting to FP16 hurts (gradient underflow, normalisation denominators, accumulation, weight updates) and give the standard mitigation for each. Explain why bf16 often needs no loss scaling.
Expected deliverable

Worked arithmetic with units for parts 1 and 2, a short derivation for part 3, and a list of pitfalls with their mitigations for part 4.</pre>

## Worked solution

1. Apply the roofline model to a matrix multiplication. The roofline compares available compute throughput with the rate at which needed data can reach the processor.
2. For A:(M,K) and B:(K,N), estimate about 2MKN floating-point operations.
3. Estimate bytes moved under an explicit reuse assumption, then compute arithmetic intensity=FLOPs/bytes.
4. The idealized throughput ceiling is min(peak_FLOPs,bandwidth*intensity). Use profiling to include tiling, launch overhead and cache behavior.
5. Train with mixed precision without losing small gradients. Lower-precision matrix operations can improve throughput, while sensitive reductions and optimizer state may need higher precision.
6. Choose supported autocast dtypes and keep numerically sensitive loss calculations in an appropriate accumulator precision.
7. For FP16, loss scaling can protect small gradients; unscale before clipping, detect overflow and skip invalid updates. BF16 usually needs less range protection but still has limited mantissa precision.
8. Compare convergence and output quality against a higher-precision baseline; measure actual speed and memory rather than assuming benefits.

### Small example / sanity check

If bandwidth is 1 TB/s and intensity is 10 FLOPs/byte, the bandwidth ceiling is 10 TFLOPs/s, even if peak compute is 100 TFLOPs/s.

### Common trap

Counting every scalar reference as an uncached memory transfer, or treating a theoretical bound as achieved performance.
